# MacStorageChip

The Storage column: one word, with no icon. Every state that stands still is a plain word in the row's text: a chip on every row would say nothing. Only the states with progress are chips: Uploading, Pinning and Moving (to This Mac) fill with `progress`. At rest: Local, Pinned, Cloud. A pin, an upload or a move to This Mac waiting its turn shows the word Queued. An upload held by a missing original shows the word Waiting, in warning: the release's own problem, which only restoring the file fixes. A pin, a move to the cloud or a move to This Mac that failed shows the word Error, in danger. With `long`, which a release's Storage sheet passes (`MacStorageBand`), the word or chip names what its change does, as every screen but the column does: Queued to upload, Queued to pin, Queued to move to This Mac, Moving to This Mac…. The inspector says what is queued or moving, what failed, and which file an upload waits for (`MacTransferSummary`, `MacFailedTransferRow`, `MacFileRow`); the chip names no file. Nothing says how many wait ahead or what holds the queue back (Paused, Waiting for network): what holds a whole queue back shows once, on `MacStorageFooter`, not on each release.

**In the code:** macOS: `MacStorageChip`, with `StorageUploadingChipContainer`, `StoragePinningChipContainer` and `StorageMovingToThisDeviceChipContainer`, each reading its release's transfer stream and drawing the chip (`Views/Storage/Table/MacStorageChip.swift`) and `StorageProgressChip` (`StorageProgressChip.swift`).
