# MacStorageChip

The Storage column: one chip of one word, with no icon: the word says the state and the tone tells resting, moving and problem chips apart (README, Words). At rest: Local, Pinned, Cloud. Moving: Uploading, Pinning and Moving (to This Mac) fill with `progress`. A pin, an upload or a move to This Mac waiting its turn reads Queued. An upload held by a missing original reads Waiting, in warning: the release's own problem, which only restoring the file fixes. A pin, a move to the cloud or a move to This Mac that failed reads Error, in danger. The inspector says what is queued or moving, what failed, and which file an upload waits for (`MacTransferSummary`, `MacDownloadRow`, `MacFileRow`); the chip names no file. Nothing says how many wait ahead or what holds the queue back (Paused, Waiting for network): what holds a whole queue back shows once, on `MacStorageFooter`, not on each release.

**In the code:** macOS: `MacStorageChip`, with `QueuedUploadChip`, `StorageUploadingChipContainer`, `StoragePinningChipContainer` and `StorageMakingLocalChipContainer`, each reading its release's transfer stream and drawing the chip (`Views/Storage/Table/MacStorageChip.swift`) and `StorageProgressChip` (`StorageProgressChip.swift`).
