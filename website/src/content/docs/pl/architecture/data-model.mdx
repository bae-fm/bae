## Biblioteki i lokalizacje przechowywania

**Biblioteka** jest główną jednostką: kolekcją muzyki z własną tożsamością (`library_id`), nazwą i kluczem szyfrowania. Leży w **katalogu domowym biblioteki** na dysku (`~/.bae/libraries/{uuid}/`), gdzie aplikacja desktopowa zapisuje autorytatywną bazę danych.

Biblioteka może opcjonalnie mieć **cloud home**: jedną lokalizację cloud, np. folder Google Drive albo bucket S3, która działa jako centrum synchronizacji wielu urządzeń. Jeden cloud home na bibliotekę, skonfigurowany w `config.yaml`. Szczegóły są w [Cloud Home](/pl/architecture/cloud-home).

Pliki wydań mogą znajdować się w jednej lub kilku z tych lokalizacji:

- **Katalog domowy biblioteki** (`~/.bae/libraries/{uuid}/storage/`) — lokalna kopia, dostępna offline
- **Cloud home** (`cloud-home/storage/`) — zaszyfrowana kopia, dostępna do synchronizacji
- **Niezarządzane** — pliki zostają tam, gdzie są na dysku; bae tylko je indeksuje

Wydanie może być tylko lokalne, tylko cloud albo oba. Pliki tylko cloud nie są dostępne offline.

## Układ katalogów

### Katalog domowy biblioteki

```
~/.bae/libraries/{uuid}/
  config.yaml                  # ustawienia specyficzne dla urządzenia (niesynchronizowane)
  library.db                   # SQLite -- wszystkie metadane
  images/ab/cd/{id}            # obrazy biblioteki (okładki, zdjęcia wykonawców)
  storage/ab/cd/{file_id}      # pliki wydań
```

`config.yaml` przechowuje ustawienia specyficzne dla urządzenia. Nie jest synchronizowany. Dane dostępu trafiają do pęku kluczy systemu operacyjnego, nie tutaj.

Pliki w `images/` i `storage/` używają układu opartego na hashu: pierwsze 2 znaki ID tworzą katalog prefiksu, następne 2 podkatalog. Na dysku nie ma nazw plików ani rozszerzeń; oryginalne nazwy i typy treści są w bazie danych. Ten sam układ jest używany w katalogu domowym biblioteki i cloud home.

### Cloud home

Cloud home odzwierciedla dane biblioteki i dodaje mechanizmy synchronizacji oraz kontroli dostępu:

| Ścieżka | Cel |
|---|---|
| `snapshot.db.enc` | Pełny snapshot bazy danych dla nowych urządzeń |
| `changes/{device_id}/{seq}.enc` | Przyrostowe changesety synchronizacji |
| `heads/{device_id}.json.enc` | Numery sekwencji dla urządzeń |
| `images/ab/cd/{id}` | Zaszyfrowane obrazy biblioteki |
| `storage/ab/cd/{file_id}` | Zaszyfrowane pliki wydań |
| `membership/{pubkey}/{seq}.enc` | Wpisy łańcucha członkostwa |
| `keys/{user_pubkey}.enc` | Klucze szyfrowania opakowane dla urządzeń |

### Wpisy pęku kluczy

Zarządzane przez `KeyService`, z użyciem pęku kluczy systemu. Na macOS to chroniony magazyn danych z synchronizacją iCloud Keychain. Wszystkie wpisy mają przestrzeń nazw według `library_id`, chyba że zaznaczono inaczej.

| Wpis | Zakres | Cel |
|---|---|---|
| `encryption_master_key` | na bibliotekę | Szyfrowanie plików i metadanych |
| `cloud_home_credentials` | na bibliotekę | Serializowany enum: dostęp+sekret S3, token OAuth albo none (iCloud) |
| `discogs_api_key` | na bibliotekę | Dostęp do API Discogs |
| `bae_user_signing_key` | globalny | Klucz podpisu Ed25519 |
| `bae_user_public_key` | globalny | Klucz publiczny Ed25519 |

## Dwie klasy plików

### Pliki wydań

Wszystkie pliki, które przyszły z wydaniem: audio, obrazy, arkusze CUE, logi itd. To dane użytkownika. bae przechowuje je dokładnie tak, jak zostały zaimportowane, zachowując oryginały, aby można było je wyeksportować bez zmian.

### Obrazy metadanych

Obrazy tworzone i zarządzane przez bae, oddzielne od plików wydań:

- **Okładki wydań** — grafika wyświetlana w siatkach albumów, widokach szczegółów i odtwarzaniu. Jedna na wydanie. Może pochodzić z pliku w wydaniu albo z MusicBrainz/Discogs. bae robi własną kopię, aby móc kadrować lub zmieniać rozmiar bez wpływu na oryginał.
- **Obrazy wykonawców** — pobierane z zewnętrznych źródeł podczas importu.

## Przepływy pierwszego uruchomienia

**Nowa biblioteka**: przy pierwszym uruchomieniu aplikacja desktopowa pokazuje ekran powitalny. Użytkownik tworzy nową bibliotekę; generuje to UUID, tworzy strukturę katalogów i uruchamia aplikację. Katalog `storage/` zaczyna pusty; pliki pojawiają się podczas importów.

**Odtworzenie z cloud home**: użytkownik podaje dane dostępu do cloud home i klucz szyfrowania. bae pobiera snapshot, stosuje nowsze changesety i pobiera obrazy. Lokalne `storage/` zaczyna pusty; pliki wydań są strumieniowane z cloud home na żądanie.

**Przejście z lokalnego do cloud**: użytkownik loguje się u dostawcy cloud. bae generuje klucz szyfrowania, jeśli trzeba, wysyła pełny snapshot, obrazy i pliki wydań, a potem przełącza się na synchronizację przyrostową.
