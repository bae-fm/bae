---
title: Ohne eigenen Server
description: Wie bae ohne eigenen Server synchronisiert
---

bae hat keinen eigenen Server. Jedes Gerät ist ein Client, der ein gemeinsames Cloud Home liest und schreibt; die gesamte Synchronisierung läuft über diesen Speicher, nicht über eine Maschine, die bae betreibt.

## Das Cloud Home ist der Treffpunkt

Das [Cloud Home](/de/architecture/cloud-home) einer Bibliothek ist ein Bucket oder Ordner in einem Speicherbackend, das du kontrollierst: S3-kompatibler Speicher, Google Drive, Dropbox, OneDrive oder iCloud. Jedes Gerät:

- lädt seine verschlüsselten Datenbank-Changesets und Editionsdateien in das Cloud Home hoch
- lädt die Änderungen der anderen Geräte in jedem Synchronisierungszyklus von dort herunter

Deine Geräte sprechen nie direkt miteinander. Sie gleichen sich an, weil beide gegen dasselbe Cloud Home synchronisieren.

## Was im Cloud Home liegt

- Verschlüsselte Editionsdateien: Audio, Bilder usw.
- Verschlüsselte Datenbank-Snapshots und Sync-Changesets
- Verschlüsselte Bibliotheksbilder
- Die Mitgliedschaftskette, die festhält, wer die Bibliothek lesen oder schreiben darf

## Speicher ohne Kenntnis der Inhalte

Das Speicherbackend hält nie Schlüssel und entschlüsselt nie. Jeder Blob wird vor dem Upload auf dem Client verschlüsselt und nach dem Download auf dem Client entschlüsselt. Das Cloud Home kennt weder Inhalte, Metadaten noch Verschlüsselungsschlüssel deiner Bibliothek; es kann deine Musik nicht lesen, durchsuchen oder indexieren. Es ist nur Speicher.

Ein weiteres Gerät hinzuzufügen ist eine [Mitgliedschafts](/de/architecture/membership)-Freigabe über denselben gemeinsamen Speicher; es gibt keinen Server, zu dem eine Verbindung aufgebaut wird.
