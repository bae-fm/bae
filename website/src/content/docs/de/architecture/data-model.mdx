## Bibliotheken und Speicherorte

Eine **Bibliothek** ist die oberste Einheit: eine Musiksammlung mit eigener Identität (`library_id`), eigenem Namen und eigenem Verschlüsselungsschlüssel. Sie liegt in einem **Bibliotheks-Home** auf der Festplatte (`~/.bae/libraries/{uuid}/`), wo die Desktop-App die maßgebliche Datenbank schreibt.

Eine Bibliothek kann optional ein **Cloud Home** haben: einen einzelnen Cloud-Ort, etwa einen Google-Drive-Ordner oder S3-Bucket, der als Zentrum für Synchronisierung zwischen Geräten dient. Ein Cloud Home pro Bibliothek, konfiguriert in `config.yaml`. Siehe [Cloud Home](/de/architecture/cloud-home) für Details.

Editionsdateien können an einem oder mehreren dieser Orte liegen:

- **Bibliotheks-Home** (`~/.bae/libraries/{uuid}/storage/`) — lokale Kopie, offline verfügbar
- **Cloud Home** (`cloud-home/storage/`) — verschlüsselte Kopie, für Synchronisierung verfügbar
- **Nicht verwaltet** — Dateien bleiben an ihrem Ort auf der Festplatte; bae indexiert sie nur

Eine Edition kann nur lokal, nur in der Cloud oder an beiden Orten sein. Nur in der Cloud liegende Dateien sind offline nicht abspielbar.

## Verzeichnisstruktur

### Bibliotheks-Home

```
~/.bae/libraries/{uuid}/
  config.yaml                  # gerätespezifische Einstellungen (nicht synchronisiert)
  library.db                   # SQLite -- alle Metadaten
  images/ab/cd/{id}            # Bibliotheksbilder (Cover, Künstlerfotos)
  storage/ab/cd/{file_id}      # Editionsdateien
```

`config.yaml` enthält gerätespezifische Einstellungen. Es wird nicht synchronisiert. Zugangsdaten gehören in den OS-Schlüsselbund, nicht hierhin.

Dateien unter `images/` und `storage/` nutzen eine Hash-basierte Struktur: Die ersten 2 Zeichen der ID bilden das Präfixverzeichnis, die nächsten 2 ein Unterverzeichnis. Keine Dateinamen oder Erweiterungen auf der Festplatte; Originalnamen und Inhaltstypen stehen in der Datenbank. Dieselbe Struktur gilt im Bibliotheks-Home und im Cloud Home.

### Cloud Home

Das Cloud Home spiegelt die Daten der Bibliothek und ergänzt Synchronisierung sowie Zugriffskontrolle:

| Pfad | Zweck |
|---|---|
| `snapshot.db.enc` | Vollständiger Datenbank-Snapshot, Startpunkt für neue Geräte |
| `changes/{device_id}/{seq}.enc` | Inkrementelle Sync-Changesets |
| `heads/{device_id}.json.enc` | Sequenznummern pro Gerät |
| `images/ab/cd/{id}` | Bibliotheksbilder, verschlüsselt |
| `storage/ab/cd/{file_id}` | Editionsdateien, verschlüsselt |
| `membership/{pubkey}/{seq}.enc` | Einträge der Mitgliedschaftskette |
| `keys/{user_pubkey}.enc` | Pro Gerät umhüllte Verschlüsselungsschlüssel |

### Schlüsselbund-Einträge

Verwaltet von `KeyService` über den OS-Schlüsselbund. Auf macOS ist das der geschützte Datenspeicher mit iCloud-Keychain-Synchronisierung. Alle Einträge sind nach `library_id` namespaced, sofern nicht anders angegeben.

| Eintrag | Geltungsbereich | Zweck |
|---|---|---|
| `encryption_master_key` | pro Bibliothek | Datei- und Metadatenverschlüsselung |
| `cloud_home_credentials` | pro Bibliothek | Serialisiertes Enum: S3-Zugang+Secret, OAuth-Token oder none (iCloud) |
| `discogs_api_key` | pro Bibliothek | Discogs-API-Zugriff |
| `bae_user_signing_key` | global | Ed25519-Signaturschlüssel |
| `bae_user_public_key` | global | Öffentlicher Ed25519-Schlüssel |

## Zwei Dateiklassen

### Editionsdateien

Alle Dateien, die mit einer Edition kamen: Audio, Bilder, CUE-Sheets, Logs usw. Das sind die Daten des Nutzers. bae speichert sie genau wie importiert und bewahrt die Originaldateien, damit sie unverändert exportiert werden können.

### Metadatenbilder

Bilder, die bae erzeugt und verwaltet, getrennt von Editionsdateien:

- **Editionscover** — Anzeigeart für Albumraster, Detailansichten und Wiedergabe. Eines pro Edition. Es kann aus einer Datei der Edition oder aus MusicBrainz/Discogs stammen. bae erstellt eine eigene Kopie, damit Zuschneiden oder Skalieren das Original nicht verändert.
- **Künstlerbilder** — beim Import aus externen Quellen geladen.

## Erststart-Abläufe

**Neue Bibliothek**: Beim ersten Start zeigt die Desktop-App einen Willkommensbildschirm. Der Nutzer erstellt eine neue Bibliothek; dabei werden UUID und Verzeichnisstruktur erzeugt und die App geöffnet. Das Verzeichnis `storage/` beginnt leer; Dateien erscheinen durch Importe.

**Aus Cloud Home wiederherstellen**: Der Nutzer gibt Cloud-Home-Zugangsdaten und den Verschlüsselungsschlüssel an. bae lädt den Snapshot, wendet neuere Changesets an und lädt Bilder. Lokales `storage/` beginnt leer; Editionsdateien werden bei Bedarf aus dem Cloud Home gestreamt.

**Von lokal zu Cloud wechseln**: Der Nutzer meldet sich bei einem Cloud-Anbieter an. bae erzeugt bei Bedarf einen Verschlüsselungsschlüssel, lädt einen vollständigen Snapshot, Bilder und Editionsdateien hoch und wechselt dann zur inkrementellen Synchronisierung.
