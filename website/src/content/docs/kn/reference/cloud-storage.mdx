ಮೇಘ ಮನೆ ಬಳಕೆದಾರ ಈಗಾಗಲೇ ಹೊಂದಿರುವ ಸಂಗ್ರಹದಲ್ಲಿನ ಒಂದು ಸ್ಥಳ. ಪ್ರತಿಯೊಂದು ಒದಗಿಸುವವರನ್ನೂ [coven](https://coven.bae.fm) ನ ಅದೇ ಸಂಗ್ರಹ ಸಂಪರ್ಕದ ಮೂಲಕ ನಡೆಸಲಾಗುತ್ತದೆ; ಒದಗಿಸುವವರ ಪ್ರಕಾರ ಬದಲಾಗುವುದು sign-in, ಸಿದ್ಧತೆ, ಮತ್ತು ಇತರ ಜನರು ಹಾಗೂ ಸಾಧನಗಳು ಅಲ್ಲಿಗೆ ಹೇಗೆ ತಲುಪುತ್ತವೆ ಎಂಬುದು.

## ಒದಗಿಸುವವರು

| ಒದಗಿಸುವವರು | Sign-in | ನಿಮ್ಮದೇ ಹೊಸ ಸಾಧನ | ನೀವು ಆಹ್ವಾನಿಸುವ ವ್ಯಕ್ತಿ |
|---|---|---|---|
| S3-compatible | Access ಕೀ + secret | restore code, QR ಕೋಡ್‌ನಲ್ಲಿ ಅದರ ಪಕ್ಕ ಬರುವ ನಿಮ್ಮ access key ಜೊತೆ | ಅವರಿಗಾಗಿ ರಚಿಸಿದ access key |
| Dropbox | OAuth, coven ಬಳಿ | restore code, ನಂತರ ನಿಮ್ಮ Dropbox ಗೆ sign in | ಗ್ರಂಥಾಲಯದ ಹಂಚಿದ ಕಡತಕೋಶ ಅವರ ಖಾತೆಯೊಂದಿಗೆ ಹಂಚಲ್ಪಡುತ್ತದೆ |
| OneDrive | OAuth, coven ಬಳಿ | restore code, ನಂತರ ನಿಮ್ಮ OneDrive ಗೆ sign in | ಗ್ರಂಥಾಲಯದ ಕಡತಕೋಶ ಅವರ ಖಾತೆಯೊಂದಿಗೆ ಹಂಚಲ್ಪಡುತ್ತದೆ |
| iCloud (CloudKit) | Apple Account, sign-in ಇಲ್ಲ | restore code, iCloud Keychain ನಿಂದಲೂ ಸಿಗುತ್ತದೆ | ಗ್ರಂಥಾಲಯದ CloudKit zone ಅವರ Apple Account ನೊಂದಿಗೆ ಹಂಚಲ್ಪಡುತ್ತದೆ |

S3-compatible AWS, Backblaze B2, Cloudflare R2, Wasabi, MinIO, ಮತ್ತು API ಮಾತನಾಡುವ ಇನ್ನಾವುದನ್ನಾದರೂ ಒಳಗೊಂಡಿದೆ. ಸಿದ್ಧತೆ ಫಾರ್ಮ್ bucket, region, endpoint ಮತ್ತು access key ಅನ್ನು ಮಾತ್ರ ಕೇಳುತ್ತದೆ; coven ತಿಳಿದಿರುವ ಸೇವೆಗಳನ್ನು endpoint ನ host ನಿಂದ ಗುರುತಿಸಿ ಅವುಗಳೊಂದಿಗೆ ಹೇಗೆ ಮಾತನಾಡಬೇಕು ಎಂಬುದನ್ನು ತುಂಬುತ್ತದೆ. **Advanced** ನಲ್ಲಿ ಐಚ್ಛಿಕ key prefix ಮತ್ತು service profile ಆಯ್ಕೆ ಇವೆ, ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಸ್ವಯಂಚಾಲಿತ. coven ಗೆ ತಿಳಿಯದ ಸೇವೆಗೆ **Detect Settings** ಕೀಯಿಂದ bucket ಪರೀಕ್ಷಿಸಿ ಕಂಡದ್ದನ್ನು ತೋರಿಸುತ್ತದೆ. ಏನನ್ನಾದರೂ ಉಳಿಸುವ ಮೊದಲು ಸಿದ್ಧತೆ ಒದಗಿಸುವವರಲ್ಲಿ ಪರಿಶೀಲಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ typo ಮೊದಲ ಸಮನ್ವಯದಲ್ಲಿ ಅಲ್ಲ, ಸಿದ್ಧಪಡಿಸುವಾಗಲೇ ವಿಫಲವಾಗುತ್ತದೆ, ಮತ್ತು bae coven ನೀಡುವ ಕಾರಣವನ್ನು ಸರಳ ಮಾತುಗಳಲ್ಲಿ ಹೇಳುತ್ತದೆ. Dropbox, OneDrive ಮತ್ತು iCloud ಪೂರ್ಣ **bae** ಆವೃತ್ತಿಯಲ್ಲಿ ಮಾತ್ರ ಇವೆ; **baeium** builds ಅವನ್ನು ಹೊರತುಪಡಿಸುತ್ತವೆ.

## Sign-in ಮತ್ತು ಕಡತಕೋಶಗಳು

coven Dropbox ಮತ್ತು OneDrive sign-in ಅನ್ನು ತಾನೇ ನಡೆಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಯಾವುದೇ token bae ಮೂಲಕ ಹಾದುಹೋಗುವುದಿಲ್ಲ. ಡೆಸ್ಕ್‌ಟಾಪ್‌ನಲ್ಲಿ browser ಒದಗಿಸುವವರ ಪುಟವನ್ನು ತೆರೆಯುತ್ತದೆ ಮತ್ತು ಸ್ಥಳೀಯ listener ಆ ಒಂದು redirect ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ; mobile ನಲ್ಲಿ ಈ ಕೆಲಸವನ್ನು ವೇದಿಕೆಯ sign-in sheet ಮಾಡುತ್ತದೆ. coven token ಗಳನ್ನು OS ಕೀ ಸಂಗ್ರಹ ನಲ್ಲಿ ಇಡುತ್ತದೆ ಮತ್ತು ಒದಗಿಸುವವರು ತಿರಸ್ಕರಿಸಿದಾಗ token ಅನ್ನು ಒಮ್ಮೆ ಹೊಸಗೊಳಿಸುತ್ತದೆ; ವಿಫಲವಾದ ಹೊಸಗೊಳಿಸುವಿಕೆ silent retry loop ಆಗದೆ ಸಮನ್ವಯ ಸ್ಥಿತಿಯಲ್ಲಿ **Sign In** ಕ್ರಿಯೆಯಾಗಿ ಕಾಣುತ್ತದೆ.

sign in ಆದ ನಂತರ ಬಳಕೆದಾರ ಗ್ರಂಥಾಲಯ ಎಲ್ಲಿ ಇರಬೇಕು ಎಂದು ಆರಿಸುತ್ತಾರೆ. Dropbox ನಲ್ಲಿ ಅದು ಹಂಚಿದ ಕಡತಕೋಶ, ಏಕೆಂದರೆ ಮನೆಯ ಗ್ರಂಥಾಲಯ ಇತರ ಜನರ ಖಾತೆಗಳೊಂದಿಗೆ ಹಂಚಲ್ಪಡುತ್ತದೆ; ಇದಕ್ಕಾಗಿ bae app folder ಅಲ್ಲ, ಪೂರ್ಣ Dropbox ಪ್ರವೇಶವನ್ನು ಬಳಸುತ್ತದೆ. ಇನ್ನೂ ಹಂಚಿದ ಕಡತಕೋಶ ಇಲ್ಲದಿದ್ದರೆ bae Dropbox ನಲ್ಲಿ ಒಂದನ್ನು ಹಂಚಿ ಮತ್ತೆ ಹುಡುಕಲು ಹೇಳುತ್ತದೆ. OneDrive ನಲ್ಲಿ ಅದು ಯಾವುದೇ ಕಡತಕೋಶ, ಮೇಲಿನಿಂದ ಬ್ರೌಸ್ ಮಾಡಲ್ಪಡುತ್ತದೆ, ಮತ್ತು ಅಲ್ಲಿ ಹೊಸ ಕಡತಕೋಶ ರಚಿಸಬಹುದು.

CloudKit ಗೆ ಹರಿವು ಬೇಕಿಲ್ಲ: coven ಅದನ್ನು Apple ವೇದಿಕೆಗಳಲ್ಲಿ sign in ಆಗಿರುವ Apple Account ಆಗಿಯೇ ನಡೆಸುತ್ತದೆ.

## ಮನೆಯ ವಿನ್ಯಾಸ

ಮನೆ ಒಳಗೆ ಪ್ರತಿಯೊಂದು ವಸ್ತುವಿನ ಮಾರ್ಗ ಗ್ರಂಥಾಲಯದ store id ಯಿಂದ ಆರಂಭವಾಗುತ್ತದೆ: coven ನ ಕ್ರಮಾಂಕಿತ ಬದಲಾವಣೆ ಸರಣಿ, ಅದರ ಸ್ನ್ಯಾಪ್‌ಶಾಟ್‌ಗಳು, ಸೇರುವ ವಿನಂತಿಗಳು ಮತ್ತು ಸಂಗ್ರಹಿಸಿದ ಕಡತಗಳು. ಹಲವು ಗ್ರಂಥಾಲಯಗಳು ಪರಸ್ಪರರ ವಸ್ತುಗಳನ್ನು ಮುಟ್ಟದೆ ಒಂದೇ Dropbox ಅಥವಾ OneDrive ಕಡತಕೋಶವನ್ನು ಹಂಚಿಕೊಳ್ಳಬಹುದು.

ಪ್ರತಿಯೊಂದು ವಸ್ತು ಎನ್‌ಕ್ರಿಪ್ಟ್ ಆಗಿ ಯಾದೃಚ್ಛಿಕ ಹೆಸರಿನ ಅಡಿಯಲ್ಲಿ ಸಂಗ್ರಹವಾಗುತ್ತದೆ; plaintext ವಿಧಾನ ಇಲ್ಲ. bae ಕಡತಗಳು ಮೂರು ಸಮನ್ವಯಿತ ಪಟ್ಟಿಗಳಾದ `release_files`, `covers` ಮತ್ತು `artist_images` ನ ಸಾಲುಗಳಿಗೆ ಜೋಡಿಸಲ್ಪಟ್ಟಿವೆ, ಜೊತೆಗೆ ಪ್ರತಿಯೊಂದು `people` ಸಾಲಿನ avatar. ಕಡತದ ಮಾರ್ಗ ಅದು ತನ್ನ ಸಾಲಿಗೆ ಜೋಡಿಸಲ್ಪಟ್ಟಾಗ ಸ್ಥಿರವಾಗುತ್ತದೆ, ಆದ್ದರಿಂದ ಆಲ್ಬಮ್ ಹೆಸರು ಬದಲಾಯಿಸಿದರೂ ಅದು ಎಂದಿಗೂ ಸರಿಯುವುದಿಲ್ಲ. [ಎನ್‌ಕ್ರಿಪ್ಶನ್](/kn/reference/encryption) ನೋಡಿ.

## ನೈಜ ಜಾಲಗಳಲ್ಲಿ ವರ್ತನೆ

ಪ್ಲೇಬ್ಯಾಕ್‌ಗಾಗಿ ಓದುಗಳು ranged: player ಸಂಪೂರ್ಣ ಕಡತಗಳ ಬದಲು ಬೇಕಾದ ಎನ್‌ಕ್ರಿಪ್ಟ್ ಆದ chunks ಮಾತ್ರ ತರುತ್ತದೆ, ಮತ್ತು ಕಡತ ಕ್ರಮವಾಗಿ ಪ್ಲೇ ಆಗುವಾಗ ಮುಂದಿನ chunks ಅನ್ನು ಮುಂಚೆಯೇ ತರುತ್ತದೆ. ದರ ಮಿತಿ ಮತ್ತು ತಾತ್ಕಾಲಿಕ ಒದಗಿಸುವವರ ದೋಷಗಳು ಒಂದೇ backoff ಯೋಜನೆಯಿಂದ ಮರುಪ್ರಯತ್ನಿಸುತ್ತವೆ, ಒದಗಿಸುವವರು retry-after ಕೊಟ್ಟರೆ ಅದನ್ನು ಪಾಲಿಸಿ. ಅಪ್‌ಲೋಡ್ ಸರತಿ restart ನಂತರವೂ ಉಳಿಯುತ್ತದೆ: ಆಪ್ ಮುಚ್ಚಿದ್ದರಿಂದ ನಿಂತ ಅಪ್‌ಲೋಡ್ ಆರಂಭದಿಂದಲ್ಲ, ನಿಂತಲ್ಲಿಂದಲೇ ಮುಂದುವರಿಯುತ್ತದೆ, ಮತ್ತು ವಿರಾಮಗೊಳಿಸಿದ ಅಪ್‌ಲೋಡ್‌ಗಳು ವಿರಾಮದಲ್ಲೇ ಇರುತ್ತವೆ.
