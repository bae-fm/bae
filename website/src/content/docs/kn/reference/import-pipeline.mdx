ಫೈಲ್‌ಗಳ ಬೈಟ್ ಅನ್ನು ಮಾರ್ಪಡಿಸದೆಯೇ ಆಮದು ಫೈಲ್‌ಗಳ ಫೋಲ್ಡರ್ ಅನ್ನು ಕ್ಯಾಟಲಾಗ್ ನಮೂದಾಗಿ ಪರಿವರ್ತಿಸುತ್ತದೆ. ಈ ಪುಟವು [ಬಳಕೆಯ ಮಾರ್ಗದರ್ಶಿ](/kn/guide/importing) ನಲ್ಲಿ ವಿವರಿಸಲಾದ ಹರಿವಿನ ಹಿಂದಿನ ಪೈಪ್‌ಲೈನ್ ಆಗಿದೆ.

## ಸ್ಕ್ಯಾನ್

ಗಮನಿಸುವ ಕಡತಕೋಶಗಳನ್ನು ವೇದಿಕೆಯ ಕಡತ-system events ಮೂಲಕ ಗಮನಿಸಲಾಗುತ್ತದೆ, debounce ಮಾಡಲಾಗುತ್ತದೆ, ಮತ್ತು ಬದಲಾದಾಗ ಮರು-ಸ್ಕ್ಯಾನ್ ಮಾಡಲಾಗುತ್ತದೆ; ಸ್ಕ್ಯಾನ್‌ಗಳು ಮತ್ತೆ ಆರಂಭಿಸುವ ಬದಲು ಈಗಿರುವ ಅಭ್ಯರ್ಥಿ ಪಟ್ಟಿಯೊಂದಿಗೆ ಹೊಂದಿಸಿಕೊಳ್ಳುತ್ತವೆ. ಸ್ಕ್ಯಾನರ್ ಕಡತಕೋಶವನ್ನು ಒಂದು ಬಿಡುಗಡೆ ಎಂದು ವರ್ಗೀಕರಿಸುತ್ತದೆ (ಆಡಿಯೋ ನೇರವಾಗಿ ಒಳಗೆ, ಅಥವಾ `CD1`/`CD2` ಮಾದರಿಯ disc-shaped ಉಪಕಡತಕೋಶಗಳು), ಅಥವಾ ಸಂಗ್ರಹವಾಗಿ ಒಳಗೆ ಇಳಿಯುತ್ತದೆ. ಕಡತಗಳನ್ನು ವಿಸ್ತರಣೆಯ ಆಧಾರದ ಮೇಲೆ ಆಡಿಯೋ, ಕಲೆಚಿತ್ರ, ಮತ್ತು ದಾಖಲೆಗಳಾಗಿ ವರ್ಗೀಕರಿಸಲಾಗುತ್ತದೆ, ನಂತರ ಆಡಿಯೋ ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ: ಮುಖ್ಯ codec FFmpeg ಬೈಟ್‌ಗಳಲ್ಲಿ ಕಂಡುಕೊಳ್ಳುವುದೇ, ಕಡತ ವಿಸ್ತರಣೆ ಅಲ್ಲ. partial-ಡೌನ್‌ಲೋಡ್ ಗುರುತುಗಳಿರುವ ಕಡತಕೋಶಗಳನ್ನು ಡೌನ್‌ಲೋಡ್ ಮುಗಿಯುವವರೆಗೆ ಹೊರಗಿಡಲಾಗುತ್ತದೆ.

CUE sheet ಒಂದು ಆಡಿಯೋ image ಅನ್ನು ಟ್ರ್ಯಾಕ್ ಪಟ್ಟಿಯಾಗಿ ಮಾಡುತ್ತದೆ. parser pregaps ಮತ್ತು postgaps, ಪ್ರತಿ-ಟ್ರ್ಯಾಕ್ performers ಮತ್ತು ISRCs, ಹಾಗೂ ಒಂದೇ ಕಡತದ images ಮತ್ತು ಪ್ರತಿ ಟ್ರ್ಯಾಕ್‌ಗೆ ಒಂದು ಕಡತ CUE ವಿನ್ಯಾಸಗಳು ಎರಡನ್ನೂ ನೋಡಿಕೊಳ್ಳುತ್ತದೆ. ಟ್ರ್ಯಾಕ್ ಗಡಿಗಳು CUE frames (second ನ 1/75) ಇಂದ ನಿಖರ ಸ್ಯಾಂಪಲ್ ಸ್ಥಾನಗಳು ಗೆ ಬದಲಾಗುತ್ತವೆ, ಅವು ನಂತರ ಪ್ಲೇಬ್ಯಾಕ್ ಬಳಸುವ byte ಮತ್ತು ಸ್ಯಾಂಪಲ್ ಕಿಟಕಿಗಳು ಆಗುತ್ತವೆ.

## ಮೆಟಾಡೇಟಾ ಕರಡುಗಳು

ಪ್ರತಿಯೊಂದು ಅಭ್ಯರ್ಥಿಯು ಒಂದು ಸಂಪಾದಿಸಬಹುದಾದ ಮೆಟಾಡೇಟಾ ಡ್ರಾಫ್ಟ್ ಮತ್ತು ಆಯ್ಕೆಯ ಮೂಲವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಡ್ರಾಫ್ಟ್ ಖಾಲಿ ಇರಬಹುದು, ನೇರವಾಗಿ ತುಂಬಬಹುದು, ಹೊರಗಿನ ಬಿಡುಗಡೆಯಿಂದ ತುಂಬಬಹುದು, ಅಥವಾ ಸಂಗ್ರಹಿಸಲಾದ ಕಡತ- ಟ್ಯಾಗ್ ಸ್ನಾಪ್ ಶೋನಿಂದ ತುಂಬಬಹುದು. ಮೂಲ ದಾಖಲೆಗಳು ಪ್ರಸ್ತುತ ಡ್ರಾಫ್ಟ್ ಪ್ರಾರಂಭವಾದ ಸ್ಥಳ; ನಂತರದ ಸಂಪಾದನೆಗಳು ಅದನ್ನು ಅಳಿಸಿ ಹಾಕುವುದಿಲ್ಲ. ನೇರ ನಮೂದು ಮತ್ತು ಅಳಿಸಿ ಹಾಕಲಾದ ಡ್ರಾಫ್ಟ್ ಗಳಿಗೆ ಮೂಲವಿಲ್ಲ.

ಮೇಲ್ಭಾಗದ ಮೆಟಾಡೇಟಾ ಸ್ಥಾನವು ಡ್ರಾಫ್ಟ್, ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿ ವೀಕ್ಷಕ, ಅಥವ ಫೈಲ್ ಟ್ಯಾಗ್‌ಗಳು ವೀಕ್ಷಕವನ್ನು ತೋರಿಸುತ್ತದೆ. ವೀಕ್ಷಕವನ್ನು ತೆರೆದು ಮುಚ್ಚುವುದು ಡ್ರಾಫ್ಟ್ ಅನ್ನು ಮರು ಬರೆಯುವುದಿಲ್ಲ. ಒಂದು ಮೂಲವನ್ನು ಅನ್ವಯಿಸಿ ಮಾಡುವುದು ಡ್ರಾಫ್ಟ್ ಅನ್ನು, ಅದರ ಮೂಲವನ್ನು ಹಾಗು ಅದರ ಆಯ್ಕೆ ಮಾಡಲಾದ ಮೂಲದ ಮುಚ್ಚಳವನ್ನು ಒಂದು ದತ್ತಸಂಚಯದಲ್ಲಿ ಕಡತ ಪಾತ್ರಗಳನ್ನು, CUE ಬಂಧನಗಳನ್ನು, ಡಿಸ್ಕ್ ನಿಯೋಜನೆಗಳನ್ನು ಹಾಗು ಇತರೆ ಮ್ಯಾಪಿಂಗ್ ನಿರ್ಧಾರಗಳನ್ನು ಕಾಯ್ದುಕೊಳ್ಳುವ ಮೂಲಕ ಬದಲಾಯಿಸುತ್ತದೆ.

### ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿ

ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿ ಮಾತ್ರವೇ ಗುರುತಿಸುವಿಕೆಯನ್ನು ಚಲಾಯಿಸುವ ಮಾರ್ಗವಾಗಿದೆ. ಇದು ಡಿಸ್ಕ್ ID ಅನ್ನು ಒಂದು ರಿಪ್ ಲಾಗ್ ಅಥವಾ CUE ಹಾಳೆಯಿಂದ ಗಣಿಸುತ್ತದೆ, OCR ನೊಂದಿಗೆ ಬಾರ್ ಕೋಡ್ ಮತ್ತು ಕ್ಯಾಟಲಾಗ್ ಪಠ್ಯವನ್ನು ಗುರುತಿಸುತ್ತದೆ, MusicBrainz ಮತ್ತು Discogs ಗಳನ್ನು ಕೇಳುತ್ತದೆ, ಮತ್ತು ಫಲಿತಾಂಶಗಳನ್ನು ಹೊಂದಿಸುತ್ತದೆ. ಅಳವಡಿಸಲಾಗಿರುವ ಆಡಿಯೊ ಟ್ಯಾಗ್‌ಗಳು ಆನ್‌ಲೈನ್ ಗುರುತಿಸುವಿಕೆಯ ಸಾಕ್ಷಿಯಾಗಿಲ್ಲ.

**ಡೀಫಾಲ್ಟ್ ಮೆಟಾಡೇಟಾ ಮೂಲ** ಮೂರು ಮೌಲ್ಯಗಳನ್ನು ಹೊಂದಿದೆ. **ಯಾವುದೂ ಇಲ್ಲ** ಖಾಲಿ ಡ್ರಾಫ್ಟ್ ರಚಿಸುತ್ತದೆ ಮತ್ತು ಯಾವುದೇ ಮೆಟಾಡೇಟಾ ಕೆಲಸ ಆರಂಭಿಸುವುದಿಲ್ಲ. **ಫೈಲ್ ಟ್ಯಾಗ್‌ಗಳು** ಟ್ಯಾಗ್ ಸ್ನ್ಯಾಪ್‌ಶಾಟ್ ಓದಿ ಅನ್ವಯಿಸುತ್ತದೆ. **ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿ** ಆನ್‌ಲೈನ್ ಕಾರ್ಯಪ್ರವಾಹವನ್ನು ತೆರೆಯುತ್ತದೆ. **ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿಯ ಡೀಫಾಲ್ಟ್ ಮೋಡ್** ಸಾಕ್ಷ್ಯ ಹೊರತೆಗೆಯುವಿಕೆ, ಪೂರೈಕೆದಾರರ ಪ್ರಶ್ನೆಗಳು ಮತ್ತು ಹೊಂದಾಣಿಕೆಯನ್ನು ಕ್ಯೂ ಮಾಡುವ **ಸ್ವಯಂಚಾಲಿತ**, ಅಥವಾ ಗುರುತಿಸುವಿಕೆಯನ್ನು ಆರಂಭಿಸದ **ಕೈಯಾರೆ ಹುಡುಕಿ** ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ಯಾವುದೇ ಅಭ್ಯರ್ಥಿಗೆ ಆನ್‌ಲೈನ್‌ನಲ್ಲಿ ಹುಡುಕಿ ಆಯ್ದ ಮೋಡ್ ಬಳಸುತ್ತದೆ; ಸ್ವಯಂಚಾಲಿತವು ಸಕ್ರಿಯ ಅಥವಾ ಪೂರ್ಣಗೊಂಡ ಕೆಲಸವನ್ನು ಮರುಪ್ರಾರಂಭಿಸುವುದಿಲ್ಲ.

### ಫೈಲ್ ಟ್ಯಾಗ್‌ಗಳು

ಫೈಲ್ ಟ್ಯಾಗ್‌ಗಳು ಹೊಸದಾಗಿ ಪತ್ತೆಯಾದ ಅಭ್ಯರ್ಥಿಗೆ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಸಂರಚಿಸಲಾಗದ ಹೊರತು, ಹುದುಗಿಸಲಾದ ಆಡಿಯೊ ಟ್ಯಾಗ್‌ಗಳನ್ನು ಮತ್ತು CUE ಮೆಟಾಡೇಟಾವನ್ನು ನಿಷ್ಕ್ರಿಯವಾಗಿ ಓದುತ್ತದೆ. ಮುನ್ನೋಟವು ಅಭ್ಯರ್ಥಿಯ ಸ್ಕ್ಯಾನಿಂಗ್ ಉತ್ಪತ್ತಿ, ಕಡತ- ಸಂಪಾದನೆ ಪರಿಷ್ಕರಣೆ, ಮತ್ತು ಗಮನಿಸಿದ ಆಡಿಯೊ ಕಡತಗಳೊಂದಿಗೆ ಸ್ಟ್ಯಾಂಪ್ ಮಾಡಲಾದ ಒಂದು ಸ್ನಾನಗೃಹವನ್ನು ಸಂಗ್ರಹಿಸುತ್ತದೆ. ಅನ್ವಯಿಸಿ ಇದನ್ನು ಬದಲಾಯಿಸಿ ನಿಜವಾದ ಸ್ನಾನಗೃಹದಿಂದ ಡ್ರಾಫ್ಟ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ. ಆಮದು ಮಾಡಿಕೊಳ್ಳುವುದು ಅದೇ ಸ್ನಾನಗೃಹವನ್ನು ಬಳಸುತ್ತದೆ ಹಾಗು ಅದರ ಸ್ಟ್ಯಾಂಪ್ ಅಥವ ಗಮನಗಳು ಬದಲಾದರೆ ಲೈಬ್ರರಿ ಬರೆಯುವುದಕ್ಕೂ ಮುನ್ನವೇ ವಿಫಲವಾಗುತ್ತದೆ; ಇದು ಬೇರೆ ಉತ್ತರವನ್ನು ಓದುವುದಿಲ್ಲ.

ನೇರವಾಗಿ ನಮೂದಿಸುವುದು ಯಾವುದೇ ಮೇಟಾಡೇಟಾ I/O ಅನ್ನು ಮಾಡುವುದಿಲ್ಲ. ಖಾಲಿ ಡ್ರಾಫ್ಟ್ ನ ಬಿಡುಗಡೆ ಮತ್ತು ಟ್ರಾಕ್ ಕ್ಷೇತ್ರಗಳನ್ನು ತಕ್ಷಣ ಸಂಪಾದಿಸಬಹುದಾಗಿದೆ, ಮತ್ತು ಅಗತ್ಯವಿರುವ ಕ್ಷೇತ್ರಗಳು ಮತ್ತು ಮ್ಯಾಪಿಂಗ್‌ಗಳನ್ನು ದೃಢೀಕರಿಸಿದ ನಂತರ ಆಮದು ಮಾಡಿಕೊಳ್ಳಬಹುದಾಗಿದೆ. ಅಭ್ಯರ್ಥಿಗಳ ಪಟ್ಟಿ ಕಾಣದ ಮೂಲವನ್ನು ದೋಷವಾಗಿ ಅಥವಾ ಗಮನಕ್ಕೆ ಕೋರಿಕೆಯಾಗಿ ಪರಿಗಣಿಸುವುದಿಲ್ಲ.

## ಮೂಲಗಳು

MusicBrainz ಖಾತೆಯಿಲ್ಲದೆ ಕಟ್ಟುನಿಟ್ಟಾದ one-request-per-second ಅಂತರದಲ್ಲಿ ಕೇಳಲ್ಪಡುತ್ತದೆ. Discogs ಬಳಕೆದಾರನ ವೈಯಕ್ತಿಕ token ಅನ್ನು ಕೀ ಸಂಗ್ರಹ ನಿಂದ ಬಳಸಿ ದೃಢೀಕರಿಸುತ್ತದೆ, ತನ್ನ ದರ ಮಿತಿಗಳೊಳಗೆ ಅಂತರದಿಂದ ಕೇಳಿ ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ, ಮತ್ತು ತಿರಸ್ಕೃತ token ಅಂಥದ್ದೇ ಎಂದು ತಿಳಿಸಲಾಗುತ್ತದೆ, UI ಅದನ್ನು flag ಮಾಡಲು; ಹುಡುಕಾಟಗಳು ಮೌನವಾಗಿ ವಿಫಲವಾಗುವುದಿಲ್ಲ. ಪ್ರತಿಕ್ರಿಯೆಗಳು ಪ್ರತಿ session ಗೆ ಕ್ಯಾಶ್ ಆಗುತ್ತವೆ, ಮತ್ತು ಗೆಲ್ಲುವ ಮೂಲದ raw JSON ಡೇಟಾಬೇಸ್‌ನಲ್ಲಿ ಮುಂದಿನ ಮರುವ್ಯಾಖ್ಯಾನಕ್ಕಾಗಿ ಸಂಗ್ರಹವಾಗುತ್ತದೆ.

## Commit

ಆಮದು ದೃಢಪಡಿಸಿದಾಗ, ಕ್ರಮವಾಗಿ ನಡೆಯುವುದು:

1. **Decode verification**: ಪ್ರತಿಯೊಂದು ಟ್ರ್ಯಾಕ್ ಕೊನೆಯವರೆಗೆ decode ಆಗುತ್ತದೆ; ಪೂರ್ಣವಾಗಿ decode ಆಗಲಾರದ rip ಏನಾದರೂ ಬರೆಯುವ ಮೊದಲು ಆಮದು ವಿಫಲವಾಗುತ್ತದೆ (config flag ಇದನ್ನು disable ಮಾಡಬಹುದು).
2. **Loudness analysis**: ಅದೇ decode ಸುತ್ತಿನಲ್ಲಿ ಸಮಗ್ರ loudness ಮತ್ತು true peak ಪ್ರತಿ ಟ್ರ್ಯಾಕ್ ಹಾಗೂ ಪ್ರತಿ ಆಲ್ಬಮ್‌ಗೆ ಅಳೆಯಲ್ಪಡುತ್ತವೆ, replay-gain ಬಳಕೆಗೆ ಇಡಲ್ಪಡುತ್ತವೆ.
3. **Cover selection**: ಆಯ್ಕೆ ಮಾಡಿದ ಕಲೆ (ದೂರಸ್ಥ ಕಲೆ, ಕಡತಕೋಶದ ಚಿತ್ರ, ಅಥವಾ embedded) ಪ್ರದರ್ಶನ thumbnail ಗೆ re-render ಆಗುತ್ತದೆ; ಕಡತಕೋಶದಿಂದ ಬಂದಿದ್ದರೆ ಮೂಲವು ಬಿಡುಗಡೆಯ ಕಡತಗಳ ನಡುವೆ ಉಳಿಯುತ್ತದೆ.
4. **Atomic write**: ಬಿಡುಗಡೆ, ಟ್ರ್ಯಾಕ್‌ಗಳು, ಕ್ರೆಡಿಟ್‌ಗಳು, ಗುರುತುಗಳು, ಸ್ವರೂಪಗಳು, segments, ಕಡತಗಳು, ಮತ್ತು ಮುಖಪುಟ ಚಿತ್ರ ಒಂದೇ transaction ನಲ್ಲಿ commit ಆಗುತ್ತವೆ. ಅರ್ಧ-ಆಮದು ಸ್ಥಿತಿ ಇಲ್ಲ.

ಬಿಡುಗಡೆ ಬಳಕೆದಾರನ ಕಡತಗಳನ್ನು ಸ್ಥಳದಲ್ಲೇ ಉಲ್ಲೇಖಿಸಿ ಬರುತ್ತದೆ. ಬಳಕೆದಾರ ಮೇಘ-ನಿರ್ವಹಿತ ಆರಿಸಿದರೆ, ಅಪ್‌ಲೋಡ್ commit ನಂತರ ಸಂಗ್ರಹ ಬದಲಾವಣೆಯಾಗಿ ನಡೆಯುತ್ತದೆ, ಮತ್ತು ಕಡತಗಳ ಮೂಲ ಬೈಟ್‌ಗಳು ಸಂಪೂರ್ಣ ಅವಧಿಯಲ್ಲಿ ಸತ್ಯದ ಮೂಲವಾಗಿಯೇ ಉಳಿಯುತ್ತವೆ; ಬಳಕೆದಾರ bae ಗೆ ಕೊಟ್ಟ ಯಾವುದನ್ನೂ ಎಂದಿಗೂ ಅಳಿಸಲಾಗುವುದಿಲ್ಲ ಅಥವಾ ಬದಲಿಸಲಾಗುವುದಿಲ್ಲ.

## Rips ಗುರುತಿಸುವುದು

ಪ್ರತಿಯೊಂದು ಬಿಡುಗಡೆ ತನ್ನ ಆಮದು ಮಾಡಿದ ಕಡತಕೋಶದ ರಚನೆ (relative ಮಾರ್ಗಗಳು ಮತ್ತು sizes, ಸ್ಥಳ-ಸ್ವತಂತ್ರ) ಮೇಲೆ content hash ದಾಖಲಿಸುತ್ತದೆ. ಮರು-ಸ್ಕ್ಯಾನ್‌ಗಳು ಅದನ್ನು ಬಳಸಿ ಈಗಾಗಲೇ ಗ್ರಂಥಾಲಯದಲ್ಲಿರುವ ಕಡತಕೋಶಗಳನ್ನು ಗುರುತಿಸುತ್ತವೆ, ಮತ್ತು ಅದೇ rip ನ ಮರು-ಆಮದುಗಳು duplicate ಮಾಡದೆ ಹಿಂದಿನ ಬಿಡುಗಡೆ ಕಂಡು ಬದಲಿಸು ಮಾಡುತ್ತವೆ.
