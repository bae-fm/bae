bae ನಲ್ಲಿ ಖಾತೆ ವ್ಯವಸ್ಥೆ ಎಲ್ಲಿಯೂ ಇಲ್ಲ. ಗ್ರಂಥಾಲಯದ ಪ್ರತಿಯೊಬ್ಬ ವ್ಯಕ್ತಿ coven *ಸದಸ್ಯ*: ಯಾದೃಚ್ಛಿಕ, ಶಾಶ್ವತ ಸದಸ್ಯ id ಮತ್ತು ಎರಡು ಕೀ ಜೋಡಿಗಳು, ಒಂದು ಸಹಿಗಾಗಿ ಮತ್ತು ಒಂದು ಕೀಗಳನ್ನು ಅದಕ್ಕೆ ಮುಚ್ಚಲು; ಆ ವ್ಯಕ್ತಿಯ ಎಲ್ಲಾ ಸಾಧನಗಳು ಅವನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ ಮತ್ತು ಪ್ರತಿಯೊಂದು ಸಾಧನದ OS ಕೀ ಸಂಗ್ರಹ ನಲ್ಲಿ ಇಡುತ್ತವೆ. ಸಾಧನ ಎಂದರೆ ಒಂದು ಸ್ಥಾಪನೆ, ತನ್ನದೇ id ಯೊಂದಿಗೆ, ಒಬ್ಬ ಸದಸ್ಯನಿಗೆ ಸೇರಿದ್ದು. ಗ್ರಂಥಾಲಯಕ್ಕೆ ಯಾರು ಸೇರಿದ್ದಾರೆ ಎಂಬುದು ಮೇಘ ಮನೆಯಲ್ಲಿರುವ ಸಹಿ ಮಾಡಿದ ದಾಖಲೆಗಳ ಸಮೂಹ, ಪ್ರತಿಯೊಬ್ಬ ಸದಸ್ಯನ ಸಾಧನ ಅವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಯಾವುದೇ ಸರ್ವರ್ ನೀಡುವುದಿಲ್ಲ. ವ್ಯವಸ್ಥೆ [coven](https://coven.bae.fm) ನದು; bae ಅದನ್ನು ಹೇಗೆ ಬಳಸುತ್ತದೆ ಎಂಬುದನ್ನು ಈ ಪುಟ ತೋರಿಸುತ್ತದೆ.

## ಸದಸ್ಯತ್ವ ದಾಖಲೆಗಳು

ಮೇಘ ಮನೆಯಲ್ಲಿ ಗ್ರಂಥಾಲಯದ ಸಂಪೂರ್ಣ ಇತಿಹಾಸ ಒಂದು ಕ್ರಮಾಂಕಿತ ಸರಣಿ, ಮತ್ತು ಪ್ರತಿಯೊಂದು ಸಾಧನ ಅದನ್ನು ಒಂದೇ ಕ್ರಮದಲ್ಲಿ ಅನ್ವಯಿಸುತ್ತದೆ. ಸದಸ್ಯತ್ವ ಅಥವಾ ಸೆಟ್ಟಿಂಗ್‌ಗಳ ಬದಲಾವಣೆ ಆ ಸರಣಿಯಲ್ಲಿ ಒಂದು *admin entry*, ಲೇಖಕನ ಕೀಯಿಂದ ಸಹಿ ಮಾಡಲ್ಪಟ್ಟು ಅದರ ತಕ್ಷಣ ಹಿಂದಿನ ಸ್ಥಿತಿಯ ಆಧಾರದ ಮೇಲೆ ನಿರ್ಧರಿಸಲ್ಪಡುತ್ತದೆ, ಆದ್ದರಿಂದ ಪ್ರತಿಯೊಂದು ಸಾಧನ ತಾನೇ ಅದೇ ನಿರ್ಧಾರಕ್ಕೆ ಬರುತ್ತದೆ. ಲೇಖಕನಿಗೆ ಅದನ್ನು ಮಾಡುವ ಹಕ್ಕು ಇದ್ದರೆ ಮಾತ್ರ entry ಲೆಕ್ಕಕ್ಕೆ ಬರುತ್ತದೆ, ಮತ್ತು ಗ್ರಂಥಾಲಯ ಸದಾ ಕನಿಷ್ಠ ಒಬ್ಬ admin ಅನ್ನು ಇಟ್ಟುಕೊಳ್ಳುತ್ತದೆ.

ಸಾಧನ ಕಳುಹಿಸುವ ಪ್ರತಿಯೊಂದು ಬದಲಾವಣೆ ಈ ದಾಖಲೆಯ ವಿರುದ್ಧ ಪರಿಶೀಲಿಸಲ್ಪಡುತ್ತದೆ: ಈಗಿನ ಸದಸ್ಯನ ಸಹಿ, ತೆಗೆದುಹಾಕದ ಸಾಧನದಿಂದ. ತೆಗೆದುಹಾಕಿದ ಸಾಧನಗಳು ಅಥವಾ ಸದಸ್ಯರಿಂದ, ಎಂದಿಗೂ ಸೇರಿಸದ ಕೀಗಳಿಂದ, ಅಥವಾ invalid signatures ಹೊಂದಿರುವ ಬದಲಾವಣೆಗಳು ಲೆಕ್ಕಕ್ಕೆ ಬರುವುದಿಲ್ಲ. ಒದಗಿಸುವವರು ದಾಖಲೆಗಳನ್ನು ಇಡುತ್ತಾರೆ ಆದರೆ ನಕಲಿ ಮಾಡಲಾರರು.

## ಪಾತ್ರಗಳು

**Admin** ಮತ್ತು **ಸದಸ್ಯ** ಎರಡೂ ಗ್ರಂಥಾಲಯವನ್ನು ಓದುತ್ತವೆ ಮತ್ತು ಬರೆಯುತ್ತವೆ: coven ಗ್ರಂಥಾಲಯಕ್ಕೆ ಬರೆಯುವಾಗ ಯಾವುದೇ ಅನುಮತಿ ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಓದಲು-ಮಾತ್ರ ಪಾತ್ರ ಉಳಿಯಲಾರದು. admin ಗಳು ಹೆಚ್ಚುವರಿಯಾಗಿ ಜನರನ್ನು ಆಹ್ವಾನಿಸುತ್ತಾರೆ ಮತ್ತು ತೆಗೆದುಹಾಕುತ್ತಾರೆ, ಪಾತ್ರಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತಾರೆ ಮತ್ತು ಗ್ರಂಥಾಲಯದ ಹೆಸರು ಬದಲಾಯಿಸುತ್ತಾರೆ. ಗ್ರಂಥಾಲಯಕ್ಕೆ ಅದರ ಮೇಘ ಮನೆಯನ್ನು ಕೊಡುವ ವ್ಯಕ್ತಿ ಅದರ ಮೊದಲ admin.

| ಕ್ರಿಯೆ | ಯಾರು |
|---|---|
| ವ್ಯಕ್ತಿಯನ್ನು ಆಹ್ವಾನಿಸುವುದು | admin |
| ಸಾಧನ ಸೇರಿಸುವುದು | ವ್ಯಕ್ತಿ ತಾನೇ, ಹೊಸ ಸಾಧನದಿಂದ, ತನ್ನ restore code ಬಳಸಿ |
| ಸಾಧನ ತೆಗೆದುಹಾಕುವುದು | ಅದರ ವ್ಯಕ್ತಿ, ಅಥವಾ ಯಾವುದೇ admin |
| ವ್ಯಕ್ತಿಯನ್ನು ತೆಗೆದುಹಾಕುವುದು | admin |
| ಗ್ರಂಥಾಲಯದ ಹೆಸರು ಬದಲಾಯಿಸುವುದು | admin |

ವ್ಯಕ್ತಿಯ profile, ratings, ಇತಿಹಾಸ ಮತ್ತು playlists owner ಸಾಲುಗಳು: ಆ ವ್ಯಕ್ತಿಯ ಸಾಧನಗಳು ಮಾತ್ರ ಅವನ್ನು ಬದಲಾಯಿಸಬಹುದು, ಆದ್ದರಿಂದ ಯಾರದೋ ಹೆಸರಿನಲ್ಲಿ ದಾಖಲಾದ rating ನಿಜವಾಗಿಯೂ ಅವರದೇ.

## ನಿಮ್ಮದೇ ಸಾಧನ ಸೇರಿಸುವುದು

restore code ಸಾಧನ ಅದರ ವ್ಯಕ್ತಿಗೆ ಸೇರಿದೆ ಎಂದು ಸಾಬೀತುಪಡಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಯಾವುದೇ ಅನುಮೋದನೆ ಬೇಕಿಲ್ಲ:

1. ಹೊಸ ಸಾಧನ ಕೋಡ್ ಪಡೆಯುತ್ತದೆ: ವ್ಯಕ್ತಿಯ ಇನ್ನೊಂದು ಸಾಧನ ತೋರಿಸುವ QR ಕೋಡ್ ಸ್ಕ್ಯಾನ್ ಮಾಡಿ, Apple ಸಾಧನಗಳಲ್ಲಿ iCloud Keychain ನಿಂದ, ಅಥವಾ ಟೈಪ್ ಮಾಡಿ.
2. ಅದು ಸಂಗ್ರಹವನ್ನು ತಲುಪುತ್ತದೆ: Dropbox ಮತ್ತು OneDrive ನಲ್ಲಿ ವ್ಯಕ್ತಿಯ ಸ್ವಂತ ಖಾತೆಗೆ sign in ಮಾಡಿ, S3 ನಲ್ಲಿ ಅವರ access key ಯಿಂದ, ಅದನ್ನು QR ಕೋಡ್ ಕೋಡಿನ ಪಕ್ಕ ತರುತ್ತದೆ.
3. ಅದು ಗ್ರಂಥಾಲಯವನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ, ಕೋಡಿನ ಕೀಗಳು ಈಗಿನ ಸದಸ್ಯನದು ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ, ಮತ್ತು ಆ ಕೀಗಳಿಂದ ಸಹಿ ಮಾಡಿದ entry ಮೂಲಕ ತನ್ನನ್ನು ಹೊಸ ಸಾಧನವಾಗಿ ದಾಖಲಿಸುತ್ತದೆ.

ಕೀಗಳು ನಂತರ ಬದಲಾದ ಕೋಡ್ ವಿಫಲವಾಗುತ್ತದೆ. ಮರುಪಡೆಯುವಿಕೆ ಸದಾ ಹೊಸ ಸಾಧನವನ್ನು ರಚಿಸುತ್ತದೆ; ಅದು ಇನ್ನೊಂದು ಸ್ಥಾಪನೆಯ ಕಳುಹಿಸದ ತಿದ್ದುಪಾಡಿಗಳನ್ನು ಉಳಿಸುವುದಿಲ್ಲ.

## ವ್ಯಕ್ತಿಯನ್ನು ಆಹ್ವಾನಿಸುವುದು

1. admin ವ್ಯಕ್ತಿಯ ಒದಗಿಸುವವರ ಖಾತೆಯನ್ನು ನಮೂದಿಸಿ ಅವರ ಪಾತ್ರವನ್ನು ಆರಿಸುತ್ತಾರೆ. bae ಗ್ರಂಥಾಲಯದ ಕಡತಕೋಶವನ್ನು ಆ ಖಾತೆಯೊಂದಿಗೆ ಹಂಚುತ್ತದೆ, ಅಥವಾ S3 ನಲ್ಲಿ ಅವರಿಗಾಗಿ access key ರಚಿಸುತ್ತದೆ, ಮತ್ತು ಆಹ್ವಾನವನ್ನು ತೋರಿಸುತ್ತದೆ: ಗ್ರಂಥಾಲಯದ ಸ್ಥಳ, ಆ ವ್ಯಕ್ತಿಗಾಗಿ ಆರಿಸಿದ ಸದಸ್ಯ id, ಒಮ್ಮೆ ಬಳಸುವ ರಹಸ್ಯ ಮತ್ತು ಗ್ರಂಥಾಲಯದ ಈಗಿನ ಹೆಸರು ಇರುವ QR ಕೋಡ್. ಅದು ರಚನೆಯಾದ ಒಂದು ದಿನದ ನಂತರ ಅವಧಿ ಮೀರುತ್ತದೆ.
2. ವ್ಯಕ್ತಿಯ ಸಾಧನ ಅದನ್ನು ಸ್ಕ್ಯಾನ್ ಮಾಡುತ್ತದೆ, ಅವರ ಸ್ವಂತ ಖಾತೆಗೆ sign in ಮಾಡುತ್ತದೆ, ಅವರ ಕೀ ಜೋಡಿಗಳನ್ನು ಸೃಜಿಸುತ್ತದೆ ಮತ್ತು ಸಂಗ್ರಹಕ್ಕೆ ಸೇರುವ ವಿನಂತಿಯನ್ನು ಬರೆಯುತ್ತದೆ, ಆಹ್ವಾನದ ರಹಸ್ಯದಿಂದ ಪಡೆದ ಕೀಯಿಂದ ಎನ್‌ಕ್ರಿಪ್ಟ್ ಆಗಿ ಮತ್ತು ಅವರ ಹೊಸ ಕೀಯಿಂದ ಸಹಿ ಮಾಡಿ.
3. admin ಸಾಧನ, ರಹಸ್ಯ ಹೊಂದಿರುವ ಏಕೈಕ ಸಾಧನ, ವಿನಂತಿಯನ್ನು ತೋರಿಸುತ್ತದೆ, ಮತ್ತು admin ಅದನ್ನು ಅನುಮೋದಿಸುತ್ತಾರೆ.
4. ಅನುಮೋದನೆ ಪ್ರತಿಯೊಂದು store key ಅನ್ನು ವ್ಯಕ್ತಿಯ ಹೊಸ ಮುದ್ರೆ ಕೀಗೆ ಮುಚ್ಚುತ್ತದೆ, ನಂತರ ಅವರನ್ನು ಸ್ವೀಕರಿಸುವ entry ಸೇರಿಸುತ್ತದೆ.
5. ಹೊಸ ಸಾಧನ ತನ್ನ ಕೀಗಳನ್ನು ತೆರೆಯುತ್ತದೆ, ಗ್ರಂಥಾಲಯವನ್ನು ಲೋಡ್ ಮಾಡುತ್ತದೆ, ತನ್ನನ್ನು ದಾಖಲಿಸುತ್ತದೆ ಮತ್ತು ವ್ಯಕ್ತಿ ಟೈಪ್ ಮಾಡಿದ ಹೆಸರಿನೊಂದಿಗೆ ಅವರ profile ಬರೆಯುತ್ತದೆ.

ಆಹ್ವಾನವನ್ನು ತಿರಸ್ಕರಿಸಿದರೆ, ಅಥವಾ ಅದರ ಅವಧಿ ಮೀರಲು ಬಿಟ್ಟರೆ, ಅದು ಕೊಟ್ಟ ಒದಗಿಸುವವರ ಪ್ರವೇಶ ಹಿಂಪಡೆಯಲ್ಪಡುತ್ತದೆ.

## ತೆಗೆದುಹಾಕುವಿಕೆ

ಸಾಧನ ಅಥವಾ ವ್ಯಕ್ತಿಯನ್ನು ತೆಗೆದುಹಾಕುವುದು admin entry, ಮತ್ತು ಸರಣಿಯಲ್ಲಿ ಅದರ ಸ್ಥಾನ ಇತಿಹಾಸದಲ್ಲಿ ಒಂದು ಗೆರೆ: ತೆಗೆದುಹಾಕಿದ ಸಾಧನ ಅಥವಾ ವ್ಯಕ್ತಿ ಅದರ ನಂತರ ಕಳುಹಿಸುವುದು ಲೆಕ್ಕಕ್ಕೆ ಬರುವುದಿಲ್ಲ, ಹಿಂದೆ ತಲುಪಿದ್ದು ಉಳಿಯುತ್ತದೆ. ವ್ಯಕ್ತಿಯನ್ನು ತೆಗೆದುಹಾಕುವುದು ಅವರ ಸಾಧನಗಳನ್ನು ಮತ್ತು ಅವರ ಖಾಸಗಿ circle ಅನ್ನೂ ತೆಗೆದುಹಾಕುತ್ತದೆ, ಮತ್ತು ಅವರ ಬಳಿ ಇದ್ದ ಕೀಗಳು ಇನ್ನಷ್ಟು ದತ್ತಾಂಶ ಬರೆಯುವ ಮೊದಲು ಬದಲಾಗುತ್ತವೆ ([ಎನ್‌ಕ್ರಿಪ್ಶನ್](/kn/reference/encryption#ಕೀ-ಬದಲಾವಣೆ) ನೋಡಿ). ಸಂಗ್ರಹ ಪ್ರವೇಶ ಕಡಿತ ಒದಗಿಸುವವರ ಕೆಲಸ: ಗ್ರಂಥಾಲಯ ಇರುವ ಖಾತೆಯ ಸಾಧನ ಕಡತಕೋಶದ ಹಂಚಿಕೆ ನಿಲ್ಲಿಸುತ್ತದೆ, ಮತ್ತು S3 ನಲ್ಲಿ ವ್ಯಕ್ತಿಯ access key ಅಳಿಸಲ್ಪಡುತ್ತದೆ. ತೆಗೆದುಹಾಕಿದ ಸಾಧನದಲ್ಲಿ ಈಗಾಗಲೇ ಸಮನ್ವಯ ಆದದ್ದು ಅದರ ಬಳಿಯೇ ಉಳಿಯುತ್ತದೆ; ದತ್ತಾಂಶವನ್ನು ಹಿಂಪಡೆಯಲಾಗುವುದಿಲ್ಲ.

## ಮರುಸ್ಥಾಪನೆ ಕೋಡ್‌ಗಳು

restore code ಸದಸ್ಯನ id ಮತ್ತು ಅವರ ಈಗಿನ ಖಾಸಗಿ ಕೀ ಜೋಡಿಗಳು, ಗ್ರಂಥಾಲಯದ store id ಮತ್ತು ಅದರ ಸಂಗ್ರಹ ಸ್ಥಳವನ್ನು ಹೊಂದಿದೆ; ಸಂಗ್ರಹ ಪ್ರಮಾಣಪತ್ರಗಳು, sign-in token ಗಳು ಅಥವಾ ಗ್ರಂಥಾಲಯದ ಹೆಸರು ಎಂದಿಗೂ ಇಲ್ಲ. ಅದು ಬೇಡಿಕೆಯ ಮೇರೆಗೆ ತೋರಿಸಲ್ಪಡುತ್ತದೆ, Apple ವೇದಿಕೆಗಳಲ್ಲಿ iCloud Keychain ನಲ್ಲಿ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಉಳಿಸಲ್ಪಡುತ್ತದೆ, ಮತ್ತು ಗ್ರಂಥಾಲಯದಷ್ಟೇ ಸೂಕ್ಷ್ಮ: ಅದು ಮತ್ತು ಸಂಗ್ರಹ ಪ್ರವೇಶ ಹೊಂದಿರುವವರು ಗ್ರಂಥಾಲಯಕ್ಕೆ ಆ ವ್ಯಕ್ತಿಯೇ. ಪ್ರತಿಯೊಂದು ಸಾಧನ ಮತ್ತು ತನ್ನ ಕೋಡ್ ಕಳೆದುಕೊಂಡ ವ್ಯಕ್ತಿಯನ್ನು admin ಅವರ ಈಗಿನ ಸದಸ್ಯ id ಗೆ ಮತ್ತೆ ಆಹ್ವಾನಿಸಬಹುದು, ಇದು ಅವರ ಕೀಗಳನ್ನು ಬದಲಾಯಿಸುತ್ತದೆ.
