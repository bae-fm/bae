ਸੁਣਾਈ ਯੰਤਰ ਦਾ ਵਾਅਦਾ ਸਰੋਤ ਨਾਲ ਵਫ਼ਾਦਾਰੀ ਹੈ: ਵਰਤੋਂਕਾਰ ਦੇ ਮੂਲ bytes decode ਕਰਨਾ, ਸਰੋਤ ਦੀ ਆਪਣੀ ਦਰ ਉੱਤੇ, ਰਿਲੀਜ਼ ਦੀ ਬਣਤਰ ਸਹੀ-ਸਲਾਮਤ ਰੱਖ ਕੇ। ਇਹ ਪੰਨਾ ਉਸਦੇ ਪਿੱਛੇ ਵਿਸ਼ੇਸ਼ਣ ਹੈ।

## ਡੀਕੋਡਿੰਗ

ਸਾਰੀ ਡੀਕੋਡਿੰਗ FFmpeg ਹੈ, in-ਪ੍ਰਕਿਰਿਆ, ਹਰ platform ਉੱਤੇ: FLAC, MP3, APE, ALAC, AAC, PCM (WAV/AIFF), Ogg Vorbis, Opus, WavPack, ਅਤੇ DSD ਉਹ ਹਨ ਜੋ ਆਯਾਤ ਮੰਨਦਾ ਹੈ, ਅਤੇ FFmpeg bytes ਤੋਂ ਜੋ report ਕਰਦਾ ਹੈ, ਫਾਈਲ ਐਕਸਟੈਂਸ਼ਨ ਨਹੀਂ, ਉਹ codec of ਰਿਕਾਰਡ ਹੈ। ਨਮੂਨੇ ਬਾਹਰਲਾ ਸ਼ਬਦ ਪੜਾਅ ਲਈ 32-bit float ਵਜੋਂ ਆਉਂਦੇ ਹਨ; ਨਮੂਨਾ ਫਾਰਮੈਟ conversion ਹੀ ਇਕੱਲਾ conversion ਹੈ।

ਬਾਹਰਲਾ ਸ਼ਬਦ platform ਦਾ ਸਥਾਨਕ ਸ਼ਬਦ API ਹੈ (desktop ਅਤੇ iOS ਉੱਤੇ cpal ਰਾਹੀਂ Core ਸ਼ਬਦ, Android ਉੱਤੇ AAudio)। ਬਾਹਰਲਾ ਸ਼ਬਦ ਧਾਰਾ **source's sample rate and channel count** ਲਈ configured ਹੈ: 96 kHz ਫਾਈਲ 96 kHz ਉੱਤੇ ਵੱਜਦੀ ਹੈ। ਮੁੜ-ਨਮੂਨਾ ਪੜਾਅ ਨਹੀਂ। ਮੂਲ ਬਾਹਰਲਾ ਸ਼ਬਦ ਯੰਤਰ ਹਰ ਧਾਰਾ ਬਣਾਵਟ ਉੱਤੇ ਨਿਰਧਾਰਤ ਹੁੰਦਾ ਹੈ, ਇਸ ਲਈ playback ਪ੍ਰਣਾਲੀ ਦੇ ਯੰਤਰ ਬਦਲਾਅ ਦਾ ਪਿੱਛਾ ਕਰਦਾ ਹੈ। Android ਉੱਤੇ, hardware-supported codecs offloaded ਡੀਕੋਡਿੰਗ ਲਈ FFmpeg ਨੂੰ ਪੂਰੀ ਤਰ੍ਹਾਂ ਪਾਰ ਕਰ ਸਕਦੇ ਹਨ।

## ਧਾਰਾ-ਸੁਣਾਈ ਪੜ੍ਹਤਾਂ

Playback ਨੂੰ ਪੂਰਾ ਫਾਈਲਾਂ ਦੀ ਲੋੜ ਨਹੀਂ। ਸ਼ਬਦ ਵਿਰਲਾ ਬਫਰ ਰਾਹੀਂ ਪੜ੍ਹਨਾ ਹੁੰਦਾ ਹੈ ਜੋ ਮੰਗ ਉੱਤੇ ਬਾਈਟ ranges fetch ਕਰਦਾ ਹੈ, ਸਥਾਨਕ ਫਾਈਲ, ਅਸਥਾਈ ਭੰਡਾਰ, ਜਾਂ ਕਲਾਉਡ ਤੋਂ, ਅਤੇ seeking ਲਕਸ਼ ਨਮੂਨਾ ਨੂੰ ਬਾਈਟ ਸਥਿਤੀ ਉੱਤੇ ਨਕਸ਼ਾ ਕਰਦੇ ਕਰਦੀ ਹੈ ਤਾਂ ਜੋ ਨਾ-ਲਿਆ ਖੇਤਰ ਵਿੱਚ seek ਉੱਥੋਂ fetch ਕਰੇ। Fetch ਨਿਰਣੇਤਾ playing ਟ੍ਰੈਕ ਦੇ ਪੜ੍ਹਤਾਂ ਨੂੰ ਪਹਿਲਾਂ-ਲੋਡ ਤੋਂ ਉੱਪਰ priority ਦਿੰਦਾ ਹੈ, ਇਸ ਲਈ ਆਉਣ ਵਾਲਾ ਟ੍ਰੈਕ ਮੌਜੂਦਾ ਟ੍ਰੈਕ ਨੂੰ ਦੇਰੀ ਨਹੀਂ ਕਰਦਾ।

## ਟ੍ਰੈਕ ਜਾਲਕਾਂ ਵਜੋਂ

ਟ੍ਰੈਕ ਫਾਈਲ ਨਹੀਂ; ਇਹ ਇੱਕ ਜਾਂ ਵੱਧ ਫਾਈਲਾਂ ਉੱਤੇ ਨਮੂਨਾ windows ਦੀ ਕ੍ਰਮਬੱਧ list ਹੈ, ਆਯਾਤ ਵੇਲੇ CUE sheet ਜਾਂ ਫਾਈਲ ਦੇ ਆਪਣੇ ਫੈਲਾਅ ਤੋਂ ਬਣੀ। ਇਹ ਇੱਕ ਨੁਮਾਇੰਦਗੀ ਹਰ ਡਿਸਕ shape ਰੱਖਦੀ ਹੈ: ਫਾਈਲ per ਟ੍ਰੈਕ, ਇੱਕ image ਵਿੱਚ ਪੂਰਾ ਡਿਸਕ, ਇੱਕ ਫਾਈਲ ਦੇ end ਅਤੇ ਦੂਜੇ ਦੇ start ਉੱਤੇ ਰਹਿਣ ਵਾਲਾ pregap, ਅਤੇ ਨੁਕਸਾਨੀ rips cut ਇੱਕ ਫਾਈਲ per ਟ੍ਰੈਕ।

Pregap windows ਇਸੇ ਤਰ੍ਹਾਂ ਨਿਸ਼ਾਨਿਤ ਹਨ। Playback ਟ੍ਰੈਕ ਦੇ pregap ਵਿੱਚ ਦਾਖਲ ਹੁੰਦਾ ਹੈ ਜਦੋਂ ਉਸ ਕੋਲ ਇੱਕ ਹੋਵੇ (ਸੂਚਕ 00, hidden-ਟ੍ਰੈਕ ਸ਼ਬਦ ਸ਼ਾਮਲ) ਜਦੋਂ ਘੜੀ ਟ੍ਰੈਕ time ਦਿਖਾਉਂਦਾ ਹੈ: ਸਥਿਤੀ ਟ੍ਰੈਕ ਅਸਲ ਸ਼ੁਰੂ ਹੋਣ ਤੱਕ ਸਿਫ਼ਰ ਉੱਤੇ ਫੜੀ ਰਹਿੰਦੀ ਹੁੰਦੀ ਹੈ, ਅਤੇ ਦਿਖਾਈ ਅਵਧੀ pregap ਨੂੰ exclude ਕਰਦੀ ਹੈ, CD ਸੁਣਾਉਣ ਵਾਲਾ ਦੇ ਵਰਤਾਅ ਨਾਲ ਮਿਲਦੀ ਹੈ।

## ਬਿਨਾ ਖਾਲੀ ਥਾਂ

ਅਗਲਾ ਟ੍ਰੈਕ ਮੌਜੂਦਾ ਟ੍ਰੈਕ ਵੱਜਦੇ ਹੋਏ ਖੋਲ੍ਹਿਆ ਅਤੇ ਬਫਰ ਕੀਤਾ ਹੁੰਦਾ ਹੈ। ਜਦੋਂ ਦੋਵੇਂ ਨਮੂਨਾ ਦਰ ਅਤੇ ਚੈਨਲ ਗਿਣਤੀ ਸਾਂਝੇ ਕਰਦੇ ਹਨ, ਯੰਤਰ live ਸ਼ਬਦ ਵਾਪਸੀ-ਸੱਦਾ ਦੇ ਅੰਦਰ ਉਨ੍ਹਾਂ ਨੂੰ ਜੋੜਦਾ ਕਰਦਾ ਹੈ: ਧਾਰਾ ਕਦੇ ਨਹੀਂ ਰੁਕਦਾ, ਅਤੇ ਹੱਦ ਨਮੂਨਾ-ਸਹੀ ਹੈ। ਜਦੋਂ ਫਾਰਮੈਟ ਵੱਖਰੇ ਹੋਣ, ਧਾਰਾ ਮੁੜ ਬਣਿਆ ਹੁੰਦਾ ਹੈ, ਜੋ ਉਹੀ ਹਾਲਤ ਹੈ ਜਿੱਥੇ ਫਾਰਮੈਟ ਬਦਲਾਅ ਹੱਦ ਨੂੰ ਸੁਣਨਯੋਗ ਕਰਦਾ ਹੀ ਹੈ।

## Loudness

ਆਯਾਤ decode-ਜਾਂਚ pass ਦੌਰਾਨ ਇਕੱਠੀ loudness (EBU R128) ਅਤੇ true peak, per ਟ੍ਰੈਕ ਅਤੇ per album, ਮਾਪਦਾ ਹੈ। ਮੁੜ-ਚਲਾਉਣਾ gain ਇਨ੍ਹਾਂ ਮਾਪ ਤੋਂ play time ਉੱਤੇ ਕੱਢਿਆ ਹੈ, ਫਾਈਲਾਂ ਵਿੱਚ ਕਦੇ ਸ਼ਾਮਲ ਨਹੀਂ: ਲਕਸ਼ -18 LUFS, ਸੀਮਿਤ ਤਾਂ ਜੋ true peak ਕਲਿਪ ਨਾ ਕਰੇ, per ਟ੍ਰੈਕ ਜਾਂ per album ਲਾਗੂ, gapless ਹੱਦਾਂ ਉੱਤੇ ਸਾਫ਼ ਬਦਲਣਾ। ਰੂਪ ਇਸ ਵੇਲੇ ਸੈਟਿੰਗਾਂ UI ਬਿਨਾ ਆਉਂਦਾ ਹੈ ਹੁੰਦਾ ਹੈ ਅਤੇ ਮੂਲ off ਹੈ; ਇਸਨੂੰ ਸੰਗ੍ਰਹਿ ਦੀ ਸੰਰਚਨਾ ਫਾਈਲ ਵਿੱਚ ਸਮੂਹ ਕੀਤਾ ਜਾ ਸਕਦਾ ਹੈ।

## ਪਾਸੀ ਰੋਕਾਂ

ਟ੍ਰੈਕ lists ਆਪਣੀ side ਅਤੇ ਡਿਸਕ ਬਣਤਰ ਰੱਖਦੀਆਂ ਹਨ, ਅਤੇ ਯੰਤਰ side ਹੱਦ ਉੱਤੇ ਰੋਕ ਕਰ ਸਕਦਾ ਹੈ, continue ਕਰਨ ਲਈ ਪੁੱਛਗਿੱਛ ਦਿਖਾਉਂਦਾ ਹੈ, ਜਦ ਵਰਤੋਂਕਾਰ pause-between-sides ਚਾਲੂ ਕਰਦਾ ਹੈ। ਰੋਕ playback-service ਹਾਲਤ ਹੈ, decoded silence ਨਹੀਂ, ਇਸ ਲਈ ਮੁੜ ਚਲਾਉਣਾ ਤੁਰੰਤ ਹੈ।
