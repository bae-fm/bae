bae ਵਿੱਚ ਕਿਤੇ ਵੀ ਖਾਤਾ ਪ੍ਰਣਾਲੀ ਨਹੀਂ। ਸੰਗ੍ਰਹਿ ਦਾ ਹਰ ਵਿਅਕਤੀ coven *ਮੈਂਬਰ* ਹੈ: ਇੱਕ ਬੇਤਰਤੀਬ, ਸਥਾਈ ਮੈਂਬਰ id ਅਤੇ ਦੋ ਕੁੰਜੀ-ਜੋੜੇ, ਇੱਕ ਦਸਤਖਤ ਲਈ ਅਤੇ ਇੱਕ ਜਿਸ ਲਈ ਕੁੰਜੀਆਂ ਮੋਹਰਬੰਦ ਹੁੰਦੀਆਂ ਹਨ; ਉਸ ਵਿਅਕਤੀ ਦੇ ਸਾਰੇ ਯੰਤਰ ਇਨ੍ਹਾਂ ਨੂੰ ਸਾਂਝਾ ਕਰਦੇ ਹਨ ਅਤੇ ਹਰ ਯੰਤਰ ਦੇ OS ਕੀਰਿੰਗ ਵਿੱਚ ਰੱਖਦੇ ਹਨ। ਯੰਤਰ ਇੱਕ ਇੰਸਟਾਲੇਸ਼ਨ ਹੈ, ਆਪਣੇ id ਨਾਲ, ਜੋ ਇੱਕ ਮੈਂਬਰ ਦਾ ਹੈ। ਸੰਗ੍ਰਹਿ ਵਿੱਚ ਕੌਣ ਹੈ, ਇਹ ਕਲਾਉਡ ਘਰ ਵਿੱਚ ਦਸਤਖਤੀ ਰਿਕਾਰਡਾਂ ਦਾ ਸਮੂਹ ਹੈ, ਜੋ ਹਰ ਮੈਂਬਰ ਦਾ ਯੰਤਰ ਜਾਂਚਦਾ ਹੈ, ਕੋਈ ਸਰਵਰ ਜਾਰੀ ਨਹੀਂ ਕਰਦਾ। ਪ੍ਰਣਾਲੀ [coven](https://coven.bae.fm) ਦੀ ਹੈ; ਇਹ ਪੰਨਾ ਦੱਸਦਾ ਹੈ ਕਿ bae ਇਸਨੂੰ ਕਿਵੇਂ ਵਰਤਦਾ ਹੈ।

## ਮੈਂਬਰਤਾ ਰਿਕਾਰਡ

ਕਲਾਉਡ ਘਰ ਵਿੱਚ ਸੰਗ੍ਰਹਿ ਦਾ ਪੂਰਾ ਇਤਿਹਾਸ ਇੱਕ ਨੰਬਰਦਾਰ ਲੜੀ ਹੈ, ਅਤੇ ਹਰ ਯੰਤਰ ਇਸਨੂੰ ਇੱਕੋ ਤਰਤੀਬ ਵਿੱਚ ਲਾਗੂ ਕਰਦਾ ਹੈ। ਮੈਂਬਰਤਾ ਜਾਂ ਸੈਟਿੰਗਾਂ ਦੀ ਤਬਦੀਲੀ ਉਸ ਲੜੀ ਵਿੱਚ ਇੱਕ *admin entry* ਹੈ, ਲੇਖਕ ਦੀ ਕੁੰਜੀ ਨਾਲ ਦਸਤਖਤੀ ਅਤੇ ਉਸਦੇ ਠੀਕ ਪਹਿਲਾਂ ਦੀ ਹਾਲਤ ਦੇ ਆਧਾਰ ਉੱਤੇ ਤੈਅ, ਇਸ ਲਈ ਹਰ ਯੰਤਰ ਆਪ ਉਸੇ ਫੈਸਲੇ ਉੱਤੇ ਪਹੁੰਚਦਾ ਹੈ। entry ਤਾਂ ਹੀ ਗਿਣੀ ਜਾਂਦੀ ਹੈ ਜੇ ਲੇਖਕ ਨੂੰ ਇਹ ਕਰਨ ਦਾ ਹੱਕ ਹੋਵੇ, ਅਤੇ ਸੰਗ੍ਰਹਿ ਹਮੇਸ਼ਾਂ ਘੱਟੋ-ਘੱਟ ਇੱਕ admin ਰੱਖਦਾ ਹੈ।

ਯੰਤਰ ਵੱਲੋਂ ਭੇਜੀ ਹਰ ਤਬਦੀਲੀ ਇਸ ਰਿਕਾਰਡ ਨਾਲ ਜਾਂਚੀ ਜਾਂਦੀ ਹੈ: ਮੌਜੂਦਾ ਮੈਂਬਰ ਦੇ ਦਸਤਖਤ, ਅਜਿਹੇ ਯੰਤਰ ਤੋਂ ਜੋ ਹਟਾਇਆ ਨਹੀਂ ਗਿਆ। ਹਟਾਏ ਯੰਤਰਾਂ ਜਾਂ ਮੈਂਬਰਾਂ ਤੋਂ, ਕਦੇ ਨਾ ਜੋੜੀਆਂ ਕੁੰਜੀਆਂ ਤੋਂ, ਜਾਂ ਗਲਤ ਦਸਤਖਤਾਂ ਵਾਲੀਆਂ ਤਬਦੀਲੀਆਂ ਗਿਣੀਆਂ ਨਹੀਂ ਜਾਂਦੀਆਂ। ਦਾਤਾ ਰਿਕਾਰਡ ਰੱਖਦਾ ਹੈ ਪਰ ਉਨ੍ਹਾਂ ਨੂੰ ਜਾਅਲੀ ਨਹੀਂ ਬਣਾ ਸਕਦਾ।

## ਭੂਮਿਕਾਵਾਂ

**Admin** ਅਤੇ **ਮੈਂਬਰ** ਦੋਵੇਂ ਸੰਗ੍ਰਹਿ ਪੜ੍ਹਦੇ ਅਤੇ ਲਿਖਦੇ ਹਨ: coven ਸੰਗ੍ਰਹਿ ਵਿੱਚ ਲਿਖਣ ਉੱਤੇ ਕੋਈ ਇਜਾਜ਼ਤ ਨਹੀਂ ਜਾਂਚਦਾ, ਇਸ ਲਈ ਸਿਰਫ਼-ਪੜ੍ਹਨ ਵਾਲੀ ਭੂਮਿਕਾ ਟਿਕ ਨਹੀਂ ਸਕਦੀ। admins ਇਸ ਤੋਂ ਇਲਾਵਾ ਲੋਕਾਂ ਨੂੰ ਸੱਦਦੇ ਅਤੇ ਹਟਾਉਂਦੇ ਹਨ, ਭੂਮਿਕਾਵਾਂ ਬਦਲਦੇ ਹਨ ਅਤੇ ਸੰਗ੍ਰਹਿ ਦਾ ਨਾਂ ਬਦਲਦੇ ਹਨ। ਜੋ ਵਿਅਕਤੀ ਸੰਗ੍ਰਹਿ ਨੂੰ ਉਸਦਾ ਕਲਾਉਡ ਘਰ ਦਿੰਦਾ ਹੈ ਉਹ ਉਸਦਾ ਪਹਿਲਾ admin ਹੈ।

| ਕਾਰਵਾਈ | ਕੌਣ |
|---|---|
| ਵਿਅਕਤੀ ਨੂੰ ਸੱਦਣਾ | admin |
| ਯੰਤਰ ਜੋੜਨਾ | ਵਿਅਕਤੀ ਆਪ, ਨਵੇਂ ਯੰਤਰ ਤੋਂ, ਆਪਣੇ restore code ਨਾਲ |
| ਯੰਤਰ ਹਟਾਉਣਾ | ਉਸਦਾ ਵਿਅਕਤੀ, ਜਾਂ ਕੋਈ ਵੀ admin |
| ਵਿਅਕਤੀ ਨੂੰ ਹਟਾਉਣਾ | admin |
| ਸੰਗ੍ਰਹਿ ਦਾ ਨਾਂ ਬਦਲਣਾ | admin |

ਵਿਅਕਤੀ ਦੀ profile, ratings, ਇਤਿਹਾਸ ਅਤੇ playlists owner ਕਤਾਰਾਂ ਹਨ: ਸਿਰਫ਼ ਉਸ ਵਿਅਕਤੀ ਦੇ ਯੰਤਰ ਇਨ੍ਹਾਂ ਨੂੰ ਬਦਲ ਸਕਦੇ ਹਨ, ਇਸ ਲਈ ਕਿਸੇ ਦੇ ਨਾਂ ਹੇਠ ਦਰਜ rating ਸੱਚਮੁੱਚ ਉਸੇ ਦੀ ਹੈ।

## ਆਪਣਾ ਯੰਤਰ ਜੋੜਨਾ

restore code ਸਾਬਤ ਕਰਦਾ ਹੈ ਕਿ ਯੰਤਰ ਉਸਦੇ ਵਿਅਕਤੀ ਦਾ ਹੈ, ਇਸ ਲਈ ਕੋਈ ਮਨਜ਼ੂਰੀ ਨਹੀਂ ਚਾਹੀਦੀ:

1. ਨਵਾਂ ਯੰਤਰ ਕੋਡ ਲੈਂਦਾ ਹੈ: ਵਿਅਕਤੀ ਦੇ ਕਿਸੇ ਹੋਰ ਯੰਤਰ ਉੱਤੇ ਦਿਖਾਇਆ QR ਕੋਡ ਸਕੈਨ ਕਰਕੇ, Apple ਯੰਤਰਾਂ ਉੱਤੇ iCloud Keychain ਤੋਂ, ਜਾਂ ਟਾਈਪ ਕਰਕੇ।
2. ਇਹ ਭੰਡਾਰਣ ਤੱਕ ਪਹੁੰਚਦਾ ਹੈ: Dropbox ਅਤੇ OneDrive ਉੱਤੇ ਵਿਅਕਤੀ ਦੇ ਆਪਣੇ ਖਾਤੇ ਵਿੱਚ ਸਾਈਨ ਇਨ ਕਰਕੇ, S3 ਉੱਤੇ ਉਸਦੀ access key ਨਾਲ, ਜੋ QR ਕੋਡ ਕੋਡ ਦੇ ਨਾਲ ਲਿਆਉਂਦਾ ਹੈ।
3. ਇਹ ਸੰਗ੍ਰਹਿ ਲੋਡ ਕਰਦਾ ਹੈ, ਜਾਂਚਦਾ ਹੈ ਕਿ ਕੋਡ ਦੀਆਂ ਕੁੰਜੀਆਂ ਮੌਜੂਦਾ ਮੈਂਬਰ ਦੀਆਂ ਹਨ, ਅਤੇ ਉਨ੍ਹਾਂ ਕੁੰਜੀਆਂ ਨਾਲ ਦਸਤਖਤੀ entry ਰਾਹੀਂ ਆਪਣੇ-ਆਪ ਨੂੰ ਨਵੇਂ ਯੰਤਰ ਵਜੋਂ ਦਰਜ ਕਰਦਾ ਹੈ।

ਜਿਸ ਕੋਡ ਦੀਆਂ ਕੁੰਜੀਆਂ ਬਾਅਦ ਵਿੱਚ ਬਦਲ ਗਈਆਂ ਹੋਣ ਉਹ ਫੇਲ੍ਹ ਹੁੰਦਾ ਹੈ। ਬਹਾਲੀ ਹਮੇਸ਼ਾਂ ਨਵਾਂ ਯੰਤਰ ਬਣਾਉਂਦੀ ਹੈ; ਇਹ ਕਿਸੇ ਹੋਰ ਇੰਸਟਾਲੇਸ਼ਨ ਦੀਆਂ ਨਾ-ਭੇਜੀਆਂ ਸੋਧਾਂ ਨਹੀਂ ਬਚਾਉਂਦੀ।

## ਵਿਅਕਤੀ ਨੂੰ ਸੱਦਣਾ

1. admin ਵਿਅਕਤੀ ਦਾ ਦਾਤਾ ਖਾਤਾ ਭਰਦਾ ਹੈ ਅਤੇ ਉਸਦੀ ਭੂਮਿਕਾ ਚੁਣਦਾ ਹੈ। bae ਸੰਗ੍ਰਹਿ ਦਾ ਫੋਲਡਰ ਉਸ ਖਾਤੇ ਨਾਲ ਸਾਂਝਾ ਕਰਦਾ ਹੈ, ਜਾਂ S3 ਉੱਤੇ ਉਸ ਲਈ access key ਬਣਾਉਂਦਾ ਹੈ, ਅਤੇ ਸੱਦਾ ਦਿਖਾਉਂਦਾ ਹੈ: ਇੱਕ QR ਕੋਡ ਜਿਸ ਵਿੱਚ ਸੰਗ੍ਰਹਿ ਦੀ ਥਾਂ, ਉਸ ਵਿਅਕਤੀ ਲਈ ਚੁਣਿਆ ਮੈਂਬਰ id, ਇੱਕ ਵਾਰ ਵਰਤਿਆ ਜਾਣ ਵਾਲਾ ਰਾਜ਼ ਅਤੇ ਸੰਗ੍ਰਹਿ ਦਾ ਮੌਜੂਦਾ ਨਾਂ ਹੁੰਦਾ ਹੈ। ਇਹ ਬਣਨ ਤੋਂ ਇੱਕ ਦਿਨ ਬਾਅਦ ਮੁੱਕ ਜਾਂਦਾ ਹੈ।
2. ਵਿਅਕਤੀ ਦਾ ਯੰਤਰ ਇਸਨੂੰ ਸਕੈਨ ਕਰਦਾ ਹੈ, ਉਸਦੇ ਆਪਣੇ ਖਾਤੇ ਵਿੱਚ ਸਾਈਨ ਇਨ ਕਰਦਾ ਹੈ, ਉਸਦੇ ਕੁੰਜੀ-ਜੋੜੇ ਬਣਾਉਂਦਾ ਹੈ ਅਤੇ ਭੰਡਾਰਣ ਵਿੱਚ ਜੁੜਨ ਦੀ ਬੇਨਤੀ ਲਿਖਦਾ ਹੈ, ਸੱਦੇ ਦੇ ਰਾਜ਼ ਤੋਂ ਬਣੀ ਕੁੰਜੀ ਨਾਲ ਇਨਕ੍ਰਿਪਟ ਅਤੇ ਉਸਦੀ ਨਵੀਂ ਕੁੰਜੀ ਨਾਲ ਦਸਤਖਤੀ।
3. admin ਦਾ ਯੰਤਰ, ਰਾਜ਼ ਰੱਖਣ ਵਾਲਾ ਇੱਕੋ-ਇੱਕ ਯੰਤਰ, ਬੇਨਤੀ ਦਿਖਾਉਂਦਾ ਹੈ, ਅਤੇ admin ਇਸਨੂੰ ਮਨਜ਼ੂਰ ਕਰਦਾ ਹੈ।
4. ਮਨਜ਼ੂਰੀ ਹਰ store key ਨੂੰ ਵਿਅਕਤੀ ਦੀ ਨਵੀਂ ਮੋਹਰ ਕੁੰਜੀ ਲਈ ਮੋਹਰਬੰਦ ਕਰਦੀ ਹੈ, ਫਿਰ ਉਸਨੂੰ ਸਵੀਕਾਰ ਕਰਨ ਵਾਲੀ entry ਜੋੜਦੀ ਹੈ।
5. ਨਵਾਂ ਯੰਤਰ ਆਪਣੀਆਂ ਕੁੰਜੀਆਂ ਖੋਲ੍ਹਦਾ ਹੈ, ਸੰਗ੍ਰਹਿ ਲੋਡ ਕਰਦਾ ਹੈ, ਆਪਣੇ-ਆਪ ਨੂੰ ਦਰਜ ਕਰਦਾ ਹੈ ਅਤੇ ਵਿਅਕਤੀ ਦੇ ਟਾਈਪ ਕੀਤੇ ਨਾਂ ਨਾਲ ਉਸਦੀ profile ਲਿਖਦਾ ਹੈ।

ਸੱਦਾ ਰੱਦ ਕਰਨ ਨਾਲ, ਜਾਂ ਉਸਨੂੰ ਮੁੱਕਣ ਦੇਣ ਨਾਲ, ਉਸ ਵੱਲੋਂ ਦਿੱਤੀ ਦਾਤਾ ਪਹੁੰਚ ਵਾਪਸ ਲੈ ਲਈ ਜਾਂਦੀ ਹੈ।

## ਹਟਾਉਣਾ

ਯੰਤਰ ਜਾਂ ਵਿਅਕਤੀ ਨੂੰ ਹਟਾਉਣਾ ਇੱਕ admin entry ਹੈ, ਅਤੇ ਲੜੀ ਵਿੱਚ ਉਸਦੀ ਥਾਂ ਇਤਿਹਾਸ ਵਿੱਚ ਇੱਕ ਲਕੀਰ ਹੈ: ਹਟਾਇਆ ਯੰਤਰ ਜਾਂ ਵਿਅਕਤੀ ਉਸ ਤੋਂ ਬਾਅਦ ਜੋ ਭੇਜੇ ਉਹ ਗਿਣਿਆ ਨਹੀਂ ਜਾਂਦਾ, ਜਦਕਿ ਪਹਿਲਾਂ ਪਹੁੰਚਿਆ ਬਣਿਆ ਰਹਿੰਦਾ ਹੈ। ਵਿਅਕਤੀ ਨੂੰ ਹਟਾਉਣਾ ਉਸਦੇ ਯੰਤਰ ਅਤੇ ਉਸਦਾ ਨਿੱਜੀ circle ਵੀ ਹਟਾਉਂਦਾ ਹੈ, ਅਤੇ ਉਸ ਕੋਲ ਰਹੀਆਂ ਕੁੰਜੀਆਂ ਹੋਰ ਡਾਟਾ ਲਿਖੇ ਜਾਣ ਤੋਂ ਪਹਿਲਾਂ ਬਦਲ ਜਾਂਦੀਆਂ ਹਨ ([ਇਨਕ੍ਰਿਪਸ਼ਨ](/pa/reference/encryption#ਕੁੰਜੀ-ਬਦਲੀ) ਵੇਖੋ)। ਭੰਡਾਰਣ ਪਹੁੰਚ ਕੱਟਣਾ ਦਾਤੇ ਦਾ ਕੰਮ ਹੈ: ਜਿਸ ਖਾਤੇ ਵਿੱਚ ਸੰਗ੍ਰਹਿ ਹੈ ਉਸਦਾ ਯੰਤਰ ਫੋਲਡਰ ਸਾਂਝਾ ਕਰਨਾ ਬੰਦ ਕਰਦਾ ਹੈ, ਅਤੇ S3 ਉੱਤੇ ਵਿਅਕਤੀ ਦੀ access key ਮਿਟਾਈ ਜਾਂਦੀ ਹੈ। ਹਟਾਏ ਯੰਤਰ ਉੱਤੇ ਪਹਿਲਾਂ ਸਮਕਾਲੀ ਹੋਇਆ ਉਸ ਕੋਲ ਰਹਿੰਦਾ ਹੈ; ਡਾਟਾ ਵਾਪਸ ਨਹੀਂ ਲਿਆ ਜਾ ਸਕਦਾ।

## ਬਹਾਲੀ ਕੋਡ

restore code ਵਿੱਚ ਮੈਂਬਰ ਦਾ id ਅਤੇ ਉਸਦੇ ਮੌਜੂਦਾ ਨਿੱਜੀ ਕੁੰਜੀ-ਜੋੜੇ, ਸੰਗ੍ਰਹਿ ਦਾ store id ਅਤੇ ਉਸਦੀ ਭੰਡਾਰਣ ਥਾਂ ਹੁੰਦੇ ਹਨ; ਭੰਡਾਰਣ ਪ੍ਰਮਾਣ-ਪੱਤਰ, ਸਾਈਨ-ਇਨ ਟੋਕਨ ਜਾਂ ਸੰਗ੍ਰਹਿ ਦਾ ਨਾਂ ਕਦੇ ਨਹੀਂ। ਇਹ ਮੰਗ ਉੱਤੇ ਦਿਖਾਇਆ ਜਾਂਦਾ ਹੈ, Apple ਪਲੇਟਫਾਰਮਾਂ ਉੱਤੇ ਆਪਣੇ-ਆਪ iCloud Keychain ਵਿੱਚ ਸਾਂਭਿਆ ਜਾਂਦਾ ਹੈ, ਅਤੇ ਸੰਗ੍ਰਹਿ ਜਿੰਨਾ ਹੀ ਨਾਜ਼ੁਕ ਹੈ: ਜਿਸ ਕੋਲ ਇਹ ਅਤੇ ਭੰਡਾਰਣ ਪਹੁੰਚ ਹੈ, ਸੰਗ੍ਰਹਿ ਲਈ ਉਹੀ ਉਹ ਵਿਅਕਤੀ ਹੈ। ਹਰ ਯੰਤਰ ਅਤੇ ਆਪਣਾ ਕੋਡ ਗੁਆ ਚੁੱਕੇ ਵਿਅਕਤੀ ਨੂੰ admin ਉਸਦੇ ਮੌਜੂਦਾ ਮੈਂਬਰ id ਉੱਤੇ ਮੁੜ ਸੱਦ ਸਕਦਾ ਹੈ, ਜਿਸ ਨਾਲ ਉਸਦੀਆਂ ਕੁੰਜੀਆਂ ਬਦਲ ਜਾਂਦੀਆਂ ਹਨ।
