title: Architecture
description: Native apps on one Rust core, on coven
---

bae is one Rust core wearing four native apps. Everything that defines the product, the library model, import, playback, sync, encryption, lives in Rust and behaves identically on every platform; each app is a thin native UI over it.

## The layers

- **`bae-core`**: the product. Library and metadata model, the import and identify pipelines, the FFmpeg playback engine, loudness analysis, export, and the integration with coven below it. Import and identify compile only on desktop; mobile builds are sync and playback clients.
- **[coven](https://coven.bae.fm)**: the data layer, a separate library. coven owns the SQLite connection, captures every change bae commits, and syncs those changes end-to-end encrypted through the user's cloud storage. It also owns blob storage (audio bytes, artwork), the local cache, identity keys, and membership. bae pins an exact coven revision and stamps it into every binary; it defines the sync-compatibility generation between builds.
- **`bae-bridge`**: the UniFFI boundary. Bridge types are defined once in Rust and generated into Swift and Kotlin at build time.
- **The apps**: SwiftUI on macOS and iOS, Jetpack Compose on Android, and a native Windows app. Each also implements the platform pieces the core asks for: audio output, artwork text recognition, media controls, keychain access, crash reporting.

Alongside the apps: `bae-mcp` (the MCP server) and `bae-automation`.

## One library on disk

A library lives in two directories (platform data directories on mobile): coven's store, and bae's own settings beside it.

```
~/.bae/stores/<id>/       # coven's store, opened only through coven
  store.db                # SQLite: catalog, credits, playback specs, coven's bookkeeping
  files/                  # coven's copies of bae's own files (covers, artist images, avatars)
  cache/                  # cached and pinned copies of uploaded files
~/.bae/libraries/<id>/    # bae's own; never synced
  preferences.toml        # bae's settings
  cache/                  # artwork fetched from the catalogs
```

The database is opened only through coven, which keeps its own bookkeeping tables (merge records, upload queue, file state) next to bae's schema and runs bae's migration. A local release's audio files are not under `~/.bae` at all: the database references them at the paths where they were imported.

Secrets never live in these files. Member keys, the library's keys, cloud sign-ins, and API tokens live in the OS keyring (Keychain on Apple platforms, the platform equivalents elsewhere); on Apple platforms the restore code is also saved in iCloud Keychain.

## Editions

Two build-time editions exist on every platform. **bae** compiles in the OAuth providers (Dropbox, OneDrive), CloudKit, and telemetry. **baeium** compiles all of that out: S3-compatible storage only, and no telemetry, nothing proprietary in the dependency tree. The editions are the same source and the same core; a feature flag decides the provider list and the diagnostics wiring.

## Versioning

Apps version as `MAJOR.MINOR` per platform. The major is the compatibility era, shared by every app: devices on the same major can sync a library. It bumps only when a wire or on-disk format breaks, most often the pinned coven revision. Minors count releases per app and are not comparable across platforms.
