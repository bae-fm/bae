title: インポート
description: 各フォルダーがインポートのメタデータをどこから得るかを選びます

フォルダーは、インポートする音声とその他のファイルを提供します。編集できるメタデータを、オンラインのリリース、フォルダー自身のメタデータ、空のフォームのどれから始めるかを選びます。

インポートはデスクトップ（macOS、Windows）で行います。ファイルは読み取られるだけで、変更されません。bae は移動、リネーム、タグ書き換え、再エンコードを行いません。インポート後のファイルの置き場所については、[ストレージとオフライン](/ja/guide/storage) を参照してください。

## 監視フォルダー

**取り込む** セクションに切り替え、フォルダーを追加します。選択する、ウィンドウへドラッグする、または <kbd>⌘I</kbd> を押します。以後、bae はそのフォルダーを監視します。そこへ追加された新しい音楽は、自動的に新しい候補として表示されます。手作業で再スキャンする必要はありません。まだダウンロード中のフォルダーは、完了するまで無視されます。

スキャンは、リッピングが実際に取る形のリリースを認識します。

| レイアウト | 見た目 |
|--------|-------------------|
| トラックごとにファイル | `01 - Song.flac`, `02 - Song.flac`, … |
| CUE + イメージ | `album.cue` + `album.flac`、ディスク全体が 1 つのファイル |
| 複数ディスク | `CD1/`, `CD2/` サブフォルダー、内部はどちらの形でも可 |
| コレクション | フォルダーの中にフォルダーがあり、それぞれが独自のリリース |

bae は、再生できる形式をインポートします。FLAC、MP3、APE、`.m4a` 内の ALAC と AAC、WAV、AIFF、Ogg Vorbis、Opus、WavPack、DSD（`.dsf`/`.dff`）です。フォルダー内のアートワークと文書（CUE シート、リッピングログ、テキストファイル）は認識され、リリースと一緒に保持されます。

## メタデータの下書きを埋める

各候補は、編集できるメタデータの下書きを 1 つ持ちます。下書きは空から始めることも、オンラインのリリースから埋めることも、フォルダー自身のファイルの内容から埋めることもできます。空の下書きへの入力は直接入力であり、別のメタデータソースではありません。

カードの **識別** コントロールには、識別ページへの入り方が 2 つあり、何を開始するかが異なります。**自動** はページを開き、候補がすでに何を持っていても、毎回新しい識別の実行を要求します。実行中の識別は破棄され、新しいものに置き換わります。**検索** は同じページを手動検索で開き、何も開始しません。どちらも下書きを変更しません。結果を適用すると下書きが置き換わり、編集できるカードに戻ります。カードのメニューには、下書きをその場で書き換えるコマンドが 2 つあります。候補自身のファイル、シート、フォルダー名の内容で置き換える **ファイルのメタデータにリセット** と、下書きを空にする **メタデータを消去** です。どちらも先に確認を求め、候補のファイルやトラック構成には触れません。

### 識別

識別ページは、フォルダーがどのリリースなのかを見つけます。フォルダーから手がかりを読み取り、それぞれを照会します。

- **ディスク ID。** CD の正確なトラック構成のフィンガープリントで、リッピングログまたは CUE シートから計算されます。一致すれば、CD の正確な版を特定します。
- **バーコード。** フォルダー内のカバースキャンから文字認識で読み取るか、CUE シートから読み取ります。
- **カタログ番号とテキスト。** アートワークやファイル名、フォルダー名で見つかったカタログ番号で、結果の絞り込みに使います。

シグナルは MusicBrainz と Discogs に同時に照会され、結果は相互に照合されます。各シグナルは結果の上にバッジとして表示されます。何が見つかったか、どこから来たか（ポインターを重ねると出どころが表示されます: ディスク TOC、CUE シート、カバースキャン、フォルダー名）を確認でき、誤解を招くシグナルは個別にオフにできます。

結果は 3 通りです。

- **見つかりました。** 手がかりが 1 つのリリースグループで一致します。その一覧から正確な盤を選びます。
- **競合。** 2 つのシグナルが別々のリリースを指しています。たとえばディスク ID とバーコードが食い違う場合です。bae は両方を示し、どちらを信頼するかを選ぶか、シグナルを無視します。
- **見つかりませんでした。** 手動で検索します。アーティストとアルバム、カタログ番号、バーコードで、どちらかのデータベースを検索します。アートワークから認識したテキストが入力候補として提示されます。

ソースブラウザーには、検索フォーム、識別の進行状況、シグナル、結果がまとめて表示されます。結果を選ぶと、bae がリリース全体を取得する間その行が進行状況とともに開いたままになり、その後下書きに適用されます。できあがったカードには MusicBrainz または Discogs のソースチップが表示されます。カードの **自動** は最初からやり直し、**検索** は見つかったものを残したまま手動検索に戻ります。

自動識別も同じ経路を使います。候補が追加されると、その下書きはファイル、シート、フォルダー名から作られます。設定、取り込む の **自動で識別** は、現在のファイルに対する結果を持たないすべての候補で識別を実行します。オフの場合は、各実行を自分で開始します。事前に埋められた下書きは出発点であって答えではないため、実行を止めません。

### ファイルのメタデータ

ファイルのメタデータは、候補が追加されたときの事前入力で読み取られ、**ファイルのメタデータにリセット** を選ぶたびに再び読み取られます。どちらの場合も、下書きはその読み取り結果（埋め込みの音声タグ、CUE メタデータ、フォルダー自身の名前）そのもので置き換えられ、カードはそれに合わせて描き直されます。読み取り後に候補やその音声ファイルが変わった場合、インポートはライブラリに書き込む前に失敗します。

下書きがその読み取り結果を保持している間、編集できるカードには控えめなファイルのメタデータのチップが表示されます。入力だけで埋めた下書きにはソースチップはありません。

## 確認してインポート

確認ペインには、インポートが書き込むものがすべて表示されます。

- **カバー。** データベースのアートワーク、フォルダー内の画像、ファイルに埋め込まれたアートワークから選びます。候補のギャラリーから画像をカバーの枠へドラッグするか、後で変更します。
- **メタデータ。** アルバム、アーティスト、年、レーベル、カタログ番号、国、バーコード、すべてのトラックです。保存前にここですべて編集できます。
- **ストレージ。** クラウドホームが接続されている場合、**クラウド** を選ぶとリリースをそこへアップロードし、**ピン留め済み** を選ぶとそのファイルをこのデバイスにも保持します。そうでなければリリースはローカルです。情報は他のデバイスに同期され、音声はこのデバイスに残ります。[ストレージとオフライン](/ja/guide/storage) を参照してください。

インポートはバックグラウンドで実行されます。bae はすべてのトラックが問題なくデコードできることを検証し、アルバムと各トラックのラウドネスを測定し、リリースを保存し、クラウドへのインポートではアップロードを開始します。候補一覧は次のフォルダーへ進み、リリースはすぐ再生できます。

## データソース

**MusicBrainz** にはアカウントもキーも不要です。**Discogs** には自分の無料 API トークンが必要です。設定、取り込む に貼り付けると、動作しなくなった場合に bae が知らせます。トークンがない場合、Discogs 検索と Discogs 由来のメタデータは使えませんが、それ以外は動作します。どちらのサービスにもレート制限があります。bae は制限内に収まるようリクエストの間隔を調整します。
