bae માં ક્યાંય ખાતા વ્યવસ્થા નથી. લાઇબ્રેરીની દરેક વ્યક્તિ coven *સભ્ય* છે: એક રેન્ડમ, કાયમી સભ્ય id અને બે key pairs, એક સહી માટે અને એક જેના માટે કી seal થાય છે; તે વ્યક્તિના બધા ઉપકરણો તેમને વહેંચે છે અને દરેક ઉપકરણના OS keyring માં રાખે છે. ઉપકરણ એક ઇન્સ્ટોલેશન છે, પોતાના id સાથે, જે એક સભ્યનું હોય છે. લાઇબ્રેરીમાં કોણ છે તે cloud home માં સહી કરેલા records નો સમૂહ છે, જે દરેક સભ્યનું ઉપકરણ ચકાસે છે, કોઈ server જારી કરતું નથી. વ્યવસ્થા [coven](https://coven.bae.fm) ની છે; આ page બતાવે છે કે bae તેને કેવી રીતે વાપરે છે.

## Membership records

Cloud home માં લાઇબ્રેરીનો આખો ઇતિહાસ એક ક્રમાંકિત ક્રમ છે, અને દરેક ઉપકરણ તેને એક જ ક્રમમાં લાગુ કરે છે. સભ્યપદ કે settings નો ફેરફાર એ ક્રમમાં એક *admin entry* છે, લેખકની key થી સહી કરેલી અને તેની તરત પહેલાંની સ્થિતિના આધારે નક્કી થતી, તેથી દરેક ઉપકરણ જાતે એ જ નિર્ણય પર પહોંચે છે. Entry ત્યારે જ ગણાય છે જ્યારે લેખકને તે કરવાનો અધિકાર હોય, અને લાઇબ્રેરી હંમેશા ઓછામાં ઓછો એક admin રાખે છે.

ઉપકરણ મોકલે તે દરેક ફેરફાર આ record સામે ચકાસાય છે: હાલના સભ્યની સહી, એવા ઉપકરણ પરથી જે દૂર કરાયું નથી. દૂર કરાયેલાં ઉપકરણો કે સભ્યોના, ક્યારેય ન ઉમેરાયેલી કીના, કે અમાન્ય સહીવાળા ફેરફારો ગણાતા નથી. પ્રદાતા records રાખે છે પણ બનાવટી બનાવી શકતો નથી.

## Roles

**Admin** અને **સભ્ય** બંને લાઇબ્રેરી વાંચે અને લખે છે: coven લાઇબ્રેરીમાં લખવા પર કોઈ પરવાનગી ચકાસતું નથી, તેથી ફક્ત-વાંચવાની ભૂમિકા ટકી ન શકે. Admins વધારામાં લોકોને આમંત્રિત કરે અને દૂર કરે છે, ભૂમિકાઓ બદલે છે અને લાઇબ્રેરીનું નામ બદલે છે. જે વ્યક્તિ લાઇબ્રેરીને તેનું cloud home આપે તે તેની પહેલી admin છે.

| ક્રિયા | કોણ |
|---|---|
| વ્યક્તિને આમંત્રણ આપવું | admin |
| ઉપકરણ ઉમેરવું | વ્યક્તિ પોતે, નવા ઉપકરણ પરથી, પોતાના restore code સાથે |
| ઉપકરણ દૂર કરવું | તેની વ્યક્તિ, અથવા કોઈ પણ admin |
| વ્યક્તિને દૂર કરવી | admin |
| લાઇબ્રેરીનું નામ બદલવું | admin |

વ્યક્તિની profile, ratings, ઇતિહાસ અને playlists owner હરોળો છે: ફક્ત તે વ્યક્તિનાં ઉપકરણો તેમને બદલી શકે છે, તેથી કોઈના નામે નોંધાયેલું rating ખરેખર તેનું જ હોય છે.

## તમારું પોતાનું ઉપકરણ ઉમેરવું

Restore code સાબિત કરે છે કે ઉપકરણ તેની વ્યક્તિનું છે, તેથી કોઈ મંજૂરીની જરૂર નથી:

1. નવું ઉપકરણ code મેળવે છે: વ્યક્તિના બીજા ઉપકરણે બતાવેલો QR code સ્કેન કરીને, Apple ઉપકરણો પર iCloud Keychain માંથી, અથવા ટાઇપ કરીને.
2. તે સ્ટોરેજ સુધી પહોંચે છે: Dropbox અને OneDrive પર વ્યક્તિના પોતાના ખાતામાં સાઇન ઇન કરીને, S3 પર તેની access key થી, જે QR code code ની બાજુમાં લાવે છે.
3. તે લાઇબ્રેરી લોડ કરે છે, ચકાસે છે કે code ની કી હાલના સભ્યની છે, અને તે કીથી સહી કરેલી entry વડે પોતાને નવા ઉપકરણ તરીકે નોંધે છે.

જેની કી પછીથી બદલાઈ ગઈ હોય તે code નિષ્ફળ જાય છે. પુનઃસ્થાપન હંમેશા નવું ઉપકરણ બનાવે છે; તે બીજા ઇન્સ્ટોલેશનનાં ન મોકલાયેલાં સંપાદનો બચાવતું નથી.

## વ્યક્તિને આમંત્રણ આપવું

1. Admin તે વ્યક્તિનું પ્રદાતા ખાતું દાખલ કરે છે અને તેની ભૂમિકા પસંદ કરે છે. bae લાઇબ્રેરીનું ફોલ્ડર તે ખાતા સાથે શેર કરે છે, અથવા S3 પર તેના માટે access key બનાવે છે, અને આમંત્રણ બતાવે છે: એક QR code જેમાં લાઇબ્રેરીની જગ્યા, તે વ્યક્તિ માટે પસંદ કરેલો સભ્ય id, એક વાર વપરાતું ગુપ્ત મૂલ્ય અને લાઇબ્રેરીનું હાલનું નામ હોય છે. તે બન્યાના એક દિવસ પછી સમાપ્ત થાય છે.
2. વ્યક્તિનું ઉપકરણ તેને સ્કેન કરે છે, તેના પોતાના ખાતામાં સાઇન ઇન કરે છે, તેની key pairs બનાવે છે અને સ્ટોરેજમાં જોડાવાની વિનંતી લખે છે, જે આમંત્રણના ગુપ્ત મૂલ્યમાંથી મેળવેલી key થી encrypted અને તેની નવી key થી સહી કરેલી હોય છે.
3. Admin નું ઉપકરણ, ગુપ્ત મૂલ્ય ધરાવતું એકમાત્ર ઉપકરણ, વિનંતી બતાવે છે, અને admin તેને મંજૂર કરે છે.
4. મંજૂરી દરેક store key ને વ્યક્તિની નવી sealing key માટે seal કરે છે, પછી તેને સ્વીકારતી entry ઉમેરે છે.
5. નવું ઉપકરણ પોતાની કી ખોલે છે, લાઇબ્રેરી લોડ કરે છે, પોતાને નોંધે છે અને વ્યક્તિએ ટાઇપ કરેલા નામ સાથે તેની profile લખે છે.

આમંત્રણ નકારવાથી, અથવા તેને સમાપ્ત થવા દેવાથી, તેણે આપેલી પ્રદાતા પહોંચ પાછી ખેંચાય છે.

## દૂર કરવું

ઉપકરણ અથવા વ્યક્તિને દૂર કરવી એ admin entry છે, અને ક્રમમાં તેની જગ્યા ઇતિહાસમાં એક રેખા છે: દૂર કરાયેલું ઉપકરણ કે વ્યક્તિ ત્યાર પછી જે મોકલે તે ગણાતું નથી, જ્યારે પહેલાં પહોંચેલું રહે છે. વ્યક્તિને દૂર કરવાથી તેનાં ઉપકરણો અને તેનું ખાનગી circle પણ દૂર થાય છે, અને તેની પાસેની કી વધુ ડેટા લખાય તે પહેલાં બદલાઈ જાય છે ([Encryption](/gu/reference/encryption#ફેરબદલ) જુઓ). સ્ટોરેજ પહોંચ કાપવી એ પ્રદાતાનું કામ છે: લાઇબ્રેરી જે ખાતામાં છે તેનું ઉપકરણ ફોલ્ડરનું શેરિંગ બંધ કરે છે, અને S3 પર વ્યક્તિની access key કાઢી નાખવામાં આવે છે. દૂર કરાયેલા ઉપકરણ પર પહેલેથી sync થયેલું તેની પાસે જ રહે છે; ડેટા પાછો લઈ શકાતો નથી.

## રિસ્ટોર કોડ

Restore code માં સભ્યનો id અને તેની હાલની ખાનગી key pairs, લાઇબ્રેરીનો store id અને તેની સ્ટોરેજ જગ્યા હોય છે; સ્ટોરેજ ઓળખપત્રો, સાઇન-ઇન tokens કે લાઇબ્રેરીનું નામ ક્યારેય નહીં. તે માંગ પર બતાવાય છે, Apple પ્લેટફોર્મ પર iCloud Keychain માં આપમેળે સચવાય છે, અને લાઇબ્રેરી જેટલો જ સંવેદનશીલ છે: જેની પાસે તે અને સ્ટોરેજની પહોંચ છે, લાઇબ્રેરી માટે તે જ તે વ્યક્તિ છે. દરેક ઉપકરણ અને પોતાનો code ગુમાવનાર વ્યક્તિને admin તેના હાલના સભ્ય id પર ફરી આમંત્રિત કરી શકે છે, જેનાથી તેની કી બદલાય છે.
