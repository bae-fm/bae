bae ચાર native apps પહેરેલું એક Rust core છે. Product ને define કરતું બધું, library model, import, playback, sync, encryption, Rust માં રહે છે અને દરેક platform પર સમાન રીતે વર્તે છે; દરેક app તેના ઉપર thin native UI છે.

## Layers

- **`bae-core`**: product. Library અને metadata model, import અને identify pipelines, FFmpeg playback engine, loudness analysis, export, અને નીચેના coven સાથે integration. Import અને identify ફક્ત desktop પર compile થાય છે; mobile builds sync અને playback clients છે.
- **[coven](https://coven.bae.fm)**: data layer, અલગ library. coven SQLite connection own કરે છે, bae commit કરે તે દરેક change capture કરે છે, અને user ના cloud storage મારફતે તે changes end-to-end encrypted sync કરે છે. તે blob storage (audio bytes, artwork), local cache, identity keys, અને membership પણ own કરે છે. bae exact coven revision pin કરે છે અને દરેક binary માં stamp કરે છે; તે builds વચ્ચે sync-compatibility generation define કરે છે.
- **`bae-bridge`**: UniFFI boundary. Bridge types Rust માં એક વાર defined છે અને build time પર Swift અને Kotlin માં generated થાય છે.
- **Apps**: macOS અને iOS પર SwiftUI, Android પર Jetpack Compose, અને native Windows app. દરેક core માગે તે platform pieces પણ implement કરે છે: audio output, artwork text recognition, media controls, keychain access, crash reporting.

Apps સાથે: `bae-mcp` (MCP server) અને `bae-automation`.

## Disk પર એક library

લાઇબ્રેરી બે directories માં રહે છે (mobile પર platform data directories): coven નો store, અને તેની બાજુમાં bae ની પોતાની settings.

```
~/.bae/stores/<id>/       # coven નો store, ફક્ત coven મારફતે ખોલાય છે
  store.db                # SQLite: catalog, credits, playback specs, coven નો હિસાબ
  files/                  # bae ની પોતાની files ની coven નકલો (covers, કલાકારની છબીઓ, avatars)
  cache/                  # upload થયેલી files ની cache અને pinned નકલો
~/.bae/libraries/<id>/    # bae નું પોતાનું; ક્યારેય sync થતું નથી
  preferences.toml        # bae ની settings
  cache/                  # catalogs માંથી લાવેલું artwork
```

Database ફક્ત coven મારફતે ખૂલે છે, જે bae ના schema ની બાજુમાં પોતાનાં હિસાબી tables (ભેગા કરવાના records, upload કતાર, file સ્થિતિ) રાખે છે અને bae નું migration ચલાવે છે. સ્થાનિક release ની audio files `~/.bae` નીચે બિલકુલ નથી: database તેમને જ્યાંથી import થઈ હતી તે paths પર જ દર્શાવે છે.

ગુપ્ત બાબતો આ files માં ક્યારેય રહેતી નથી. સભ્ય કી, લાઇબ્રેરીની કી, cloud સાઇન-ઇન અને API tokens OS keyring માં રહે છે (Apple પ્લેટફોર્મ પર Keychain, બીજે પ્લેટફોર્મ સમકક્ષ); Apple પ્લેટફોર્મ પર restore code iCloud Keychain માં પણ સચવાય છે.

## Editions

દરેક platform પર બે build-time editions છે. **bae** OAuth providers (Dropbox, OneDrive), CloudKit, અને telemetry compile કરે છે. **baeium** આ બધું compile out કરે છે: ફક્ત S3-compatible storage, અને telemetry નહીં, dependency tree માં proprietary કશું નહીં. Editions એ જ source અને એ જ core છે; feature flag provider list અને diagnostics wiring નક્કી કરે છે.

## Versioning

Apps દરેક platform પ્રમાણે `MAJOR.MINOR` તરીકે version થાય છે. Major compatibility era છે, દરેક app દ્વારા shared: same major પર devices library sync કરી શકે છે. તે ફક્ત wire અથવા on-disk format તૂટે ત્યારે bump થાય છે, મોટાભાગે pinned coven revision. Minors દરેક app માટે releases ગણે છે અને platforms વચ્ચે comparable નથી.
