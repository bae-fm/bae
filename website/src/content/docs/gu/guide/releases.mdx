---
title: Releases અને metadata
description: Release-accurate library, અને તેને સાચું રાખવાની રીત
---

મોટાભાગની music apps "album" model કરે છે: એક title, એક cover, એક track list. વાસ્તવિક collections આ રીતે કામ કરતી નથી. તમારી પાસે એ જ record નો original CD, remaster, અને vinyl pressing હોઈ શકે છે, અને તેમની track lists, timings, artwork અને credits જુદા હોય છે. bae **releases** model કરે છે: દરેક import ચોક્કસ pressing છે, અને એ જ album ના pressings સાથે group થાય છે.

## Albums releases group કરે છે

Library માં, અનેક pressings ધરાવતો album એક entry છે. Album page release picker બતાવે છે; દરેક release પોતાની track list, cover, year, label, catalog number, અને credits રાખે છે. એક release **primary** છે: album grid અને playback default જે વાપરે છે તે. Album menu માંના **Set as primary release** થી કોઈ પણ release ને primary set કરો, અને સાંભળવા માટે ક્યારે પણ જુદો release પસંદ કરો; bae દરેક album માટે તમારી પસંદગી યાદ રાખે છે.

## Release શું જાણે છે

Identified releases databases નું જ્ઞાન ધરાવે છે, ફક્ત track names નહીં:

- Pressing details: label, catalog number, barcode, country, format, year.
- Credits: performers, producers, engineers, per release અને per track.
- Classical structure: composers, works, અને તેમના parts, તેમની recordings સાથે linked. Library નું composer view આમાંથી બને છે; [Browsing અને search](/gu/guide/browsing) જુઓ.
- ઓળખ: આ ચોક્કસ MusicBrainz અથવા Discogs રિલીઝ છે.

એક વાર લાગુ થયા પછી આ values release ની પોતાની છે: bae source સાથે કોઈ link રાખતું નથી, અને edits તેમને ત્યાં જ બદલે છે.

## Editing

Metadata સુધારવાનું તમારા હાથમાં છે. Album menu માંનું **Edit…** release editor ખોલે છે, import જે form વાપરે છે તે જ: album title અને artist, pressing details, અને દરેક track નું title, artist અને numbering. **Save** તમારા ફેરફારો write કરે છે; **Cancel** તેમને રદ કરે છે.

Edits ફક્ત bae ના database માં રહે છે. તમારી files ના embedded tags ક્યારેય rewrite થતા નથી; files import થયા તેમ byte-for-byte રહે છે.

## ફરી identify કરો

જો release unknown તરીકે import થયો હોય, ખોટા pressing સાથે matched હોય, અથવા database ત્યારથી સુધર્યું હોય, તો editor ના **Identify** controls existing release પર identification ફરી ચલાવે છે: **Automatic** તેને તેની files પરથી identify કરે છે, અને **Search** typed search ખોલે છે. Pressing પસંદ કરવાથી editor ની values તરત બદલાય છે; **Save** તેમને રાખે છે, અને **Cancel** તમારી પાસે જે હતું તે રાખે છે.

## Covers

દરેક release પાસે એક display cover હોય છે. **Change cover** databases નું artwork અને release સાથે આવેલી image files આપે છે. bae પસંદ કરેલા cover ની display માટે sized પોતાની copy રાખે છે, તેથી તમારા folder નો original scan untouched રહે છે. Release ની images ની full gallery ખોલવા cover ક્યાંય tap કરો.

## Deleting

Release કાઢી નાખવાથી તે લાઇબ્રેરીમાંથી દૂર થાય છે અને, cloud માંના release માટે, તેની નકલો તમારા cloud home માંથી પણ. તમારી પોતાની files ક્યારેય કાઢી નાખવામાં આવતી નથી: bae ફક્ત તેમને ભૂલી જાય છે.
