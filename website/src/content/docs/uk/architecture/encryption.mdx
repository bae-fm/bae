---
title: Шифрування
description: Як bae шифрує ваші дані
---

Типово bae шифрує музичні файли й metadata бібліотеки до виходу з пристрою, і storage provider бачить лише ciphertext. Cloud home також може бути browsable: plaintext у structured paths.

## Режими сховища: opaque і browsable

- **Opaque** — кожен об'єкт шифрується ключем бібліотеки й зберігається за obfuscated content-addressed path (`storage/ab/cd/{id}`, `images/ab/cd/{id}`). Провайдер бачить лише ciphertext.
- **Browsable** — об'єкти зберігаються unencrypted зі справжніми filenames у stable id paths: `storage/{album_id}/{release_id}/{import_folder}/01 Track Title.flac`, `images/{album_id}/{release_id}/cover.jpg`, `images/{artist_id}/artist.jpg`. Це не public; доступ контролюють provider credentials.

Browsable означає не прихований, але не human-named: folders — це ids, не artist/album text. Це запобігає collision між releases. Решта сторінки описує opaque home; browsable home не виконує шифрування нижче.

## Ключ бібліотеки

Кожна бібліотека має 256-bit master encryption key, створений під час створення бібліотеки й збережений в OS keyring: macOS Keychain, Windows Credential Manager або Linux Secret Service. Ключ не записується на диск plaintext.

## Шифрування файлів

Файли шифруються XChaCha20-Poly1305 блоками 64 KB. Кожен файл має випадковий nonce перед encrypted blob. Однакові файли дають різний ciphertext; файли розшифровуються незалежно; chunk encryption підтримує range requests для streaming.

## Шифрування cloud home

Changesets, snapshots, images, membership entries і wrapped keys шифруються. Wrapped keys шифруються для кожного пристрою через sealed boxes; дивіться [Членство](/uk/architecture/membership). Head files також шифруються.

## Керування ключами

Ключ бібліотеки зберігається в OS keyring під namespace бібліотеки. На кількох пристроях ключ розповсюджується через membership system, зашифрований для public key пристрою. Якщо втратити всі пристрої й backup keyring, дані в bucket не відновити; server-side recovery немає.
