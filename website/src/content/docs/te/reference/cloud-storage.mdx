మేఘ నిల్వ ఇల్లు వినియోగదారుకు ఇప్పటికే ఉన్న నిల్వలోని ఒక స్థానం. ప్రతి సేవా [coven](https://coven.bae.fm) లోని అదే నిల్వ interface ద్వారా నడుస్తుంది; సేవను బట్టి మారేది sign-in, setup, మరియు ఇతర వ్యక్తులు, పరికరాలు అక్కడికి ఎలా చేరతారు అనేదే.

## సేవలు

| సేవ | Sign-in | మీ స్వంత కొత్త పరికరం | మీరు ఆహ్వానించే వ్యక్తి |
|---|---|---|---|
| S3-compatible | Access key + secret | restore code, QR కోడ్‌లో దానితో పాటు వచ్చే మీ access key తో | వారి కోసం సృష్టించిన access key |
| Dropbox | OAuth, coven దగ్గర | restore code, తర్వాత మీ Dropbox లో sign in | గ్రంథాలయపు పంచుకున్న సంచయం వారి ఖాతాతో పంచుకోబడుతుంది |
| OneDrive | OAuth, coven దగ్గర | restore code, తర్వాత మీ OneDrive లో sign in | గ్రంథాలయపు సంచయం వారి ఖాతాతో పంచుకోబడుతుంది |
| iCloud (CloudKit) | Apple Account, sign-in లేదు | restore code, iCloud Keychain నుంచి కూడా | గ్రంథాలయపు CloudKit zone వారి Apple Account తో పంచుకోబడుతుంది |

S3-compatible లో AWS, Backblaze B2, Cloudflare R2, Wasabi, మరియు ఆ API మాట్లాడే మరేదైనా ఉంటాయి. setup ఫారం bucket, region, endpoint, access key మాత్రమే అడుగుతుంది; coven తెలిసిన సేవలను endpoint host ద్వారా గుర్తించి, వాటితో ఎలా మాట్లాడాలో నింపుతుంది. **Advanced** లో ఐచ్ఛిక key prefix మరియు service profile ఎంపిక ఉంటాయి, డిఫాల్ట్‌గా స్వయంచాలకం. coven కు తెలియని సేవ కోసం **Detect Settings** కీతో bucket ను పరిశీలించి కనుగొన్నది చూపిస్తుంది. ఏదైనా save చేసే ముందు setup సేవతో తనిఖీ చేస్తుంది, కాబట్టి అక్షరదోషం మొదటి సమకాలీకరణలో కాదు, setup సమయంలోనే విఫలమవుతుంది; coven ఇచ్చే కారణాన్ని bae సరళమైన మాటల్లో చెబుతుంది. Dropbox, OneDrive, iCloud పూర్తి **bae** ఎడిషన్‌లో మాత్రమే ఉంటాయి; **baeium** builds వాటిని మినహాయిస్తాయి.

## Sign-in మరియు సంచయాలు

coven Dropbox మరియు OneDrive sign-in ను తానే నడుపుతుంది, కాబట్టి ఏ టోకెన్ కూడా bae గుండా వెళ్లదు. డెస్క్‌టాప్‌లో బ్రౌజర్ సేవ పుటను తెరుస్తుంది, ఒక స్థానిక listener ఆ ఒక్క redirect ను అందుకుంటుంది; mobile లో ఈ పని వేదిక sign-in sheet చేస్తుంది. coven టోకెన్లను OS keyring లో ఉంచి, సేవ తిరస్కరించినప్పుడు టోకెన్‌ను ఒకసారి refresh చేస్తుంది; విఫలమైన refresh నిశ్శబ్ద retry loop గా కాకుండా సమకాలీకరణ స్థితిలో **Sign In** చర్యగా కనిపిస్తుంది.

sign in తర్వాత వినియోగదారు గ్రంథాలయం ఎక్కడ ఉండాలో ఎంచుకుంటారు. Dropbox లో అది పంచుకున్న సంచయం, ఎందుకంటే ఇంటి గ్రంథాలయం ఇతర వ్యక్తుల ఖాతాలతో పంచుకోబడుతుంది; దీని కోసం bae app folder కాదు, పూర్తి Dropbox ప్రాప్యతను వాడుతుంది. ఇంకా పంచుకున్న సంచయం లేకపోతే bae Dropbox లో ఒకదాన్ని పంచుకుని మళ్లీ చూడమంటుంది. OneDrive లో అది ఏ సంచయమైనా, పై నుంచి బ్రౌజ్ చేయబడుతుంది, అక్కడ కొత్త సంచయాన్ని సృష్టించవచ్చు.

CloudKit కు ఏ ప్రక్రియా అవసరం లేదు: coven దాన్ని Apple వేదికలపై sign in అయి ఉన్న Apple Account గానే నడుపుతుంది.

## ఇంటి అమరిక

ఇంటి లోపల ప్రతి object path గ్రంథాలయపు store id తో మొదలవుతుంది: coven యొక్క సంఖ్యాక్రమ మార్పుల వరుస, దాని snapshots, చేరిక అభ్యర్థనలు, నిల్వ చేసిన దస్త్రాలు. అనేక గ్రంథాలయాలు ఒకదాని objects ను మరొకటి తాకకుండా ఒకే Dropbox లేదా OneDrive సంచయాన్ని పంచుకోవచ్చు.

ప్రతి object గుప్తీకరించబడి యాదృచ్ఛిక పేరు కింద నిల్వ అవుతుంది; plaintext విధానం లేదు. bae దస్త్రాలు మూడు సమకాలీకరించబడే పట్టికలు `release_files`, `covers`, `artist_images` వరుసలకు జోడించబడి ఉంటాయి, అదనంగా ప్రతి `people` వరుస avatar. దస్త్రపు path అది తన వరుసకు జోడించబడినప్పుడు స్థిరపడుతుంది, కాబట్టి ఆల్బమ్ పేరు మార్చినా అది ఎప్పుడూ కదలదు. [గుప్తీకరణ](/te/reference/encryption) చూడండి.

## నిజమైన networks లో ప్రవర్తన

playback కోసం చదవడాలు ranged: player మొత్తం దస్త్రాలకు బదులు కావలసిన గుప్తీకరించిన chunks మాత్రమే తెస్తుంది, దస్త్రం క్రమంగా వినిపిస్తున్నప్పుడు తదుపరి chunks ను ముందుగానే తెస్తుంది. రేట్ పరిమితులు మరియు తాత్కాలిక సేవ లోపాలు ఒకే backoff ప్రణాళికతో మళ్లీ ప్రయత్నిస్తాయి, సేవ retry-after ఇస్తే దాన్ని పాటిస్తూ. పంపే వరుస పునఃప్రారంభం తర్వాత కూడా నిలుస్తుంది: యాప్ మూసివేయడంతో ఆగిన పంపడం మొదటి నుంచి కాదు, ఆగిన చోటు నుంచే కొనసాగుతుంది, నిలిపిన పంపడాలు నిలిచే ఉంటాయి.
