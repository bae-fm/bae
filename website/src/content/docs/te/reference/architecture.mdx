bae అంటే నాలుగు స్థానిక యాప్‌లు ధరించిన ఒక Rust మధ్యభాగం. ఉత్పత్తిని నిర్వచించే ప్రతిదీ, గ్రంథాలయ నమూనా, దిగుమతి, వినిపింపు, సమకాలీకరణ, గుప్తీకరణ, Rust లోనే ఉంటుంది మరియు ప్రతి వేదికపై ఒకేలా ప్రవర్తిస్తుంది; ప్రతి యాప్ దాని మీద పలుచని స్థానిక వాడుక తెర.

## పొరలు

- **`bae-core`**: ఉత్పత్తి. గ్రంథాలయం మరియు వివరాల నమూనా, దిగుమతి మరియు గుర్తింపు ప్రవాహాలు, FFmpeg వినిపింపు యంత్రం, శబ్ద తీవ్రత కొలత, ఎగుమతి, దాని కింద coven తో కలయిక. దిగుమతి మరియు గుర్తింపు డెస్క్‌టాప్‌లో మాత్రమే నిర్మించబడతాయి; మొబైల్ నిర్మాణాలు సమకాలీకరణ మరియు వినిపింపు క్లయింట్లు.
- **[coven](https://coven.bae.fm)**: డేటా పొర, వేరే గ్రంథాలయం. coven SQLite connection ను కలిగి ఉంటుంది, bae commit చేసే ప్రతి మార్పును పట్టుకుంటుంది, ఆ మార్పులను వినియోగదారి మేఘ నిల్వ ద్వారా end-to-end encrypted గా సమకాలీకరిస్తుంది. Blob నిల్వ (శబ్ద బైట్లు, చిత్రకళ), స్థానిక తాత్కాలిక నిల్వ, గుర్తింపు కీలు, సభ్యత్వం కూడా దానిదే. bae ఖచ్చితమైన coven revision ను pin చేసి ప్రతి binary లో stamp చేస్తుంది; నిర్మాణాల మధ్య సమకాలీకరణ-సరిపోలిక generation ను అది నిర్వచిస్తుంది.
- **`bae-bridge`**: UniFFI సరిహద్దు. Bridge రకాలు Rust లో ఒక్కసారి నిర్వచించబడి నిర్మాణ సమయంలో Swift మరియు Kotlin కు generated అవుతాయి.
- **యాప్‌లు**: macOS మరియు iOS లో SwiftUI, Android లో Jetpack Compose, స్థానిక Windows యాప్. మధ్యభాగం అడిగే వేదిక భాగాలను కూడా ప్రతి యాప్ అమలు చేస్తుంది: శబ్ద అవుట్‌పుట్, చిత్రకళ text recognition, media controls, keychain access, crash reporting.

యాప్‌లతో పాటు: `bae-mcp` (MCP server) మరియు `bae-automation`.

## డిస్క్ మీద ఒక గ్రంథాలయం

గ్రంథాలయం రెండు డైరెక్టరీల్లో ఉంటుంది (mobile లో వేదిక డేటా డైరెక్టరీలు): coven store, దాని పక్కన bae స్వంత సెట్టింగ్‌లు.

```
~/.bae/stores/<id>/       # coven store, coven ద్వారా మాత్రమే తెరవబడుతుంది
  store.db                # SQLite: catalog, credits, playback specs, coven లెక్క
  files/                  # bae స్వంత దస్త్రాల coven కాపీలు (కవర్లు, కళాకారుల చిత్రాలు, avatars)
  cache/                  # పంపిన దస్త్రాల cache మరియు pinned కాపీలు
~/.bae/libraries/<id>/    # bae సొంతం; ఎప్పుడూ సమకాలీకరించబడదు
  preferences.toml        # bae సెట్టింగ్‌లు
  cache/                  # catalogs నుంచి తెచ్చిన చిత్రకళ
```

డేటాబేస్ coven ద్వారా మాత్రమే తెరవబడుతుంది; అది bae schema పక్కన తన లెక్క పట్టికలను (కలయిక రికార్డులు, పంపే వరుస, దస్త్ర స్థితి) ఉంచి, bae migration ను నడుపుతుంది. స్థానిక విడుదల శబ్ద దస్త్రాలు `~/.bae` కింద అసలు ఉండవు: డేటాబేస్ వాటిని దిగుమతి అయిన paths లోనే సూచిస్తుంది.

రహస్యాలు ఈ దస్త్రాల్లో ఎప్పుడూ ఉండవు. సభ్య కీలు, గ్రంథాలయపు కీలు, మేఘ sign-ins, API టోకెన్లు OS keyring లో ఉంటాయి (Apple వేదికలపై Keychain, ఇతర చోట్ల వేదిక సమానమైనది); Apple వేదికలపై restore code iCloud Keychain లో కూడా సేవ్ అవుతుంది.

## Editions

ప్రతి వేదికలో రెండు నిర్మాణ editions ఉన్నాయి. **bae** OAuth providers (Dropbox, OneDrive), CloudKit, telemetry ను కలుపుతుంది. **baeium** వాటన్నింటిని బయట ఉంచుతుంది: S3-compatible నిల్వ మాత్రమే, telemetry లేదు, dependency tree లో proprietary ఏదీ లేదు. Editions ఒకే మూలం, ఒకే core; feature flag provider list మరియు diagnostics wiring ను నిర్ణయిస్తుంది.

## సంచికలు

యాప్‌లు ప్రతి వేదికకు `MAJOR.MINOR` గా సంచికలు పొందుతాయి. Major అంటే సరిపోలిక కాలం, ప్రతి యాప్ పంచుకునేది: అదే major లో ఉన్న పరికరాలు గ్రంథాలయాన్ని సమకాలీకరించగలవు. Wire లేదా on-disk ఆకృతి విరిగినప్పుడే అది పెరుగుతుంది, ఎక్కువగా pinned coven revision వల్ల. Minor సంఖ్యలు యాప్‌కు సంబంధించిన విడుదలలను లెక్కిస్తాయి, వేదికల మధ్య పోల్చదగినవి కావు.
