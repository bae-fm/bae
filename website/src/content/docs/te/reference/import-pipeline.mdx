దిగుమతి అనేది ఫైల్‌ల బైట్‌ను సవరించకుండానే ఫైల్‌ల ఫోల్డర్‌ను కేటలాగ్ ఎంట్రీగా మారుస్తుంది. ఈ పేజీ [యూజ్ గైడ్](/te/guide/importing)లో వివరించిన ఫ్లో వెనుక ఉన్న పైప్‌లైన్.

## Scanning

Watched ఫోల్డర్లు వేదిక ఫైల్-system events ద్వారా monitored అవుతాయి, debounce అవుతాయి, change పై re-scan అవుతాయి; scans మళ్లీ మొదలుపెట్టకుండా existing candidate list తో reconcile అవుతాయి. Scanner ఫోల్డర్ ను ఒక విడుదల గా classify చేస్తుంది (audio నేరుగా లోపల, లేదా `CD1`/`CD2` వంటి disc-shaped subfolders), లేదా collection గా దాంట్లోకి recurse అవుతుంది. Files extension ద్వారా audio, చిత్రకళ, documents గా classify అవుతాయి, తర్వాత audio probe అవుతుంది: ముఖ్యం ఫైల్ extension కాదు, బైట్లు లో FFmpeg కనుగొనే codec. Partial-డౌన్‌లోడ్ markers ఉన్న ఫోల్డర్లు డౌన్‌లోడ్ పూర్తి అయ్యే వరకు excluded.

CUE sheet ఒక audio image ను ట్రాక్ list గా మార్చుతుంది. Parser pregaps మరియు postgaps, per-ట్రాక్ performers మరియు ISRCs, single-ఫైల్ images మరియు one-ఫైల్-per-ట్రాక్ CUE layouts రెండింటినీ handle చేస్తుంది. Track సరిహద్దులు CUE frames (సెకనుకు 1/75) నుంచి ఖచ్చితమైన నమూనా స్థానాలు కు మారుతాయి, తర్వాత playback వాడే బైట్ మరియు నమూనా విండోలు అవుతాయి.

## మెటాడేటా విత్తనాలు

ప్రతి అభ్యర్థికి ఒక స్పష్టమైన మెటాడేటా సీడ్ ఉంటుంది: **లుకప్**, నిల్వ చేయబడిన **ఫైల్ ట్యాగ్‌లు** స్నాప్‌షాట్ లేదా **మాన్యువల్** ఎంట్రీలో ఎంపిక చేయబడిన బాహ్య విడుదల. ఉపరితలాలు మారడం ఆ విత్తనాన్ని తిరిగి వ్రాయదు.

### వెతుకులాట

డిస్క్ IDని సంగ్రహించే ఏకైక మార్గం శోధన, బార్‌కోడ్‌లు మరియు కేటలాగ్ టెక్స్ట్‌లను గుర్తించడం, ప్రొవైడర్‌లను ప్రశ్నించడం మరియు ఫలితాలను సరిపోల్చడం. స్వయంచాలక శోధన ప్రారంభించబడినప్పుడు మరియు కాన్ఫిగర్ చేయబడిన డిఫాల్ట్ శోధనకు పరిష్కరించబడినప్పుడు మాత్రమే నేపథ్య స్వీప్ ఈ మార్గాన్ని అమలు చేస్తుంది. స్పష్టమైన శోధన చర్య ఆ సెట్టింగ్‌తో సంబంధం లేకుండా దీన్ని అమలు చేయగలదు. ఫైల్ ట్యాగ్‌లు లేదా మాన్యువల్‌ని తెరవడం వలన సంగ్రహణ, ప్రొవైడర్ ప్రశ్నలు లేదా సరిపోలిక ప్రారంభం కాదు.

పొందుపరిచిన ఆడియో ట్యాగ్‌లు లుకప్ సాక్ష్యం కాదు: ట్యాగర్ ఏమి నమ్ముతున్నారో అవి వివరిస్తాయి, నొక్కడం ఏమిటో కాదు. శోధన ఫలితాలు వాటి మూలాధారాన్ని కలిగి ఉంటాయి కాబట్టి ప్రతి ఫలితం ఎందుకు అందించబడుతుందో ఇంటర్‌ఫేస్ వివరించగలదు.

### ఫైల్ ట్యాగ్‌లు

ఫైల్ ట్యాగ్‌లు పొందుపరిచిన ఆడియో ట్యాగ్‌లు మరియు CUE మెటాడేటాను బద్ధకంగా చదువుతాయి. ప్రివ్యూ అభ్యర్థి యొక్క స్కాన్ జనరేషన్, ఫైల్-ఎడిట్ రివిజన్ మరియు గమనించిన ఆడియో ఫైల్‌లతో స్టాంప్ చేయబడిన స్నాప్‌షాట్‌ను నిల్వ చేస్తుంది. **ఫైల్ ట్యాగ్‌లను ఉపయోగించండి** ఎంచుకోవడం ఆ స్నాప్‌షాట్‌ని ఎంచుకుంటుంది. కమిట్ అదే స్నాప్‌షాట్‌ను వినియోగిస్తుంది మరియు లైబ్రరీ దాని స్టాంప్ లేదా పరిశీలనలు మారితే వ్రాసే ముందు విఫలమవుతుంది; అది నిశ్శబ్దంగా వేరే సమాధానాన్ని చదవదు.

### మాన్యువల్

మాన్యువల్ మెటాడేటా ఇన్‌పుట్ లేదా అవుట్‌పుట్ చేయదు. స్కాన్ చేసిన ఫిజికల్ ట్రాక్ లేఅవుట్‌ను అలాగే ఉంచుతూ **మాన్యువల్‌గా నమోదు చేయండి**ని ఎంచుకోవడం వలన ఖాళీ ఎడిట్ చేయదగిన విడుదల ఏర్పడుతుంది.

**సీడ్ లేని అభ్యర్థులను ఇందులో తెరవండి** అనే సెట్టింగ్, సీడ్ లేని అభ్యర్థుల ప్రారంభ వీక్షణను ఎంచుకుంటుంది. స్థిర ఎంపికలు వెతుకులాట, ఫైల్ ట్యాగ్‌లు, మాన్యువల్; **చివరిగా వాడినది** వినియోగదారు స్పష్టంగా ఎంచుకున్న చివరి మోడ్‌ను సూచిస్తుంది. ప్రదర్శన స్థితి నిల్వ చేసిన సీడ్‌కు వేరుగా ఉంటుంది.

## Sources

MusicBrainz anonymous గా strict one-request-per-second pace తో query అవుతుంది. Discogs వాడుకరి personal టోకెన్ తో keyring నుంచి authenticate అవుతుంది, తన rate limits లో pace మరియు retry అవుతుంది, rejected టోకెన్ అలానే report అవుతుంది కాబట్టి UI searches నిశ్శబ్దంగా fail కాకుండా flag చేయగలదు. Responses per session క్యాష్ అవుతాయి, గెలిచిన మూలం raw JSON భవిష్యత్తులో మళ్లీ అర్థం చేసుకోవడానికి డేటాబేస్ లో archive అవుతుంది.

## Commit

Import confirm చేస్తే, క్రమంగా ఇవి నడుస్తాయి:

1. **Decode verification**: ప్రతి ట్రాక్ end to end డీకోడ్ అవుతుంది; పూర్తిగా డీకోడ్ కాని rip ఏదీ రాయడానికి ముందు దిగుమతి fail చేస్తుంది (config flag దీన్ని disable చేయగలదు).
2. **శబ్దస్థాయి విశ్లేషణ**: అదే డీకోడ్ pass లో ప్రతి ట్రాక్ మరియు ఆల్బమ్ కు integrated loudness, true peak కొలుస్తుంది, replay-gain కోసం store చేస్తుంది.
3. **Cover selection**: ఎంచుకున్న art (remote, ఫోల్డర్ image, లేదా embedded) display thumbnail గా re-render అవుతుంది; అది ఫోల్డర్ నుంచి వచ్చినదైతే అసలు విడుదల ఫైల్లలో ఉంచబడుతుంది.
4. **అణు వ్రాత**: విడుదల, ట్రాక్‌లు, credits, identities, ఆకృతులు, segments, ఫైళ్లు, కవర్ ఒక transaction లో commit అవుతాయి. Half-imported state ఉండదు.

Release వాడుకరి ఫైల్లను ఉన్నచోట reference చేస్తూ lands అవుతుంది. User క్లౌడ్-managed ఎంచుకుంటే, అప్‌లోడ్ commit తర్వాత నిల్వ transition గా జరుగుతుంది, ఫైల్ల అసలు బైట్లు అంతా మూలం of truth గానే ఉంటాయి; వాడుకరి bae కు ఇచ్చినదేదీ ఎప్పుడూ delete లేదా alter కాదు.

## Rips గుర్తించడం

ప్రతి విడుదల తన imported ఫోల్డర్ నిర్మాణం (relative paths మరియు sizes, location-independent) మీద content hash record చేస్తుంది. Re-scans దాన్ని వాడి ఇప్పటికే లైబ్రరీ లో ఉన్న ఫోల్డర్లు ను mark చేస్తాయి, అదే rip re-imports పూర్వ విడుదల ను duplicate చేయకుండా find and replace చేస్తాయి.
