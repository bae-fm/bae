클라우드 홈은 라이브러리를 위한 하나의 원격 저장 위치입니다. Google Drive 폴더 하나, S3 버킷 하나, Dropbox 폴더 하나 같은 형태입니다. 여기에는 릴리스 파일, 메타데이터 변경 세트, 아트워크, 스냅샷, 멤버십 체인이 들어갑니다. **불투명** 홈: 기본값에서는 신뢰가 저장소 백엔드가 아니라 암호화에 있습니다. 제공자는 난독화된 키 아래 암호문을 저장합니다. 대신 **탐색 가능**으로 설정하면 모든 것을 암호화하지 않고 안정적인 ID 기반 경로에 실제 파일명으로 저장합니다. [저장소 모드](/ko/architecture/encryption#storage-modes-opaque-and-browsable)를 참고하세요.

## CloudHome trait

`CloudHome` trait는 bae가 백엔드에 독립적으로 동작하게 하는 추상화입니다. trait 위의 모든 것은 공통입니다. trait 아래는 특정 클라우드 제공자에 맞게 조정됩니다.

### 공통인 것: trait 위

- **클라우드 홈 레이아웃** — `changes/`, `heads/`, `snapshot.db`, `images/`, `storage/`, `membership/`, `keys/`. 백엔드와 관계없이 같은 논리 경로입니다. 불투명 홈은 오디오와 아트워크를 ID 해시로 `storage/`와 `images/` 아래에 나눠 저장합니다. 탐색 가능 홈은 같은 두 접두사 아래 안정적인 ID 기반 경로와 실제 파일명으로 배치합니다: `storage/{album_id}/{release_id}/{import_folder}/01 Track.flac`, `images/{album_id}/{release_id}/cover.jpg`.
- **암호화** — 라이브러리마다 하나의 대칭 키. 불투명 홈에서는 모든 것이 기기를 떠나기 전에 암호화됩니다. 탐색 가능 홈은 암호화를 건너뛰고 평문을 저장합니다. `.enc` 접미사도 빠집니다.
- **동기화 프로토콜** — 변경 세트, 스냅샷, 마지막 작성자 우선 충돌 해결. 모든 곳에서 같은 알고리즘입니다.
- **멤버십 체인** — Ed25519 서명이 있는 추가 전용 로그이며, 암호화 키는 각 멤버의 공개 키로 래핑됩니다.

### 달라지는 것: trait 아래

- **저장소 API** — 파일을 실제로 읽고 쓰는 방법: S3 API, Google Drive API, 로컬 파일 시스템 등
- **접근 관리** — 새 기기가 저장소 접근 권한을 얻는 방법: 폴더 접근 또는 자격 증명 발급
- **인증** — 새 기기가 인증하는 방법: 클라우드 계정 또는 포함된 자격 증명
- **변경 알림** — 소비자용 클라우드는 푸시 알림을 지원하고, S3는 폴링이 필요합니다

### trait 인터페이스

```rust
trait CloudHome {
    // 저장소 -- 같은 인터페이스, 아래쪽 API만 다름
    fn write(path, data) -> Result;
    fn read(path) -> Result<Bytes>;
    fn read_range(path, start, end) -> Result<Bytes>;
    fn list(prefix) -> Result<Vec<String>>;
    fn delete(path) -> Result;
    fn exists(path) -> Result<bool>;

    // 접근 관리 -- 백엔드마다 다름
    fn grant_access(member_email_or_id) -> Result<JoinInfo>;
    fn revoke_access(member_email_or_id) -> Result;
}
```

호출자: 동기화 엔진, 이미지 업로더, 파일 저장소는 이 인터페이스를 직접 사용합니다. 어떤 백엔드와 대화하는지 알 필요가 없습니다.

## 접근 관리

`grant_access`와 `revoke_access`의 동작 방식은 백엔드에 따라 다릅니다. 소비자용 클라우드: Google Drive, Dropbox, OneDrive는 제공자의 API로 폴더를 공유합니다. 새 기기에서 본인 계정으로 로그인하면 폴더에 이미 접근할 수 있습니다. S3 호환 백엔드는 각 기기용 범위 제한 IAM 자격 증명을 만들고 초대 코드에 포함합니다.

두 경우 모두 암호화 키는 멤버십 체인을 통해 별도로 전달되며, 새 기기의 공개 키로 래핑됩니다.
