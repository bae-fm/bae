---
title: 멤버십
description: 신원, 멤버십 체인, 서명된 변경 세트
---

라이브러리의 멤버십은 해당 라이브러리를 읽고 쓸 권한이 있는 기기의 집합입니다. 이 페이지는 그 뒤의 기술적 메커니즘: 신원, 멤버십 체인, 서명된 변경 세트, 키 래핑을 설명합니다.

## 신원

각 기기는 첫 사용 시 Ed25519/X25519 키쌍을 생성하고 OS 키링에 저장합니다. 공개 키가 신원입니다. 중앙 디렉터리나 계정 서버는 없습니다. 공개 키는 별도 경로로 교환됩니다.

## 멤버십 체인

라이브러리 멤버십은 클라우드 홈의 `membership/{pubkey}/{seq}.enc`에 저장되는 서명된 항목의 추가 전용 체인으로 추적됩니다. 각 항목은 Add 또는 Remove 동작, 대상 기기의 공개 키와 역할을 기록하며 현재 소유자가 서명합니다.

첫 항목은 항상 시작 기기이며 owner로 추가됩니다. 체인은 구성 시 검증됩니다. 서명이 잘못되었거나 owner가 아닌 기기에서 온 항목은 거부됩니다.

## 서명된 변경 세트

클라우드 홈으로 올라가는 모든 변경 세트는 작성한 기기의 Ed25519 키로 서명됩니다. 내려받을 때 bae는 변경 세트가 만들어진 시점에 작성자가 권한 있는 기기였는지 확인합니다. 이를 위해 멤버십 체인을 확인합니다. 권한 없는 기기의 변경 세트나 잘못된 서명은 폐기됩니다.

## 키 래핑

라이브러리 암호화 키는 각 기기의 X25519 공개 키로 sealed-box 암호화되어 클라우드 홈의 `keys/{user_pubkey}.enc`에 저장됩니다. 의도된 수신자만 개인 키로 풀 수 있습니다. 기기가 취소되면 새 암호화 키를 생성하고 남은 모든 기기에 다시 래핑합니다.

## 초대 코드

초대 코드는 참여 기기가 필요한 모든 것을 묶습니다.

- 새 기기의 공개 키로 sealed-box 암호화된 라이브러리 암호화 키
- 클라우드 홈 좌표: 제공자 유형, 폴더 ID 또는 버킷
- 저장소 자격 증명: S3에서는 발급된 IAM 자격 증명, 소비자용 클라우드에서는 제공자 API를 통한 폴더 공유
- 새 기기를 추가하는 서명된 멤버십 체인 항목

소유자 기기는 새 기기의 공개 키를 받은 뒤 코드를 생성합니다. 새 기기는 bae에 코드를 붙여 넣고 암호화 키를 풀고 클라우드 홈에 연결한 뒤 동기화를 시작합니다.
