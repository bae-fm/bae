폴더는 가져오기에 쓸 오디오와 기타 파일을 제공합니다. 편집 가능한 메타데이터를 온라인 릴리스, 폴더 자체의 메타데이터, 빈 양식 중 어디에서 시작할지 선택합니다.

가져오기는 데스크톱(macOS, Windows)에서 합니다. 파일은 읽기만 하고 절대 바꾸지 않습니다. bae는 아무것도 이동, 이름 변경, 태그 변경, 재인코딩하지 않습니다. 가져온 뒤 파일이 어디에 있는지는 [저장소와 오프라인](/ko/guide/storage)을 보세요.

## 감시 폴더

**가져오기** 섹션으로 전환하고 폴더를 추가합니다. 선택하거나, 창으로 끌어다 놓거나, <kbd>⌘I</kbd>를 누릅니다. 그때부터 bae가 폴더를 감시합니다. 새 음악을 그곳에 넣으면 새 후보로 자동 표시됩니다. 손으로 다시 스캔하지 않아도 됩니다. 아직 다운로드 중인 폴더는 끝날 때까지 무시됩니다.

스캔은 실제 리핑본이 가지는 형태를 인식합니다.

| 배치 | 보이는 모습 |
|--------|-------------------|
| 트랙별 파일 | `01 - Song.flac`, `02 - Song.flac`, … |
| CUE + 이미지 | `album.cue` + `album.flac`, 전체 디스크를 담은 파일 하나 |
| 여러 디스크 | `CD1/`, `CD2/` 하위 폴더, 내부 형태는 둘 중 하나 |
| 모음 | 폴더 안의 폴더들, 각각이 자체 릴리스 |

bae는 재생하는 형식을 가져옵니다. FLAC, MP3, APE, `.m4a`의 ALAC와 AAC, WAV, AIFF, Ogg Vorbis, Opus, WavPack, DSD(`.dsf`/`.dff`)입니다. 폴더 안의 아트워크와 문서(CUE 시트, 리핑 로그, 텍스트 파일)는 인식되어 릴리스와 함께 보관됩니다.

## 메타데이터 초안 채우기

각 후보는 편집 가능한 메타데이터 초안을 하나 가집니다. 초안은 비어 있는 상태로 시작하거나, 온라인 릴리스로 채우거나, 폴더 자체 파일이 담은 내용으로 채울 수 있습니다. 빈 초안에 입력하는 것은 직접 입력이며, 별도의 메타데이터 소스가 아닙니다.

카드의 **식별** 컨트롤은 식별 페이지로 들어가는 두 가지 방법을 제공하며, 무엇을 시작하는지가 다릅니다. **자동**은 페이지를 열고, 후보에 이미 무엇이 있든 매번 새 식별 실행을 요청합니다. 이미 진행 중인 실행은 새 실행으로 대체됩니다. **검색**은 같은 페이지를 직접 입력하는 검색으로 열고 아무것도 시작하지 않습니다. 어느 쪽도 초안을 바꾸지 않습니다. 결과를 적용하면 초안이 대체되고 편집 가능한 카드로 돌아갑니다. 카드 메뉴에는 초안을 그 자리에서 다시 쓰는 명령이 두 개 있습니다. 후보 자체의 파일, 시트, 폴더 이름이 담은 내용으로 초안을 대체하는 **파일 메타데이터로 재설정**과, 초안을 비우는 **메타데이터 지우기**입니다. 둘 다 먼저 확인을 묻고, 어느 것도 후보의 파일이나 트랙 배치를 건드리지 않습니다.

### 식별

식별 페이지는 폴더가 어떤 릴리스인지 찾습니다. 폴더에서 단서를 읽고 각각을 조회합니다.

- **디스크 ID.** CD의 정확한 트랙 배치를 나타내는 지문으로, 리핑 로그나 CUE 시트에서 계산합니다. 일치하면 정확한 CD 판을 식별합니다.
- **바코드.** 폴더 안의 커버 스캔에서 텍스트 인식으로 읽거나 CUE 시트에서 읽습니다.
- **카탈로그 번호와 텍스트.** 아트워크와 파일 및 폴더 이름에서 찾은 카탈로그 번호로, 결과를 좁히는 데 씁니다.

신호는 MusicBrainz와 Discogs에서 동시에 조회되고, 결과는 서로 교차 확인됩니다. 각 신호는 결과 위에 배지로 표시됩니다. 무엇을 찾았는지, 어디서 왔는지(포인터를 올리면 출처가 표시됩니다: 디스크 TOC, CUE 시트, 커버 스캔, 폴더 이름) 볼 수 있고, 오해를 부르는 신호는 하나씩 끌 수 있습니다.

결과는 세 가지입니다.

- **찾음.** 단서가 하나의 릴리스 그룹에서 일치합니다. 그 목록에서 정확한 프레싱을 고릅니다.
- **충돌.** 두 신호가 서로 다른 릴리스를 가리킵니다. 예를 들어 디스크 ID와 바코드가 맞지 않는 경우입니다. bae는 양쪽을 모두 보여주고, 어느 쪽을 믿을지 고르거나 신호를 무시합니다.
- **찾지 못함.** 직접 검색합니다. 아티스트와 앨범, 카탈로그 번호, 바코드로 두 데이터베이스 중 하나를 검색합니다. 아트워크에서 인식한 텍스트가 자동 완성으로 제시됩니다.

소스 브라우저는 검색 양식, 식별 진행률, 신호, 결과를 함께 보여줍니다. 결과를 선택하면 bae가 전체 릴리스를 가져오는 동안 그 행이 진행률과 함께 열려 있고, 그다음 초안에 적용됩니다. 그 결과 카드에는 MusicBrainz 또는 Discogs 소스 칩이 표시됩니다. 카드의 **자동**은 처음부터 다시 실행하고, **검색**은 이미 찾은 내용을 그대로 둔 채 직접 입력하는 검색으로 돌아갑니다.

자동 식별도 같은 경로를 사용합니다. 후보가 추가되면 그 초안은 파일, 시트, 폴더 이름으로 만들어집니다. 설정, 가져오기의 **자동으로 식별**은 지금 가진 파일에 대한 결과가 없는 모든 후보에 대해 식별을 실행합니다. 꺼져 있으면 각 실행을 직접 시작합니다. 미리 채운 초안은 출발점일 뿐 답이 아니므로 실행을 막지 않습니다.

### 파일 메타데이터

파일 메타데이터는 후보가 추가될 때 미리 채우기가 읽고, **파일 메타데이터로 재설정**을 고를 때마다 다시 읽습니다. 어느 경우든 초안은 바로 그 읽은 내용(내장 오디오 태그, CUE 메타데이터, 폴더 자체의 이름)으로 대체되고, 카드는 그에 맞춰 다시 그려집니다. 읽은 뒤 후보나 그 오디오 파일이 바뀌었으면 가져오기는 라이브러리에 쓰기 전에 실패합니다.

초안이 그 읽은 내용을 담고 있는 동안 편집 가능한 카드에는 눈에 띄지 않는 파일 메타데이터 칩이 표시됩니다. 입력만으로 채운 초안에는 소스 칩이 없습니다.

## 확인과 가져오기

확인 창은 가져오기가 쓸 모든 것을 보여줍니다.

- **커버.** 데이터베이스의 아트워크, 폴더에 있는 이미지, 파일에 내장된 아트워크 중에서 고릅니다. 후보 갤러리에서 이미지를 커버 사각형으로 끌어다 놓거나 나중에 바꿀 수 있습니다.
- **메타데이터.** 앨범, 아티스트, 연도, 레이블, 카탈로그 번호, 국가, 바코드, 모든 트랙입니다. 저장 전에 여기서 모두 편집할 수 있습니다.
- **저장소.** 클라우드 홈이 연결되어 있으면 릴리스를 그곳에 업로드하려면 **클라우드**를, 파일을 이 기기에도 보관하려면 **고정됨**을 선택합니다. 그렇지 않으면 릴리스는 로컬입니다. 정보는 다른 기기로 동기화되고, 오디오는 이 기기에 남습니다. [저장소와 오프라인](/ko/guide/storage)을 보세요.

가져오기는 백그라운드에서 실행됩니다. bae는 모든 트랙이 끝까지 정상 디코딩되는지 확인하고, 앨범과 각 트랙의 라우드니스를 측정하고, 릴리스를 저장하고, 클라우드 가져오기라면 업로드를 시작합니다. 후보 목록은 다음 폴더로 넘어가고, 릴리스는 바로 재생할 수 있습니다.

## 데이터 소스

**MusicBrainz**는 계정도 키도 필요 없습니다. **Discogs**는 사용자의 무료 API 토큰이 필요합니다. 설정, 가져오기에 붙여 넣으면 토큰이 작동을 멈췄을 때 bae가 알려줍니다. 토큰이 없으면 Discogs 검색과 Discogs 기반 메타데이터를 쓸 수 없지만, 나머지는 모두 동작합니다. 두 서비스에는 요청 제한이 있습니다. bae는 제한 안에 머무르도록 요청 속도를 조절합니다.
