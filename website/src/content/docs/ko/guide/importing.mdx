리핑 폴더는 자기 자신에 대해 거의 아무것도 알지 못합니다. 어느 릴리스에서 왔는지, 어떤 프레싱인지, 레이블과 크레딧, 12번 트랙이 실제로 어디서 끝나는지는 파일 이름이 아니라 MusicBrainz와 Discogs 같은 데이터베이스에 있습니다. 가져오기는 bae가 둘을 연결하는 방법입니다. 음악을 가리키면 bae가 각 폴더가 어떤 릴리스인지 알아내고, 라이브러리는 그 폴더를 해당 릴리스로 기록합니다.

가져오기는 데스크톱(macOS, Windows)에서 합니다. 파일은 읽기만 하고 절대 바꾸지 않습니다. bae는 아무것도 이동, 이름 변경, 태그 변경, 재인코딩하지 않습니다. 가져온 뒤 파일이 어디에 있는지는 [저장소와 오프라인](/ko/guide/storage)을 보세요.

## 감시 폴더

**Import** 섹션으로 전환하고 폴더를 추가합니다. 선택하거나, 창으로 끌어다 놓거나, <kbd>⌘I</kbd>를 누릅니다. 그때부터 bae가 폴더를 감시합니다. 새 음악을 그곳에 넣으면 새 후보로 자동 표시됩니다. 손으로 다시 스캔하지 않아도 됩니다. 아직 다운로드 중인 폴더는 끝날 때까지 무시됩니다.

스캔은 실제 리핑본이 가지는 형태를 인식합니다.

| 배치 | 보이는 모습 |
|--------|-------------------|
| 트랙별 파일 | `01 - Song.flac`, `02 - Song.flac`, ... |
| CUE + 이미지 | `album.cue` + `album.flac`, 전체 디스크를 담은 파일 하나 |
| 여러 디스크 | `CD1/`, `CD2/` 하위 폴더, 내부 형태는 둘 중 하나 |
| 모음 | 폴더 안의 폴더들, 각각이 자체 릴리스 |

bae는 재생하는 형식을 가져옵니다. FLAC, MP3, APE, `.m4a`의 ALAC와 AAC, WAV, AIFF, Ogg Vorbis, Opus, WavPack, DSD(`.dsf`/`.dff`)입니다. 폴더 안의 아트워크와 문서(CUE 시트, 리핑 로그, 텍스트 파일)는 인식되어 릴리스와 함께 보관됩니다.

## 릴리스 식별

후보를 선택하면 bae가 식별을 시작합니다. 태그로 추측하는 대신 폴더 안의 증거를 읽고 각각을 조회합니다.

- **Disc ID.** CD의 정확한 트랙 배치 지문입니다. 리핑 로그나 CUE 시트에서 계산합니다. 일치하면 정확한 CD 에디션을 식별합니다.
- **Barcode.** 폴더의 커버 스캔에서 텍스트 인식으로 읽거나 CUE 시트에서 읽습니다.
- **Catalog numbers and text.** 아트워크와 파일 및 폴더 이름에서 찾은 카탈로그 번호로 결과를 좁힙니다.

신호는 MusicBrainz와 Discogs에서 동시에 조회하고, 결과는 서로 대조합니다. 각 신호는 결과 위에 배지로 나타납니다. 무엇이 발견됐는지, 어디서 왔는지(원본을 보려면 가리키기: disc TOC, CUE sheet, cover scan, folder name)를 볼 수 있고, 신호 하나가 잘못 이끌 때는 개별 신호를 끌 수 있습니다.

세 가지 결과가 있습니다.

- **Found.** 증거가 하나의 릴리스 그룹에 일치합니다. 사용자는 그 목록에서 정확한 프레싱을 고릅니다.
- **Conflict.** 두 신호가 서로 다른 릴리스를 가리킵니다. 예를 들어 disc ID와 barcode가 다를 수 있습니다. bae는 양쪽을 보여주고 사용자가 어느 쪽을 믿을지 고르거나 한 신호를 무시하게 합니다.
- **Nothing found.** 직접 검색합니다. 아티스트와 앨범, 카탈로그 번호, barcode로 어느 데이터베이스든 검색합니다. 아트워크에서 인식한 텍스트는 자동 완성으로 제시됩니다.

**skip identifying**을 선택해 알 수 없는 릴리스로 가져올 수도 있습니다. 그러면 bae는 이름에 파일의 내장 태그를 사용하고, 나중에 릴리스가 데이터베이스에 생기거나 더 나은 증거가 있을 때 다시 식별할 수 있습니다.

## 정확 또는 근사

일치 항목을 선택하면 bae가 파일과 대조하고 트랙 수 불일치를 표시합니다. 그런 다음 일치의 성격을 사용자가 선언합니다.

- **Exact**: 사용자의 파일은 이 프레싱입니다.
- **Metadata only**: 맞는 앨범이지만 반드시 이 정확한 프레싱은 아닙니다. bae는 메타데이터를 쓰고 프레싱이 근사치임을 기억합니다.

그 릴리스가 이미 라이브러리에 있거나 같은 앨범의 다른 프레싱이 있으면, bae는 중복 가져오기 전에 알려줍니다.

## 확인과 가져오기

확인 창은 가져오기가 쓸 모든 것을 보여줍니다.

- **Cover.** 데이터베이스의 아트, 폴더 안 이미지, 파일에 내장된 아트 중에서 선택됩니다. 나중에 바꿀 수 있습니다.
- **Metadata.** 앨범, 아티스트, 연도, 레이블, 카탈로그 번호, 국가, barcode, 모든 트랙입니다. 저장 전에 여기서 모두 편집할 수 있습니다.
- **Storage.** 클라우드 홈이 연결되어 있으면 bae가 파일을 클라우드에서 관리할지, 로컬 사본도 보관할지 선택합니다. [저장소와 오프라인](/ko/guide/storage)을 보세요.

가져오기는 백그라운드에서 실행됩니다. bae는 모든 트랙이 끝까지 정상 디코딩되는지 확인하고, 앨범과 각 트랙의 loudness를 측정하고, 릴리스를 저장하고, 관리되는 가져오기라면 업로드를 시작합니다. 후보 목록은 다음 폴더로 넘어가고, 릴리스는 바로 재생할 수 있습니다.

## 데이터 소스

**MusicBrainz**는 계정도 키도 필요 없습니다. **Discogs**는 사용자의 무료 API token이 필요합니다. Settings에 붙여 넣으면 bae가 동작을 멈췄을 때 알려줍니다. 토큰이 없으면 Discogs 검색과 Discogs 기반 메타데이터를 쓸 수 없지만, 나머지는 모두 동작합니다. 두 서비스에는 요청 제한이 있습니다. bae는 제한 안에 머무르도록 요청 속도를 조절합니다.
