---
title: 저장소 개요
description: bae가 음악 파일을 저장하는 방식
---

릴리스 파일은 최대 세 곳에 있을 수 있습니다. 릴리스를 가져올 때 **관리형**과 **자체 관리형** 중 하나를 선택합니다. 관리형 파일은 bae 저장소로 복사되고, 자체 관리형 파일은 원래 위치에 남습니다.

## 한눈에 보기

|                              | 자체 관리형        | 관리형 — 로컬    | 관리형 — 클라우드    |
|------------------------------|------------------|--------------------|--------------------|
| 파일 위치                | 사용자의 위치    | `~/.bae/libraries/` | 클라우드 제공자    |
| 가져올 때 bae가 파일 복사   | 아니요               | 예                | 예                |
| 오프라인 사용 가능            | 예              | 예                | 아니요                 |
| 저장 시 암호화            | 아니요               | 아니요                 | 불투명 홈만   |
| 클라우드로 동기화 가능            | 아니요               | 예                | —                  |
| 다른 기기와 동기화       | 아니요               | 아니요                 | 예                |
| 릴리스 삭제 시 파일 제거 | 아니요               | 예                | 예                |

관리형 릴리스는 로컬, 클라우드, 또는 둘 다에 파일을 둘 수 있습니다. 클라우드 홈이 설정되어 있으면 관리형 가져오기는 둘 다에 저장합니다.

## 자체 관리형

이미 정리해 둔 파일을 bae에 지정합니다. bae는 파일을 인덱싱하지만 이동, 복사, 수정하지 않습니다. 이미 원하는 방식으로 정리한 음악이 많다면 한 바이트도 복제하지 않고 카탈로그를 만들 수 있습니다.

제약: bae는 자체 관리형 파일을 암호화, 동기화, 백업할 수 없습니다.

## 관리형 — 로컬

모든 라이브러리는 컴퓨터에 홈 디렉터리(`~/.bae/libraries/{uuid}/`)를 갖습니다. 이곳에 bae가 데이터베이스, 이미지, 관리형 릴리스의 로컬 파일 복사본을 둡니다.

릴리스를 관리형으로 가져오면 bae는 파일을 라이브러리 홈으로 복사합니다. 원본은 건드리지 않습니다. bae는 이 로컬 복사본으로 재생합니다.

## 관리형 — 클라우드

클라우드 홈은 릴리스 파일, 메타데이터 변경 세트, 아트워크, 스냅샷을 보관하는 하나의 원격 저장 위치입니다. 이를 설정하면 여러 기기 동기화와 클라우드 백업이 가능해집니다.

클라우드 홈이 설정된 상태에서 관리형 릴리스를 가져오면 bae는 파일을 라이브러리 홈으로 복사하고 클라우드 홈에도 업로드합니다. 둘 다 가져오기 중 수행됩니다.

클라우드 홈에만 있는 릴리스: 아직 다운로드하지 않은 다른 기기에서 동기화된 항목은 파일을 로컬로 가져오기 전까지 오프라인 재생에 사용할 수 없습니다.

### 불투명 또는 탐색 가능

클라우드 홈을 설정할 때 제공자와 관계없이 객체 저장 방식을 선택합니다.

- **불투명**: 기본값. 모든 객체를 라이브러리 키로 암호화하고 난독화된 경로에 저장합니다. 제공자는 암호문만 봅니다.
- **탐색 가능**: 모든 것을 암호화하지 않고 실제 파일명을 유지한 안정적인 ID 기반 경로에 저장합니다. 릴리스 파일은 `storage/{album_id}/{release_id}/{import_folder}/01 Track.flac`, 아트워크는 `images/{album_id}/{release_id}/cover.jpg` 같은 경로를 사용합니다. 버킷을 열어 일반 도구로 실제 파일을 재생하거나 복사할 수 있습니다. 폴더는 아티스트나 앨범 텍스트가 아니라 ID이므로 충돌을 피하고 각 릴리스 폴더가 변하지 않습니다. 아무것도 암호화되지 않으며, 홈은 제공자의 접근 제어에 의존합니다. 탐색 가능 모드는 공개가 아닙니다. 어느 모드든 버킷 자격 증명이 접근을 막습니다.

전체 비교는 [암호화](/ko/architecture/encryption#storage-modes-opaque-and-browsable)를 참고하세요.

### 지원 제공자

- **Google Drive** — OAuth로 로그인하면 bae가 Drive에 폴더를 만듭니다
- **Dropbox** — OAuth로 로그인
- **OneDrive** — OAuth로 로그인
- **iCloud Drive**(macOS) — iCloud 컨테이너를 사용하며 별도 로그인이 필요 없습니다
- **S3 호환** — 어떤 버킷이든 가능: AWS S3, Backblaze B2, Cloudflare R2, Wasabi, MinIO 등

소비자용 클라우드 제공자: Google Drive, Dropbox 등은 OAuth 로그인을 사용하며 API 키나 버킷 설정이 필요 없습니다. iCloud Drive는 macOS에서만 기존 iCloud 컨테이너를 사용합니다. S3 호환 제공자는 수동 자격 증명 설정이 필요하며 더 기술적인 사용자를 대상으로 합니다.

## 작동 방식

1. 릴리스를 가져오며 **관리형** 또는 **자체 관리형**을 선택합니다
2. 관리형 가져오기는 파일을 라이브러리 홈: 로컬에 복사합니다
3. 클라우드 홈이 설정되어 있으면 관리형 가져오기는 파일도 그곳에 업로드합니다. 불투명 홈에서는 암호화되고, 탐색 가능 홈에서는 평문입니다
4. 같은 클라우드 홈에 연결된 다른 기기가 자동으로 동기화됩니다

여러 기기 동기화 방식은 [동기화](/ko/storage/sync)를, 파일 암호화 방식은 [암호화](/ko/architecture/encryption)를 참고하세요.
