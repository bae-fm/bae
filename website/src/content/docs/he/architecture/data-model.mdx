## ספריות ומיקומי אחסון

**ספרייה** היא הישות העליונה: אוסף מוזיקה עם זהות (`library_id`), שם ומפתח הצפנה. היא נמצאת ב-**library home** על הדיסק (`~/.bae/libraries/{uuid}/`), ושם אפליקציית שולחן העבודה כותבת את מסד הנתונים הראשי.

ספרייה יכולה לכלול **cloud home** אופציונלי: מיקום ענן יחיד, כמו תיקיית Google Drive או bucket S3, שמשמש מרכז לסנכרון בין מכשירים. לכל ספרייה cloud home אחד, המוגדר ב-`config.yaml`. ראו [Cloud Home](/he/architecture/cloud-home).

קובצי מהדורה יכולים להימצא באחד או יותר מהמיקומים הבאים:

- **Library home** (`~/.bae/libraries/{uuid}/storage/`) — עותק מקומי, זמין ללא חיבור
- **Cloud home** (`cloud-home/storage/`) — עותק מוצפן לסנכרון
- **לא מנוהל** — הקבצים נשארים במקומם בדיסק, ו-bae רק מאנדקס אותם

מהדורה יכולה להיות מקומית בלבד, בענן בלבד, או בשניהם. קבצים בענן בלבד אינם זמינים לניגון ללא חיבור.

## מבנה תיקיות

### Library home

```
~/.bae/libraries/{uuid}/
  config.yaml                  # הגדרות ספציפיות למכשיר, לא מסתנכרנות
  library.db                   # SQLite, כל הנתונים
  images/ab/cd/{id}            # תמונות ספרייה
  storage/ab/cd/{file_id}      # קובצי מהדורות
```

`config.yaml` מכיל הגדרות ספציפיות למכשיר ואינו מסתנכרן. פרטי גישה נשמרים ב-keyring של מערכת ההפעלה, לא כאן.

קבצים תחת `images/` ו-`storage/` משתמשים במבנה מבוסס hash: שני התווים הראשונים של המזהה הם תיקיית קידומת, ושני התווים הבאים הם תת-תיקייה. אין שמות קבצים או סיומות על הדיסק; שמות מקוריים וסוגי תוכן נשמרים במסד הנתונים. אותו מבנה משמש גם ב-library home וגם ב-cloud home.

### Cloud home

cloud home משקף את נתוני הספרייה ומוסיף מנגנוני סנכרון ובקרת גישה:

| נתיב | מטרה |
|---|---|
| `snapshot.db.enc` | snapshot מלא של מסד הנתונים למכשיר חדש |
| `changes/{device_id}/{seq}.enc` | חבילות שינוי מצטברות |
| `heads/{device_id}.json.enc` | מספרי רצף לכל מכשיר |
| `images/ab/cd/{id}` | תמונות ספרייה מוצפנות |
| `storage/ab/cd/{file_id}` | קובצי מהדורות מוצפנים |
| `membership/{pubkey}/{seq}.enc` | רשומות membership chain |
| `keys/{user_pubkey}.enc` | מפתחות הצפנה עטופים לכל מכשיר |

### רשומות keyring

מנוהלות על ידי `KeyService` דרך keyring מערכת ההפעלה. ב-macOS זהו מאגר הנתונים המוגן עם סנכרון iCloud Keychain. כל הרשומות מופרדות לפי `library_id`, אלא אם צוין אחרת.

| רשומה | תחום | מטרה |
|---|---|---|
| `encryption_master_key` | לכל ספרייה | הצפנת קבצים ונתונים |
| `cloud_home_credentials` | לכל ספרייה | enum מסוריאל: S3 access+secret, OAuth token, או none עבור iCloud |
| `discogs_api_key` | לכל ספרייה | גישה ל-Discogs API |
| `bae_user_signing_key` | גלובלי | מפתח חתימה Ed25519 |
| `bae_user_public_key` | גלובלי | מפתח ציבורי Ed25519 |

## שני סוגי קבצים

### קובצי מהדורות

כל קובץ שהגיע עם מהדורה: שמע, תמונות, CUE sheets, logs ועוד. אלו נתוני המשתמש. bae שומר אותם כפי שיובאו, כדי שאפשר יהיה לייצא אותם בשלמותם.

### תמונות נתונים

תמונות ש-bae יוצר ומנהל, בנפרד מקובצי המהדורה:

- **עטיפות מהדורות** — תמונות תצוגה לרשתות אלבומים, דפי פרטים וניגון. אחת לכל מהדורה. הן יכולות להגיע מקובץ במהדורה או מ-MusicBrainz/Discogs. bae יוצר עותק משלו כדי לחתוך או לשנות גודל בלי להשפיע על המקור.
- **תמונות אמנים** — נמשכות ממקורות חיצוניים בזמן הייבוא.

## זרימות הפעלה ראשונה

**ספרייה חדשה**: בהפעלה הראשונה אפליקציית שולחן העבודה מציגה מסך פתיחה. המשתמש יוצר ספרייה חדשה, bae יוצר UUID, בונה את מבנה התיקיות ופותח את האפליקציה. `storage/` מתחיל ריק; קבצים מופיעים אחרי ייבוא.

**שחזור מ-cloud home**: המשתמש מספק פרטי גישה ל-cloud home ומפתח הצפנה. bae מוריד snapshot, מיישם חבילות שינוי חדשות יותר ומוריד תמונות. `storage/` המקומי מתחיל ריק; קובצי מהדורות נמשכים מ-cloud home לפי דרישה.

**מעבר ממקומי לענן**: המשתמש מתחבר לספק ענן. bae יוצר מפתח הצפנה אם צריך, דוחף snapshot מלא, תמונות וקובצי מהדורות, ואז עובר לסנכרון מצטבר.
