membership של ספרייה הוא קבוצת המכשירים שמורשים לקרוא ולכתוב אותה. הדף הזה מסביר את המנגנונים הטכניים: זהות, membership chain, חבילות שינוי חתומות ועטיפת מפתחות.

## זהות

לכל מכשיר יש זוג מפתחות Ed25519/X25519, שנוצר בשימוש הראשון ונשמר ב-keyring של מערכת ההפעלה. מפתחות ציבוריים הם זהויות. אין ספרייה מרכזית או שרת חשבונות. מפתחות ציבוריים מוחלפים מחוץ למערכת.

## Membership chain

membership של הספרייה מתועד בשרשרת להוספה בלבד של רשומות חתומות, הנשמרת ב-cloud home בנתיב `membership/{pubkey}/{seq}.enc`. כל רשומה מתעדת פעולת Add או Remove, את המפתח הציבורי והתפקיד של מכשיר היעד, ונחתמת על ידי owner נוכחי.

הרשומה הראשונה היא תמיד המכשיר שממנו נוצרה הספרייה, שנוסף כ-owner. בעת בניית השרשרת היא נבדקת; רשומות עם חתימה לא תקינה או כאלה שהגיעו ממי שאינו owner נדחות.

## חבילות שינוי חתומות

כל חבילת שינוי שנדחפת ל-cloud home חתומה על ידי מפתח Ed25519 של המכשיר שיצר אותה. בזמן משיכה, bae מוודא שהיוצר היה מכשיר מורשה בזמן יצירת החבילה, לפי membership chain. חבילות ממכשירים לא מורשים או עם חתימה לא תקינה נזרקות.

## עטיפת מפתחות

מפתח ההצפנה של הספרייה מוצפן ב-sealed box למפתח X25519 הציבורי של כל מכשיר, ונשמר ב-cloud home ב-`keys/{user_pubkey}.enc`. רק הנמען המיועד יכול לפתוח אותו עם המפתח הפרטי שלו. כשמכשיר מבוטל, נוצר מפתח הצפנה חדש והוא נעטף מחדש לכל המכשירים שנשארו.

## קודי הזמנה

קוד הזמנה כולל את כל מה שמכשיר מצטרף צריך:

- מפתח הצפנת הספרייה, מוצפן ב-sealed box למפתח הציבורי של המכשיר החדש
- פרטי cloud home: סוג ספק, מזהה תיקייה או bucket
- פרטי גישה לאחסון: ב-S3 פרטי IAM שנוצרו עבור המכשיר; בעננים צרכניים שיתוף התיקייה נעשה דרך API של הספק
- רשומת membership חתומה שמוסיפה את המכשיר החדש

מכשיר owner יוצר את הקוד לאחר שקיבל את המפתח הציבורי של המכשיר החדש. המכשיר החדש מדביק אותו ב-bae, פותח את מפתח ההצפנה, מתחבר ל-cloud home ומתחיל לסנכרן.
