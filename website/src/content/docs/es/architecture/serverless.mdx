---
title: Sin servidor propio
description: Cómo bae sincroniza sin un servidor suyo
---

bae no tiene un servidor propio. Cada dispositivo es un cliente que lee y escribe en un cloud home compartido; toda la sincronización pasa por ese almacenamiento, no por una máquina que ejecute bae.

## El cloud home es el punto de encuentro

El [cloud home](/es/architecture/cloud-home) de una biblioteca es un bucket o carpeta en un backend de almacenamiento que controlas: almacenamiento compatible con S3, Google Drive, Dropbox, OneDrive o iCloud. Cada dispositivo:

- envía sus conjuntos de cambios de base de datos cifrados y archivos de edición al cloud home
- descarga los cambios de otros dispositivos desde ahí en cada ciclo de sincronización

Tus dispositivos nunca se hablan directamente entre sí. Convergen porque ambos se sincronizan contra el mismo cloud home.

## Qué vive en el cloud home

- Archivos de edición cifrados: audio, imágenes, etc.
- Snapshots de base de datos y conjuntos de cambios cifrados
- Imágenes de biblioteca cifradas
- La cadena de membresía que registra quién puede leer o escribir la biblioteca

## Almacenamiento sin conocimiento

El backend de almacenamiento nunca contiene claves y nunca descifra. Cada blob se cifra en el cliente antes de subirlo y se descifra en el cliente después de bajarlo. El cloud home no conoce el contenido, los metadatos ni las claves de cifrado de tu biblioteca; no puede leer, buscar ni indexar tu música. Es almacenamiento, nada más.

Añadir otro dispositivo es una concesión de [membresía](/es/architecture/membership) sobre este mismo almacenamiento compartido; no hay servidor al que conectarse.
