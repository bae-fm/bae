title: Visão geral de armazenamento
description: Como bae armazena seus arquivos de música
---

Arquivos de uma edição podem existir em até três lugares. Ao importar uma edição, você escolhe entre **gerenciado** e **não gerenciado**. Arquivos gerenciados são copiados para o armazenamento do bae; arquivos não gerenciados permanecem onde estão.

## Resumo

|                              | Não gerenciado   | Gerenciado — local | Gerenciado — nuvem |
|------------------------------|------------------|--------------------|--------------------|
| Arquivos ficam em            | Seu local        | `~/.bae/libraries/` | Provedor cloud     |
| bae copia ao importar        | Não              | Sim                | Sim                |
| Disponível offline           | Sim              | Sim                | Não                |
| Criptografado em repouso     | Não              | Não                | Apenas home opaco  |
| Pode sincronizar com a nuvem | Não              | Sim                | —                  |
| Sincroniza com outros dispositivos | Não       | Não                | Sim                |
| Apagar edição remove arquivos | Não             | Sim                | Sim                |

Uma edição gerenciada pode ter arquivos localmente, na nuvem ou nos dois. Se você tiver um cloud home configurado, importações gerenciadas vão para os dois.

## Não gerenciado

Aponte bae para arquivos que você já organizou. bae os indexa, mas não move, copia nem toca em nada. Se você já tem sua música organizada do seu jeito, isso permite catalogá-la sem duplicar dados.

A limitação: bae não pode criptografar, sincronizar nem fazer backup de arquivos não gerenciados.

## Gerenciado — local

Toda biblioteca tem um diretório home na sua máquina (`~/.bae/libraries/{uuid}/`). É ali que bae guarda seu banco de dados, imagens e, para edições gerenciadas, uma cópia local dos arquivos da edição.

Ao importar uma edição como gerenciada, bae copia os arquivos para o home da biblioteca. Seus originais não são alterados. A cópia local é a que bae reproduz.

## Gerenciado — nuvem

Um cloud home é um único local remoto de armazenamento que contém seus arquivos de edições, changesets de metadados, arte e snapshots. Configurar um cloud home ativa sincronização entre dispositivos e backup em nuvem.

Ao importar uma edição gerenciada com um cloud home configurado, bae copia os arquivos para o home da biblioteca *e* os envia ao cloud home. Os dois acontecem durante a importação.

Uma edição que existe apenas no cloud home, por exemplo sincronizada de outro dispositivo que ainda não a baixou, não fica disponível para reprodução offline até que os arquivos sejam trazidos localmente.

### Opaco ou navegável

Ao configurar o cloud home, você escolhe como ele armazena objetos, para qualquer provedor:

- **Opaco** (padrão) criptografa cada objeto com a chave da biblioteca e o armazena em um caminho ofuscado. O provedor vê apenas texto cifrado.
- **Navegável** armazena tudo sem criptografia, com nomes reais de arquivos, em caminhos estáveis baseados em ids: `storage/{album_id}/{release_id}/{import_folder}/01 Track.flac` para arquivos de edição e `images/{album_id}/{release_id}/cover.jpg` para arte. Você pode abrir o bucket e reproduzir ou copiar seus arquivos com qualquer ferramenta. As pastas são ids, não texto de artista ou álbum, o que evita colisões e mantém a pasta de cada edição imutável. Nada é criptografado; o home depende do controle de acesso do provedor. Navegável não significa público: as credenciais do bucket controlam o acesso nos dois modos.

Veja [Criptografia](/pt-br/architecture/encryption#modos-de-armazenamento-opaco-e-navegavel) para a comparação completa.

### Provedores aceitos

- **Google Drive** — entre com OAuth; bae cria uma pasta no seu Drive
- **Dropbox** — entre com OAuth
- **OneDrive** — entre com OAuth
- **iCloud Drive** (macOS) — usa seu contêiner iCloud, sem login
- **Compatível com S3** — qualquer bucket: AWS S3, Backblaze B2, Cloudflare R2, Wasabi, MinIO, etc.

Provedores cloud de consumo, como Google Drive e Dropbox, usam login OAuth: sem chaves de API ou configuração de bucket. iCloud Drive, apenas macOS, usa seu contêiner iCloud existente sem login. Provedores compatíveis com S3 exigem configuração manual de credenciais e são voltados a usuários mais técnicos.

## Como funciona

1. Importe uma edição — escolha **gerenciado** ou **não gerenciado**
2. Importações gerenciadas copiam arquivos para o home da biblioteca local
3. Se um cloud home estiver configurado, importações gerenciadas também enviam arquivos para lá: criptografados em um home opaco, em claro em um home navegável
4. Outros dispositivos conectados ao mesmo cloud home sincronizam automaticamente

Veja [Sincronização](/pt-br/storage/sync) para entender a sincronização entre dispositivos e [Criptografia](/pt-br/architecture/encryption) para entender a criptografia de arquivos.
