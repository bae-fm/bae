## Bibliotecas e locais de armazenamento

Uma **biblioteca** é a entidade principal: uma coleção musical com sua própria identidade (`library_id`), nome e chave de criptografia. Ela vive em um **home da biblioteca** no disco (`~/.bae/libraries/{uuid}/`), onde o app de desktop grava o banco de dados autoritativo.

Uma biblioteca pode ter opcionalmente um **cloud home**: um único local cloud, como uma pasta do Google Drive ou bucket S3, que funciona como centro da sincronização multidispositivo. Um cloud home por biblioteca, configurado em `config.yaml`. Veja [Cloud Home](/pt-br/architecture/cloud-home) para detalhes.

Arquivos de edição podem existir em um ou mais destes locais:

- **Home da biblioteca** (`~/.bae/libraries/{uuid}/storage/`) — cópia local, disponível offline
- **Cloud home** (`cloud-home/storage/`) — cópia criptografada, disponível para sincronização
- **Não gerenciado** — arquivos ficam onde estiverem no disco; bae apenas os indexa

Uma edição pode ser apenas local, apenas cloud ou ambas. Arquivos apenas cloud não ficam disponíveis para reprodução offline.

## Estrutura de diretórios

### Home da biblioteca

```
~/.bae/libraries/{uuid}/
  config.yaml                  # configurações específicas do dispositivo (não sincronizadas)
  library.db                   # SQLite -- todos os metadados
  images/ab/cd/{id}            # imagens da biblioteca (capas, fotos de artistas)
  storage/ab/cd/{file_id}      # arquivos de edição
```

`config.yaml` contém configurações específicas do dispositivo. Ele não é sincronizado. Credenciais ficam no chaveiro do sistema operacional, não aqui.

Arquivos em `images/` e `storage/` usam uma estrutura baseada em hash: os 2 primeiros caracteres do ID formam o diretório de prefixo e os 2 seguintes formam um subdiretório. Não há nomes de arquivo nem extensões no disco; nomes originais e tipos de conteúdo ficam no banco de dados. A mesma estrutura existe no home da biblioteca e no cloud home.

### Cloud home

O cloud home espelha os dados da biblioteca e adiciona sincronização e controle de acesso:

| Caminho | Finalidade |
|---|---|
| `snapshot.db.enc` | Snapshot completo do banco de dados para iniciar dispositivos novos |
| `changes/{device_id}/{seq}.enc` | Changesets incrementais de sincronização |
| `heads/{device_id}.json.enc` | Números de sequência por dispositivo |
| `images/ab/cd/{id}` | Imagens da biblioteca criptografadas |
| `storage/ab/cd/{file_id}` | Arquivos de edição criptografados |
| `membership/{pubkey}/{seq}.enc` | Entradas da cadeia de membros |
| `keys/{user_pubkey}.enc` | Chaves de criptografia envelopadas por dispositivo |

### Entradas do chaveiro

Gerenciadas pelo `KeyService`, usando o chaveiro do sistema operacional. No macOS, é o armazenamento de dados protegido com sincronização do iCloud Keychain. Todas as entradas usam namespace por `library_id`, salvo indicação contrária.

| Entrada | Escopo | Finalidade |
|---|---|---|
| `encryption_master_key` | por biblioteca | Criptografia de arquivos e metadados |
| `cloud_home_credentials` | por biblioteca | Enum serializado: acesso+segredo S3, token OAuth ou nenhum (iCloud) |
| `discogs_api_key` | por biblioteca | Acesso à API do Discogs |
| `bae_user_signing_key` | global | Chave de assinatura Ed25519 |
| `bae_user_public_key` | global | Chave pública Ed25519 |

## Duas classes de arquivos

### Arquivos de edição

Quaisquer arquivos que vieram com uma edição: áudio, imagens, folhas CUE, logs, etc. Esses são dados do usuário. bae os armazena exatamente como importados, preservando os arquivos originais para que possam ser exportados intactos.

### Imagens de metadados

Imagens que bae cria e gerencia, separadas dos arquivos de edição:

- **Capas de edição** — arte exibida em grades de álbum, telas de detalhe e reprodução. Uma por edição. Pode vir de um arquivo da edição ou do MusicBrainz/Discogs. bae faz sua própria cópia para poder cortar ou redimensionar sem afetar o original.
- **Imagens de artistas** — buscadas de fontes externas durante a importação.

## Fluxos do primeiro uso

**Nova biblioteca**: no primeiro início, o app de desktop mostra uma tela de boas-vindas. O usuário cria uma nova biblioteca, o que gera um UUID, cria a estrutura de diretórios e abre o app. O diretório `storage/` começa vazio; arquivos aparecem quando o usuário importa.

**Restaurar do cloud home**: o usuário fornece credenciais do cloud home e a chave de criptografia. bae baixa o snapshot, aplica changesets mais recentes e baixa imagens. O `storage/` local começa vazio; arquivos de edição são transmitidos do cloud home sob demanda.

**Passar de local para cloud**: o usuário entra com um provedor cloud. bae gera uma chave de criptografia se necessário, envia um snapshot completo, imagens e arquivos de edição, e então muda para sincronização incremental.
