---
title: Membros
description: Identidade, cadeia de membros e changesets assinados
---

Os membros de uma biblioteca são os dispositivos autorizados a ler e gravar nela. Esta página cobre os mecanismos técnicos: identidade, cadeia de membros, changesets assinados e envelopamento de chaves.

## Identidade

Cada dispositivo tem um par de chaves Ed25519/X25519, gerado no primeiro uso e armazenado no chaveiro do sistema operacional. Chaves públicas são identidades. Não há diretório central nem servidor de contas. Chaves públicas são trocadas fora do sistema.

## Cadeia de membros

Os membros de uma biblioteca são acompanhados por uma cadeia somente anexável de entradas assinadas armazenadas no cloud home em `membership/{pubkey}/{seq}.enc`. Cada entrada registra uma ação Add ou Remove, a chave pública e o papel do dispositivo alvo, e é assinada por um proprietário atual.

A primeira entrada é sempre o dispositivo de origem, adicionado como proprietário. A cadeia é validada na construção: entradas com assinaturas inválidas ou vindas de não proprietários são rejeitadas.

## Changesets assinados

Cada changeset enviado ao cloud home é assinado pela chave Ed25519 do dispositivo autor. Ao baixar, bae verifica se o autor era um dispositivo autorizado no momento em que o changeset foi criado, consultando a cadeia de membros. Changesets de dispositivos não autorizados ou com assinaturas inválidas são descartados.

## Envelopamento de chaves

A chave de criptografia da biblioteca é envelopada, criptografada por sealed box, para a chave pública X25519 de cada dispositivo e armazenada no cloud home em `keys/{user_pubkey}.enc`. Apenas o destinatário previsto pode desembrulhá-la com sua chave privada. Quando um dispositivo é revogado, uma nova chave de criptografia é gerada e reenvelopada para todos os dispositivos restantes.

## Códigos de convite

Um código de convite agrupa tudo que um dispositivo novo precisa:

- A chave de criptografia da biblioteca, criptografada por sealed box para a chave pública do novo dispositivo
- Coordenadas do cloud home: tipo de provedor, ID de pasta ou bucket
- Credenciais de armazenamento: no S3, credenciais IAM emitidas; em clouds de consumo, o compartilhamento da pasta acontece pela API do provedor
- Uma entrada assinada da cadeia de membros adicionando o novo dispositivo

Um dispositivo proprietário gera o código depois de receber a chave pública do novo dispositivo. O novo dispositivo cola o código no bae, desembrulha a chave de criptografia, conecta-se ao cloud home e começa a sincronizar.
