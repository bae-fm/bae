---
title: 导入
description: 把你的文件夹匹配到真实发行
---

一个抓轨文件夹对自身几乎一无所知。它来自哪个发行、哪次压制、哪个厂牌、署名是谁、第 12 轨实际在哪里结束：这些信息存在于 MusicBrainz 和 Discogs 这类数据库中，而不在你的文件名里。导入就是 bae 连接两者的方式：你把它指向你的音乐，它判断每个文件夹是哪一个发行，资料库把该文件夹记录为该发行。

导入发生在桌面端（macOS、Windows）。你的文件会被读取，但永远不会被改动：bae 不会移动、重命名、重写标签或重新编码任何内容。导入后文件放在哪里，见[存储和离线](/zh-hans/guide/storage)。

## 监视文件夹

切换到 **Import** 区域并添加文件夹：选择它、拖到窗口上，或按 <kbd>⌘I</kbd>。从那之后 bae 会监视该文件夹。新音乐放进去后会自动显示为新候选项；不需要手动重新扫描。仍在下载的文件夹会被忽略，直到下载完成。

扫描会识别抓轨实际采用的发行形态：

| 布局 | 看起来像什么 |
|--------|-------------------|
| 每轨一个文件 | `01 - Track Title.flac`、`02 - Track Title.flac`、... |
| CUE + 镜像 | `album.cue` + `album.flac`，整张碟一个文件 |
| 多碟 | `CD1/`、`CD2/` 子文件夹，内部可为任一形态 |
| 合集 | 一个包含多个文件夹的文件夹，每个子文件夹都是自己的发行 |

bae 导入它能播放的格式：FLAC、MP3、APE、ALAC 和 `.m4a` 中的 AAC、WAV、AIFF、Ogg Vorbis、Opus、WavPack，以及 DSD（`.dsf`/`.dff`）。文件夹中的图像和文档（CUE sheets、抓轨日志、文本文件）会被识别并与发行一起保留。

## 识别发行

选择候选项后，bae 会开始识别它。它不会从标签猜测，而是读取文件夹中的证据，并逐项查找：

- **Disc ID。** CD 精确曲目布局的指纹，由抓轨日志或 CUE sheet 计算得出。匹配时，它会识别出具体的 CD 版次。
- **条码。** 通过文字识别从文件夹里的封面扫描图读取，或从 CUE sheet 读取。
- **目录号和文本。** 在图像、文件名和文件夹名中找到的目录号，用于缩小结果范围。

这些信号会同时对照 MusicBrainz 和 Discogs 查找，并交叉核对结果。每个信号都显示为结果上方的徽标：你可以看到找到的内容、来源（悬停可看来源：disc TOC、CUE sheet、封面扫描、文件夹名），也可以在某个信号有误导性时单独关闭它。

三种结果：

- **Found。** 证据指向同一个发行组。你从列表中选择确切压制版本。
- **Conflict。** 两个信号指向不同发行，例如 disc ID 和条码不一致。bae 会显示双方，你选择信任哪一个，或忽略某个信号。
- **Nothing found。** 手动搜索：艺人和专辑、目录号或条码，可针对任一数据库。图像中识别出的文本会作为自动补全提供。

你也可以**跳过识别**，以未知发行导入。bae 随后会退回到你文件内嵌标签中的名称；等该发行进入数据库，或你有更好的证据时，可以稍后重新识别。

## 精确或近似

选择匹配项后，bae 会对照你的文件检查它，并标记曲目数量不匹配。随后你声明这个匹配是什么：

- **Exact**：你的文件就是这次压制。
- **Metadata only**：专辑正确，但不一定是这次确切压制。bae 使用元数据，并记住压制版本是近似的。

如果该发行已在你的资料库中，或同一专辑的另一压制已在资料库中，bae 会在你导入重复项之前告诉你。

## 确认并导入

确认窗格会显示导入将写入的一切：

- **封面。** 从数据库图像、你文件夹中的图片，或文件内嵌图像中选择。之后可以更改。
- **元数据。** 专辑、艺人、年份、厂牌、目录号、国家或地区、条码，以及每一轨：在保存任何内容前都可在这里编辑。
- **存储。** 如果已连接云端主目录，选择 bae 是否应在你的云端管理这些文件，以及是否也保留本地副本。见[存储和离线](/zh-hans/guide/storage)。

导入在后台运行：bae 会验证每一轨都能完整解码，为专辑和每一轨测量响度，保存发行，并且对于托管导入开始上传。候选列表会移到下一个文件夹，发行会立即可播放。

## 数据来源

**MusicBrainz** 不需要账号或密钥。**Discogs** 需要你自己的免费 API token；把它粘贴到 Settings 中，如果它停止工作，bae 会告诉你。没有 token 时，Discogs 搜索和来自 Discogs 的元数据不可用，其他功能照常工作。两个服务都有速率限制；bae 会控制请求节奏，使其保持在限制内。
