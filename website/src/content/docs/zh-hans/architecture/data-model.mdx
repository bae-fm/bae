## 资料库和存储位置

**资料库**是顶层实体：一个音乐集合，拥有自己的身份（`library_id`）、名称和加密密钥。它位于磁盘上的 **library home**（`~/.bae/libraries/{uuid}/`），桌面应用在这里写入权威数据库。

资料库可以选择配置 **cloud home**：一个云端位置（Google Drive 文件夹、S3 bucket 等），作为多设备同步的中心。每个资料库最多一个 cloud home，配置在 `config.yaml` 中。详情见 [Cloud Home](/zh-hans/architecture/cloud-home)。

发行版本文件可以存在于一个或多个位置：

- **Library home**（`~/.bae/libraries/{uuid}/storage/`）— 本地副本，可离线使用
- **Cloud home**（`cloud-home/storage/`）— 加密副本，用于同步
- **非受管理** — 文件保持在磁盘原位，bae 只建立索引

一个发行版本可以仅在本地、仅在云端，或两者都有。仅云端文件不能离线播放。

## 目录布局

### Library home

```
~/.bae/libraries/{uuid}/
  config.yaml                  # 设备专属设置（不同步）
  library.db                   # SQLite，保存所有元数据
  images/ab/cd/{id}            # 资料库图片（封面、艺人照片）
  storage/ab/cd/{file_id}      # 发行版本文件
```

`config.yaml` 保存设备专属设置，不会同步。凭据保存在操作系统钥匙串中，不保存在这里。

`images/` 和 `storage/` 下的文件使用基于哈希的布局：ID 的前 2 个字符作为前缀目录，接下来的 2 个字符作为子目录。磁盘上没有原始文件名或扩展名；原始文件名和内容类型保存在数据库中。library home 和 cloud home 都使用同样布局。

### Cloud home

cloud home 镜像资料库数据，并加入同步和访问控制所需的内容：

| 路径 | 用途 |
|---|---|
| `snapshot.db.enc` | 完整数据库快照（供新设备启动） |
| `changes/{device_id}/{seq}.enc` | 增量同步变更集 |
| `heads/{device_id}.json.enc` | 每台设备的序号 |
| `images/ab/cd/{id}` | 资料库图片（已加密） |
| `storage/ab/cd/{file_id}` | 发行版本文件（已加密） |
| `membership/{pubkey}/{seq}.enc` | membership chain 条目 |
| `keys/{user_pubkey}.enc` | 为每台设备封装的加密密钥 |

### 钥匙串条目

这些条目由 `KeyService` 管理，并使用操作系统钥匙串（macOS 上是受保护数据存储，可通过 iCloud Keychain 同步）。除特别说明外，所有条目都以 `library_id` 命名隔离。

| 条目 | 范围 | 用途 |
|---|---|---|
| `encryption_master_key` | 每个资料库 | 文件和元数据加密 |
| `cloud_home_credentials` | 每个资料库 | 序列化枚举：S3 access+secret、OAuth token，或 none（iCloud） |
| `discogs_api_key` | 每个资料库 | Discogs API 访问 |
| `bae_user_signing_key` | 全局 | Ed25519 签名密钥 |
| `bae_user_public_key` | 全局 | Ed25519 公钥 |

## 两类文件

### 发行版本文件

发行版本自带的任何文件：音频、图片、CUE sheet、日志等。这些是用户数据。bae 按导入时的样子保存它们，保留原始文件以便完整导出。

### 元数据图片

bae 创建并管理的图片，与发行版本文件分开：

- **发行封面** — 专辑网格、详情视图和播放界面使用的展示图片。每个发行版本一张。可能来自发行文件夹，也可能来自 MusicBrainz 或 Discogs。bae 会创建自己的副本，因此裁剪或缩放不会影响原文件。
- **艺人图片** — 导入时从外部来源获取。

## 首次运行流程

**新资料库**：首次运行时，桌面应用显示欢迎界面。用户创建新资料库，bae 生成 UUID、创建目录结构并进入应用。`storage/` 目录一开始为空；用户导入后才会出现文件。

**从 cloud home 恢复**：用户提供 cloud home 凭据和加密密钥。bae 下载快照，应用更新的变更集，并下载图片。本地 `storage/` 一开始为空；发行版本文件按需从 cloud home 流式读取。

**从本地转到云端**：用户登录云提供商。bae 生成加密密钥（如果需要），推送完整快照、图片和发行版本文件，然后切换到增量同步。
