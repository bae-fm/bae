导入把一个文件夹转成目录项，不修改文件的任何一个字节。本页说明[使用指南](/zh-hans/guide/importing)所述流程背后的流水线。

## 扫描

监视文件夹由平台文件系统事件监控，经过防抖，并在更改时重新扫描；扫描会与现有候选列表对齐，而不是从头开始。扫描器会把文件夹分类为一个发行（音频直接在其中，或像 `CD1`/`CD2` 这样的碟形子文件夹），或把它作为合集递归进入。文件按扩展名分类为音频、图像和文档，然后探测音频：真正重要的 codec 是 FFmpeg 在字节中找到的，而不是文件扩展名。包含 partial-download marker 的文件夹会被排除，直到下载完成。

CUE sheet 会把一个音频镜像转成曲目列表。解析器处理 pregap 和 postgap、每轨 performers 和 ISRC，以及单文件镜像和每轨一文件 CUE 布局。曲目边界会从 CUE frames（1/75 秒）转换为精确采样位置，之后成为播放使用的字节窗口和采样窗口。

## 元数据种子

每个候选项都有一个明确的元数据种子：在**查找**中选择的外部发行、已存储的**文件标签**快照，或**手动**输入。切换界面不会改写这个种子。

### 查找

查找是唯一会计算 Disc ID、识别条码和目录文字、查询服务并匹配结果的路径。只有启用自动查找且配置的默认模式解析为查找时，后台扫描才会运行这条路径。明确的查找操作不受该设置限制。打开文件标签或手动绝不会启动提取、服务查询或匹配。

内嵌音频标签不是查找证据：它们描述的是打标签者相信的内容，而不是实际压制版本。查找结果保留来源，因此界面可以说明为何提供每个结果。

### 文件标签

文件标签按需读取内嵌音频标签和 CUE 元数据。预览会存储一份快照，并记录候选项的扫描代次、文件编辑版本和已观察的音频文件。选择**使用文件标签**会选定这份快照。提交会使用同一份快照；如果版本或观察结果发生变化，它会在写入资料库之前失败，不会静默读取另一个答案。

### 手动

手动不执行任何元数据输入输出。选择**手动输入**会创建空白的可编辑发行，同时保留扫描得到的物理曲目布局。

**打开未设种子的候选项时显示**设置决定未设种子的候选项最初显示哪个界面。固定选项为查找、文件标签和手动；**上次使用**会解析为用户最后一次明确选择的模式。显示状态始终与已存储的种子分开。

## 来源

MusicBrainz 以匿名方式查询，并严格保持每秒一个请求的节奏。Discogs 使用用户保存在 keyring 中的个人 token 认证，在其速率限制内控制节奏并重试；被拒绝的 token 会如实报告，因此 UI 可以标记它，而不是让搜索安静失败。响应按会话缓存，获胜来源的原始 JSON 会归档进数据库，以便将来重新解释。

## 提交

确认导入会按顺序运行：

1. **解码验证**：每一轨从头到尾解码；无法完整解码的抓轨会在写入任何内容前导入失败（一个 config flag 可以禁用此项）。
2. **响度分析**：在同一次解码遍历中测量每轨和每专辑的 integrated loudness 与 true peak，并存储以供 replay-gain 使用。
3. **封面选择**：所选图像（远程、文件夹图片或内嵌图像）重新渲染为显示缩略图；如果原图来自文件夹，它会保留在发行文件中。
4. **原子写入**：release、tracks、credits、identities、formats、segments、files 和 cover 在一个 transaction 中提交。不存在半导入状态。

发行落库时原位引用用户文件。如果用户选择云端托管，上传会在提交后作为存储转换发生，并且文件原始字节始终是真相来源；用户交给 bae 的任何内容都不会被删除或改动。

## 识别抓轨

每个发行都会记录其导入文件夹结构的 content hash（相对路径和大小，与位置无关）。重新扫描用它标记已在资料库中的文件夹，同一抓轨的重新导入也用它找到并替换先前发行，而不是复制一份。
