## المكتبات ومواقع التخزين

**المكتبة** هي الكيان الأعلى: مجموعة موسيقى لها هوية (`library_id`) واسم ومفتاح تشفير. تعيش في **library home** على القرص (`~/.bae/libraries/{uuid}/`)، حيث يكتب تطبيق سطح المكتب قاعدة البيانات المعتمدة.

يمكن للمكتبة أن تملك **cloud home** اختياريًا: موقعًا سحابيًا واحدًا مثل مجلد Google Drive أو bucket S3 يعمل كمركز للمزامنة بين الأجهزة. لكل مكتبة cloud home واحد، مضبوط في `config.yaml`. راجع [Cloud Home](/ar/architecture/cloud-home).

يمكن أن تعيش ملفات الإصدار في واحد أو أكثر من هذه المواضع:

- **Library home** (`~/.bae/libraries/{uuid}/storage/`) — نسخة محلية متاحة دون اتصال
- **Cloud home** (`cloud-home/storage/`) — نسخة مشفرة للمزامنة
- **غير مدار** — تبقى الملفات في مكانها على القرص ويفهرسها bae فقط

قد يكون الإصدار محليًا فقط، أو سحابيًا فقط، أو الاثنين معًا. الملفات السحابية فقط لا تعمل دون اتصال.

## تخطيط المجلدات

### Library home

```
~/.bae/libraries/{uuid}/
  config.yaml                  # إعدادات خاصة بالجهاز، لا تتزامن
  library.db                   # SQLite، كل البيانات الوصفية
  images/ab/cd/{id}            # صور المكتبة
  storage/ab/cd/{file_id}      # ملفات الإصدارات
```

`config.yaml` يحفظ إعدادات خاصة بالجهاز ولا يتزامن. بيانات الاعتماد تحفظ في keyring نظام التشغيل، لا هنا.

تستخدم الملفات تحت `images/` و `storage/` تخطيطًا مبنيًا على hash: أول حرفين من المعرف يشكلان مجلدًا، والحرفان التاليان مجلدًا فرعيًا. لا توجد أسماء ملفات أو امتدادات على القرص؛ الأسماء الأصلية وأنواع المحتوى محفوظة في قاعدة البيانات. التخطيط نفسه يستخدم في library home و cloud home.

### Cloud home

يعكس cloud home بيانات المكتبة ويضيف آليات المزامنة والتحكم بالوصول:

| المسار | الغرض |
|---|---|
| `snapshot.db.enc` | لقطة كاملة من قاعدة البيانات لجهاز جديد |
| `changes/{device_id}/{seq}.enc` | حزم تغييرات تزايدية |
| `heads/{device_id}.json.enc` | أرقام تسلسل لكل جهاز |
| `images/ab/cd/{id}` | صور المكتبة، مشفرة |
| `storage/ab/cd/{file_id}` | ملفات الإصدارات، مشفرة |
| `membership/{pubkey}/{seq}.enc` | إدخالات membership chain |
| `keys/{user_pubkey}.enc` | مفاتيح تشفير ملفوفة لكل جهاز |

### إدخالات keyring

يديرها `KeyService` باستخدام keyring نظام التشغيل. على macOS يستخدم مخزن البيانات المحمي مع مزامنة iCloud Keychain. كل الإدخالات معزولة حسب `library_id` إلا إذا ذكر غير ذلك.

| الإدخال | النطاق | الغرض |
|---|---|---|
| `encryption_master_key` | لكل مكتبة | تشفير الملفات والبيانات الوصفية |
| `cloud_home_credentials` | لكل مكتبة | enum متسلسل: S3 access+secret أو OAuth token أو none لـ iCloud |
| `discogs_api_key` | لكل مكتبة | وصول Discogs API |
| `bae_user_signing_key` | عام | مفتاح توقيع Ed25519 |
| `bae_user_public_key` | عام | مفتاح Ed25519 العام |

## نوعان من الملفات

### ملفات الإصدارات

أي ملفات جاءت مع الإصدار: صوت، صور، CUE sheets، logs، وغيرها. هذه بيانات المستخدم. يحفظها bae كما استوردت حتى يمكن تصديرها كما هي.

### صور البيانات الوصفية

صور ينشئها ويديرها bae، منفصلة عن ملفات الإصدار:

- **أغلفة الإصدارات** — صور العرض لشبكات الألبومات وصفحات التفاصيل والتشغيل. لكل إصدار صورة واحدة. قد تأتي من ملف داخل الإصدار أو من MusicBrainz/Discogs. يحتفظ bae بنسخة خاصة كي يستطيع القص أو تغيير الحجم دون لمس الأصل.
- **صور الفنانين** — تجلب من مصادر خارجية أثناء الاستيراد.

## تدفقات التشغيل الأول

**مكتبة جديدة**: عند التشغيل الأول يعرض تطبيق سطح المكتب شاشة ترحيب. ينشئ المستخدم مكتبة جديدة، فيولد bae UUID، وينشئ البنية، ويفتح التطبيق. يبدأ مجلد `storage/` فارغًا وتظهر الملفات بعد الاستيراد.

**استعادة من cloud home**: يقدم المستخدم بيانات اعتماد cloud home ومفتاح التشفير. ينزل bae اللقطة، يطبق أي حزم تغييرات أحدث، وينزل الصور. يبدأ `storage/` المحلي فارغًا؛ تبث ملفات الإصدارات من cloud home عند الحاجة.

**الانتقال من محلي إلى سحابي**: يسجل المستخدم الدخول إلى مزود سحابي. يولد bae مفتاح تشفير إن لزم، ويدفع لقطة كاملة وصورًا وملفات إصدارات، ثم ينتقل إلى المزامنة التزايدية.
