---
title: Serverless
description: How bae syncs without a server of its own
---

bae has no server of its own. Every device is a client that reads and writes a
shared cloud home; all sync flows through that storage, not through a machine bae
runs.

## The cloud home is the meeting point

A library's [cloud home](/architecture/cloud-home) is a bucket or folder on a
storage backend you control: S3-compatible storage, Google Drive, Dropbox,
OneDrive, or iCloud. Each device:

- pushes its encrypted database changesets and release files to the cloud home
- pulls the other devices' changes from it on each sync cycle

Your devices never talk to each other directly. They converge by both syncing
against the same cloud home.

## What lives in the cloud home

- Encrypted release files (audio, images, etc.)
- Encrypted database snapshots and sync changesets
- Encrypted library images
- The membership chain that records who can read or write the library

## Zero-knowledge storage

The storage backend never holds keys and never decrypts. Every blob is encrypted
on the client before upload and decrypted on the client after download. The cloud
home has no knowledge of your library contents, metadata, or encryption keys --
it cannot read, search, or index your music. It is storage, nothing more.

Adding another device is a [membership](/architecture/membership) grant over this
same shared storage -- there is no server to connect to.
