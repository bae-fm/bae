---
title: Membership
description: Identity, membership chain, and signed changesets
---

A library's membership is the set of devices authorized to read and write it. This page covers the technical mechanisms behind that: identity, the membership chain, signed changesets, and key wrapping.

## Identity

Each device has an Ed25519/X25519 keypair, generated on first use and stored in the OS keyring. Public keys are identities. There is no central directory or account server. Public keys are exchanged out-of-band.

## Membership chain

A library's membership is tracked by an append-only chain of signed entries stored in the cloud home at `membership/{pubkey}/{seq}.enc`. Each entry records an Add or Remove action, the target device's public key and role, and is signed by a current owner.

The first entry is always the originating device, added as owner. The chain is validated on construction -- entries with invalid signatures or from non-owners are rejected.

## Signed changesets

Every changeset pushed to the cloud home is signed by its author device's Ed25519 key. On pull, bae verifies that the author was an authorized device at the time the changeset was created (by checking the membership chain). Changesets from unauthorized devices or with invalid signatures are discarded.

## Key wrapping

The library's encryption key is wrapped (sealed-box encrypted) to each device's X25519 public key and stored in the cloud home at `keys/{user_pubkey}.enc`. Only the intended recipient can unwrap it with its private key. When a device is revoked, a new encryption key is generated and re-wrapped to all remaining devices.

## Invite codes

An invite code bundles everything a joining device needs:

- The library encryption key, sealed-box encrypted to the new device's public key
- Cloud home coordinates (provider type, folder ID or bucket)
- Storage credentials (on S3, minted IAM credentials; on consumer clouds, folder sharing happens via the provider API)
- A signed membership chain entry adding the new device

An owner device generates the code after receiving the new device's public key. The new device pastes it into bae, which unwraps the encryption key, connects to the cloud home, and starts syncing.
