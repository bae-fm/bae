title: Synchronisation
description: Toute votre bibliothèque sur chaque appareil, via votre propre cloud
---

La synchronisation signifie souvent le serveur de quelqu’un d’autre : un compte, un abonnement, une entreprise qui peut lire votre bibliothèque. bae synchronise via **votre** cloud, un stockage que vous avez déjà, et ne fait fonctionner aucun serveur. Vos appareils écrivent des changements chiffrés dans ce stockage et lisent ceux des autres ; le fournisseur conserve les octets et ne peut pas les lire.

Une bibliothèque, chaque appareil, et le seul compte impliqué est un compte que vous possédez déjà.

## L’emplacement cloud

L’emplacement cloud d’une bibliothèque est un emplacement unique dans votre stockage : un dossier dans votre Google Drive, Dropbox ou OneDrive, votre iCloud, ou tout bucket compatible S3 (AWS, Backblaze B2, Cloudflare R2, Wasabi, MinIO, ...). Il contient tout ce que la bibliothèque synchronise : les changements du catalogue, les illustrations et l’audio des sorties que vous laissez bae gérer.

Configurez-le dans Réglages, sous Synchronisation :

1. Choisissez un fournisseur. Les clouds grand public se connectent avec la propre page de connexion du fournisseur ; rien concernant votre compte n’est stocké au-delà des jetons qu’il émet. iCloud utilise votre Apple ID tel quel. S3 demande bucket, région, endpoint et clés, vérifiés avant leur enregistrement.
2. Choisissez comment l’emplacement stocke les objets (voir ci-dessous).
3. bae commence la synchronisation.

Une bibliothèque sans emplacement cloud est complète par elle-même. Le local seul est un mode, pas une limitation, et déconnecter l’emplacement cloud y revient.

## Opaque ou navigable

Lors de la configuration, vous choisissez ce que le fournisseur peut voir, et le choix est permanent pour cet emplacement :

- **Opaque** (par défaut) : chaque objet est chiffré sur votre appareil avant l’envoi et stocké sous des noms sans signification. Le fournisseur, ou toute personne qui entre dans le bucket, voit du texte chiffré. C’est le mode décrit par la page [chiffrement](/fr/reference/encryption), et le seul qui prend en charge l’ajout d’autres appareils et membres.
- **Navigable** : les objets sont stockés en clair avec de vrais noms de fichiers, dans des dossiers nommés par artiste et album. Vous pouvez ouvrir le bucket avec n’importe quel outil et copier ou lire vos fichiers directement. Rien n’est chiffré, donc le contrôle d’accès du bucket est la seule protection, et l’emplacement ne peut pas être partagé.

## Ce qui se synchronise

- Le catalogue : albums, sorties, pistes, crédits, œuvres, identités, modifications. Chaque appareil reçoit tout.
- Illustrations : pochettes et images d’artistes, récupérées d’avance pour que les grilles s’affichent partout.
- Audio : uniquement pour les sorties que vous avez choisi de gérer dans le cloud. Les sorties non gérées restent purement locales, avec leurs entrées de catalogue incluses sur les autres appareils mais les octets seulement là où vous les avez importées.

L’état propre à l’appareil ne se synchronise pas : position de lecture, volume, file d’attente et réglages de l’appareil restent sur l’appareil.

## Quand la synchronisation se lance

La synchronisation s’exécute d’elle-même : après des changements, selon un minuteur et à la demande avec **Sync Now**. Les modifications arrivent sur les autres appareils sous forme de petits changements, quelques secondes plus tard dans des conditions normales. Deux appareils qui modifient en même temps gagnent tous les deux là où ils ne se heurtent pas : bae fusionne les modifications concurrentes champ par champ, et une sortie supprimée reste supprimée même si elle a été modifiée ailleurs au même moment. Rien ne vous demande jamais de résoudre un conflit.

## En cas d’échec

Les échecs de synchronisation n’interrompent pas la bibliothèque ; vous continuez à parcourir, lire et importer localement pendant que bae réessaie avec attente progressive. La ligne d’état affiche la synchronisation et l’heure de dernière synchronisation ; un échec affiche une bannière avec l’erreur, et les envois peuvent être mis en pause, réessayés et inspectés dans le [Storage Manager](/fr/guide/storage#the-storage-manager). Si la connexion de l’emplacement cloud expire, bae vous demande de vous reconnecter.
