L'importazione trasforma una cartella di file in una voce di catalogo senza modificare un byte dei file. Questa pagina è la pipeline dietro il flusso descritto nella [guida all'uso](/it/guide/importing).

## Scansione

Le cartelle osservate sono monitorate dagli eventi del file system della piattaforma, raggruppate, e scansionate di nuovo al cambiamento; le scansioni riconciliano contro la lista candidati esistente invece di ricominciare da capo. Lo scanner classifica una cartella come una release (audio direttamente dentro, o sottocartelle a forma di disco come `CD1`/`CD2`), oppure ricorre dentro di essa come raccolta. I file vengono classificati per estensione in audio, grafica e documenti, poi l'audio viene sondato: il codec che conta è quello che FFmpeg trova nei byte, non l'estensione del file. Le cartelle che contengono marcatori di scaricamento parziale sono escluse finché lo scaricamento non finisce.

Un foglio CUE trasforma un'immagine audio in una lista tracce. Il parser gestisce pregap e postgap, performer e ISRC per traccia, e sia immagini a file singolo sia layout CUE con un file per traccia. I confini delle tracce vengono convertiti da frame CUE (1/75 di secondo) a posizioni di campione esatte, che poi diventano le finestre di byte e campioni usate dalla riproduzione.

## Semi di metadati

Ogni candidato ha un seed di metadati esplicito: una versione esterna scelta in **Ricerca**, uno snapshot archiviato di **Tag file** o una voce **Manuale**. Cambiare superficie non riscrive quel seme.

### Ricerca

La ricerca è l'unico percorso che estrae un ID disco, riconosce i codici a barre e il testo del catalogo, interroga i fornitori e abbina i risultati. La scansione in background esegue questo percorso solo quando la ricerca automatica è abilitata e l'impostazione predefinita configurata si risolve in Ricerca. Un'azione Ricerca esplicita può eseguirla indipendentemente da tale impostazione. L'apertura dei tag dei file o del manuale non avvia mai l'estrazione, le query del provider o la corrispondenza.

I tag audio incorporati non sono prove di ricerca: descrivono ciò in cui credeva un tagger, non ciò che è stato premuto. I risultati della ricerca riportano la loro provenienza in modo che l'interfaccia possa spiegare perché viene offerto ciascun risultato.

### Tag dei file

I tag dei file leggono pigramente i tag audio incorporati e i metadati CUE. L'anteprima memorizza un'istantanea contrassegnata con la generazione della scansione del candidato, la revisione della modifica del file e i file audio osservati. Scegliendo **Utilizza tag file** si seleziona l'istantanea. Il commit consuma la stessa istantanea e fallisce prima che la libreria scriva se il suo timbro o le sue osservazioni sono cambiati; non legge silenziosamente una risposta diversa.

### Manuale

Il manuale non esegue input o output di metadati. Scegliendo **Inserisci manualmente** si crea una versione modificabile vuota mantenendo il layout della traccia fisica scansionata.

L'impostazione **Apri candidati senza seed in** seleziona la superficie iniziale per i candidati senza seed. Le sue scelte fisse sono Ricerca, Tag file e Manuale; **Ultimo utilizzo** si risolve nell'ultima modalità scelta esplicitamente dall'utente. La presentazione rimane separata dal seme immagazzinato.

## Fonti

MusicBrainz viene interrogato anonimamente con un ritmo rigido di una richiesta al secondo. Discogs si autentica con il token personale dell'utente dal portachiavi, dosa e ritenta entro i suoi limiti di frequenza, e un token rifiutato viene riportato come tale così la UI può segnalarlo invece di far fallire le ricerche in silenzio. Le risposte sono memorizzate in cache per sessione, e il JSON grezzo della fonte vincente viene archiviato nel database per reinterpretazioni future.

## Commit

Confermare un'importazione esegue, in ordine:

1. **Verifica di decodifica**: ogni traccia viene decodificata da inizio a fine; un rip che non può essere decodificato completamente fa fallire l'importazione prima che venga scritto qualcosa (un flag di configurazione può disattivarlo).
2. **Analisi della sonorità**: sonorità integrata e true peak vengono misurati per traccia e per album durante lo stesso passaggio di decodifica, salvati per l'uso replay-gain.
3. **Scelta della copertina**: la grafica scelta (remota, immagine della cartella o incorporata) viene renderizzata di nuovo in una miniatura di visualizzazione; l'originale viene conservato tra i file della release se proveniva dalla cartella.
4. **Scrittura atomica**: release, tracce, crediti, identità, formati, segmenti, file e copertina vengono salvati in una transazione. Non esiste uno stato importato a metà.

La release arriva riferendo i file dell'utente sul posto. Se l'utente ha scelto la gestione cloud, il caricamento avviene dopo il commit come transizione di archiviazione, e i byte originali dei file restano la fonte di verità per tutto il tempo; nulla di ciò che l'utente ha dato a bae viene mai eliminato o alterato.

## Riconoscere i rip

Ogni release registra un hash del contenuto sulla struttura della cartella importata (percorsi relativi e dimensioni, indipendente dalla posizione). Le nuove scansioni lo usano per marcare cartelle già nella libreria, e le reimportazioni dello stesso rip trovano e sostituiscono la release precedente invece di duplicarla.
