bae म्हणजे चार मूळ अॅप्स धारण करणारे एक Rust केंद्र. उत्पादन ठरवणारे सर्वकाही, ग्रंथालय मांडणी, आयात, वाजवणे, समक्रमण, कूटबद्धीकरण, Rust मध्ये राहते आणि प्रत्येक प्लॅटफॉर्मवर सारखे वागते; प्रत्येक अॅप त्यावरची पातळ मूळ UI आहे.

## थर

- **`bae-core`**: उत्पादन. ग्रंथालय आणि माहिती मांडणी, आयात आणि ओळख प्रवाह, FFmpeg वाजवणारे यंत्र, मोठेपणा मोजणे, निर्यात, आणि खालील coven शी जोडणी. आयात आणि ओळख फक्त डेस्कटॉपवर बांधली जातात; मोबाइल बांधण्या समक्रमण आणि वाजवणारे क्लायंट असतात.
- **[coven](https://coven.bae.fm)**: माहिती थर, स्वतंत्र ग्रंथालय. coven SQLite जोडणीची मालकी ठेवते, bae साठवते तो प्रत्येक बदल पकडते, आणि ते बदल वापरकर्त्याच्या क्लाउड संचयातून टोकापासून टोकापर्यंत कूटबद्ध करून समक्रमित करते. द्वयी वस्तू संचय (ध्वनी बाइट्स, artwork), स्थानिक साठा, ओळख कळा, आणि सदस्यत्वही ते सांभाळते. bae अचूक coven आवृत्ती pin करते आणि प्रत्येक द्विमानात नोंदवते; बांधण्यांमधील समक्रमण-सुसंगत पिढी ते ठरवते.
- **`bae-bridge`**: UniFFI सीमा. Bridge प्रकार Rust मध्ये एकदाच ठरवले जातात आणि बांधणीच्या वेळी Swift आणि Kotlin मध्ये तयार होतात.
- **अॅप्स**: macOS आणि iOS वर SwiftUI, Android वर Jetpack Compose, आणि मूळ Windows अॅप. प्रत्येक केंद्र मागते ते प्लॅटफॉर्म भागही करते: ध्वनी बाहेर देणे, artwork मजकूर ओळख, माध्यम नियंत्रणे, कळसाठा प्रवेश, crash reporting.

अॅप्ससोबत: `bae-mcp` (MCP server) आणि `bae-automation`.

## डिस्कवरील एक ग्रंथालय

ग्रंथालय `~/.bae/libraries/<library-id>/` येथे राहते (मोबाइलवर प्लॅटफॉर्म डेटा संचयिका):

```
~/.bae/libraries/<id>/
  library.db        # SQLite: catalog, credits, playback specs
  config.yaml       # device-local settings, never synced
  storage/
    local/          # blobs this device owns (covers, artist images)
    cache/          # evictable copies of cloud blobs
    pinned/         # pinned-for-offline copies, never evicted
```

डेटाबेस फक्त coven मधून उघडला जातो; ते bae च्या आराखड्याशेजारी स्वतःच्या नोंदवही सारण्या (समक्रमण कर्सर, बाहेरची रांग, blob स्थिती) ठेवते आणि bae ची स्थलांतरे चालवते. न व्यवस्थापित म्हणून आयात केलेल्या ध्वनी फाइल्स `~/.bae` खाली अजिबात नसतात: डेटाबेस त्या ज्या मार्गावरून आयात झाल्या तिथे निर्देश करतो.

गुपिते या संचिकांमध्ये कधीही राहत नाहीत. ओळख कळा, ग्रंथालय कूटबद्धीकरण कळ, क्लाउड ओळखपत्रे, आणि API tokens OS कळसाठ्यात राहतात (Apple प्लॅटफॉर्मवर Keychain, iCloud Keychain मधून समक्रमित; इतरत्र प्लॅटफॉर्म समतुल्य).

## आवृत्त्या

प्रत्येक प्लॅटफॉर्मवर दोन बांधणी-वेळच्या आवृत्त्या आहेत. **bae** OAuth पुरवठादार (Google Drive, Dropbox, OneDrive), CloudKit, आणि telemetry बांधते. **baeium** हे सगळे काढून बांधते: फक्त S3-compatible संचय, telemetry नाही, अवलंबन वृक्षात मालकीचे काही नाही. आवृत्त्या तोच स्रोत आणि तेच केंद्र वापरतात; वैशिष्ट्य खूण पुरवठादार यादी आणि निदान जोडणी ठरवते.

## आवृत्तीकरण

अॅप्स `MAJOR.MINOR` म्हणून प्रत्येक प्लॅटफॉर्मवर आवृत्त होतात. major म्हणजे सुसंगतता काळ, प्रत्येक अॅपमध्ये सामायिक: त्याच major वरील साधने ग्रंथालय समक्रमित करू शकतात. तार किंवा डिस्कवरील स्वरूप तुटल्यावरच तो वाढतो, बहुधा pin केलेल्या coven आवृत्तीमुळे. minor प्रत्येक अॅपची प्रकाशने मोजतात आणि प्लॅटफॉर्मांदरम्यान तुलना करण्याजोगी नसतात.
